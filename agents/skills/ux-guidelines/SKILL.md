# UI and UX guidelines

No standard covers good UX as a whole; the **F** items below are the WCAG criteria most relevant to UI work here, not all of it. An explicit product requirement that conflicts with any item takes precedence, per the root `AGENTS.md` **Established practice** rule, and the change states the departure. Each item carries its status:

- **F**: formal standard, normative in its scope (WCAG 2.2, also ISO/IEC 40500:2025). That scope is web content: on native, [WCAG2ICT](sources/wcag2ict.md) applies WCAG only informatively, so an **F** item counts as **C** there unless a law adopts it. WCAG2ICT lists an Electron app's HTML as software, so `agents/desktop` counts as native for status and the AA bar. Items scoped to the web also apply there, apart from new tabs, copied links and URL state, which its window doesn't have (**J**).
- **V**: platform vendor recommendation, authoritative on that platform and **C** on any other (Apple HIG and app review, Google Play policy, Material 3, GNOME HIG, Google's Web Vitals, library docs for that library).
- **R**: research-backed practice (Nielsen Norman Group, Baymard); an article naming no study counts as **C**.
- **C**: common practice in mature design systems (GOV.UK, USWDS, WAI-ARIA patterns).
- **J**: Alliance judgement that no source settles.

Each item's links open local copies in `sources/`, each headed with its URL, licence and retrieval date; a page whose licence doesn't permit copying, or one far too large to be useful whole, holds only the passages the items rest on.

What a change adds or alters meets WCAG 2.2 AA, on native as an Alliance bar (**J**), and satisfies every item that applies, in this skill and in [`ux-forms-platform`](../ux-forms-platform/SKILL.md), which holds the items on forms, platform conventions, loading, URL state and visual-system values under this legend; a failure it notices elsewhere on the surface follows the root `AGENTS.md` **Scope and improvement** rule. Judging a UI applies every item of both skills to the whole surface. A screenshot can show a visual defect; keyboard, screen-reader and timing items need the running app. Colour-only meaning needs a look at the page under Chrome's `achromatopsia` (grayscale), `protanopia` and `deuteranopia` emulation. **V** [Chrome](sources/chrome-rendering-tab.md). Playwright reaches these through CDP `Emulation.setEmulatedVisionDeficiency`, and no automated rule judges colour-only meaning. **J**

## Controls and labels

- Icons stand alone only for the actions the Alliance counts as universally recognised: close, search, send, delete, settings. Every other action carries a visible word, since a tooltip or accessible name doesn't tell a sighted newcomer what an unfamiliar icon does, and most Alliance users are non-technical. **R** [icon usability](sources/nngroup-icon-usability.md): most icons are ambiguous without a label, and only a few, such as home, print and search, are broadly recognised; the Alliance's list is its own. This rule supersedes the "Icons over text labels" constraint earlier tasks recorded, so that constraint takes no precedence over it. Icons come from `lucide-react` (`lucide-react-native` on mobile), a repo convention.
- Direct interaction over modes: an inline edit over an "Edit" toggle, an Alliance preference no source weighs. Where a mode remains, the active mode is clearly shown, and none is used where a slip in the wrong mode loses work or data. **C** [modes](sources/nngroup-modes.md)
- On pointer platforms an icon-only control shows a tooltip. **J**, extending [GNOME's header-bar rule](sources/gnome-tooltips.md). A tooltip holds short text only; links or controls go in a popover opened by click. **C** [Carbon toggletip](sources/carbon-toggletip.md), [APG tooltip](sources/apg-tooltip.md). Content that hover or focus shows, a custom tooltip included, stays while the pointer moves onto it and until the pointer or focus leaves, the user dismisses it or it is no longer valid, and a key such as Escape dismisses it without moving either, unless it reports an input error or covers nothing. A browser `title` tooltip, which the user agent draws, is exempt. **F** [content on hover or focus](sources/wcag-content-on-hover-or-focus.md)
- A destructive or irreversible action says in words, on the control or in its confirmation or undo message, what it does and what it affects, and offers confirmation or undo. WCAG requires reversal, a check with a chance to correct, or confirmation only for legal, financial, stored-data and test-response submissions; elsewhere this is practice. **V** [GNOME dialogs](sources/gnome-dialogs.md), **F** [error prevention](sources/wcag-error-prevention-legal-financial-data.md). It is never the default action, the one Enter or initial focus triggers. **V** [Apple buttons](sources/apple-buttons.md) for the default button; initial focus is **J**, extending [APG dialog](sources/apg-dialog-modal.md). A web confirmation whose purpose is the destructive step may style it as a primary danger button. **C** [Carbon button](sources/carbon-button.md)
- A component with the same function keeps the same name on every screen that repeats it. **F** [consistent identification](sources/wcag-consistent-identification.md). It also behaves the same, and the current location is visible. **J**
- On the web, anything that goes somewhere is a real link, so open-in-new-tab and copy-link work, and its text or context names the destination. Anything that does something is a button. **C** [Carbon button](sources/carbon-button.md), [Carbon link](sources/carbon-link.md), [Atlassian link button](sources/atlassian-link-button.md), **F** [link purpose](sources/wcag-link-purpose-in-context.md)
- Interface text uses common words, literal phrasing and one point per sentence. A button starts with a verb naming its result. **C** [COGA](sources/w3c-coga-usable.md), [Fluent content](sources/fluent-content-design.md), [Carbon dialogs](sources/carbon-dialog-pattern.md), [Atlassian button](sources/atlassian-button.md), **R** [lower-literacy users](sources/nngroup-writing-lower-literacy.md).

## Status and feedback

- After an action starts, working, done and failed look different; a failure never looks like an empty success. **J**, applying [heuristics](sources/nngroup-ten-usability-heuristics.md)
- A failure or anything needing action stays available until resolved or dismissed, inline or in a banner; a timed toast carries only what the user can afford to miss. **C** [Carbon notifications](sources/carbon-notification.md), [Atlassian flag](sources/atlassian-flag.md), [Shopify alerts](sources/shopify-alerts.md)
- An absent value never shows as 0: zero, unavailable and not applicable read differently. **C** [Analysis Function](sources/analysis-function-symbols.md)
- An absolute time names its timezone where the reader could take it for another zone, such as a deadline, event or incident. **C** [GitLab](sources/gitlab-date-time.md), [Cloudscape](sources/cloudscape-timestamps.md)
- Feedback to a click lands within about 100 ms; a wait over about 1 s shows that work is under way, and long work names what it is doing and lets the user turn elsewhere. Progress is a percentage only when it is measurable. **R** [response times](sources/nngroup-response-times-3-important-limits.md), **V** [progress](sources/gnome-progress-bars.md)
- Status messages (saved, uploaded, failed) reach screen readers without moving focus. **F** [status messages](sources/wcag-status-messages.md)
- An empty state names what is empty and guides the next step, with a control for it where one helps. **V** [placeholders](sources/gnome-placeholders.md). "Nothing yet", "failed to load" and "no results" read differently. **J**
- An incoming chat message scrolls the view only if the reader is at or near the end; otherwise it keeps their place and offers a jump to latest. The reader's own sent message always scrolls into view. **C** [MUI](sources/mui-chat-scrolling.md), [Kendo](sources/kendo-chat-autoscroll.md)
- A notification fires once per event, keeps confidential content out of its preview, opens the thing it is about, and its outcome is also findable in the app. **J**, extending [Apple notifications](sources/apple-notifications.md)

## Trust and safety

- Members can report another member's content or account and block them from inside the app. **V** [Apple review](sources/apple-app-review-guidelines.md), [Google Play](sources/google-play-ugc.md). Every surface showing another member's content offers Report, every one-to-one surface offers Block, and both are labelled in words. **J**
- A screen showing private content, such as direct messages or private answers, is excluded from session replay, and free-text input stays masked unless a change states why. **J**. PostHog masks with `ph-no-capture` on web and `PostHogMaskView` on native. **V** [PostHog](sources/posthog-replay-privacy.md)
- Account deletion is available inside the mobile app. **V** [Apple review](sources/apple-app-review-guidelines.md). Leaving, withdrawing or switching off a channel takes no more steps than joining and is available in the same app; its wording carries no guilt or invented urgency, and counts and deadlines shown are real. **J**

## Accessibility and input

- Every action works from the keyboard unless it depends on the path of movement, nothing traps focus, and focus is visible and never fully hidden behind sticky headers, composers or overlays. **F** [keyboard](sources/wcag-keyboard.md), [no keyboard trap](sources/wcag-no-keyboard-trap.md), [focus visible](sources/wcag-focus-visible.md), [focus not obscured](sources/wcag-focus-not-obscured-minimum.md)
- After a view changes or the focused element goes away, focus lands on a logical place rather than `body`. **J**, applying [focus order](sources/wcag-focus-order.md)
- Headings, lists, tables and field groups use native elements or the platform's roles, and each view sets a descriptive title (the route's `<title>`, the screen's title on native). **F** [info and relationships](sources/wcag-info-and-relationships.md), [page titled](sources/wcag-page-titled.md)
- Meaningful images have a text alternative (`alt`, `accessibilityLabel` on native), decorative ones are hidden from screen readers, and prerecorded video with audio has captions. **F** [non-text content](sources/wcag-non-text-content.md), [captions](sources/wcag-captions-prerecorded.md)
- Controls expose their name, role and state (selected, expanded, disabled, checked) to screen readers, icon-only ones included (`aria-label`, `accessibilityLabel` on native). A control's accessible name contains its visible label's text, so a voice user can say the word they see. **F** [name, role, value](sources/wcag-name-role-value.md), [label in name](sources/wcag-label-in-name.md)
- Text contrast is at least 4.5:1, or 3:1 for large text (18 pt or about 24 CSS px, or 14 pt or about 18.5 CSS px bold); placeholder text meets the same ratio. Visual information needed to identify a control, its state or its focus, or to understand a graphic, reaches 3:1. Text and visual information in inactive controls are exempt. **F** [contrast](sources/wcag-contrast-minimum.md), [non-text contrast](sources/wcag-non-text-contrast.md)
- Colour is never the only way to convey information, indicate an action or tell elements apart: status, selection, role, category and unread state also differ by a word, icon shape, weight or a lightness difference of at least 3:1. Two identical icons in different colours, or a selected option that changes only its border or fill colour, fail with under 3:1 lightness difference. **F** [use of colour](sources/wcag-use-of-color.md)
- Danger, warning and success colours mean only that; categories, unread state and emphasis use other colours. **V** [Apple colour](sources/apple-color.md) for one colour keeping one meaning; reserving these colours is **J**, extending the status roles in [Atlassian colour](sources/atlassian-color.md) and [Carbon status](sources/carbon-status-indicator.md)
- On the web, a link inside a sentence stands out at rest by a non-colour cue or a 3:1 lightness difference from the text around it. **F** [use of colour](sources/wcag-use-of-color.md), failure [F73](sources/wcag-failure-f73.md). The Alliance uses an underline. **J**
- Chart series differ by label, dash or pattern, or reach 3:1 between neighbours; rainbow and red-green ramps stay out. **F** [use of colour](sources/wcag-use-of-color.md), [non-text contrast](sources/wcag-non-text-contrast.md), technique [G111](sources/wcag-technique-g111.md), **R** [Crameri 2020](sources/crameri-2020.md). Values are also available as text. **J**
- A focusable web element styled with Tailwind that has its own visible focus indicator hides the default outline with `outline-hidden`, which preserves it in forced colours mode, where `outline-none` removes it. **V** [Tailwind](sources/tailwind-outline-style.md)
- Web text stays usable at 200% zoom, and content reflows at 320 CSS px wide without horizontal scrolling, except content such as a data table that needs two dimensions. **F** [resize](sources/wcag-resize-text.md), [reflow](sources/wcag-reflow.md)
- Web hit areas are at least 24×24 CSS px, measured on the hit area rather than the icon, unless WCAG's spacing, equivalent-control, inline, user-agent or essential exception applies; touch targets default to 44×44 pt on iOS and 48×48 dp on Android. **F** [target size](sources/wcag-target-size-minimum.md), **V** [Apple](sources/apple-accessibility.md), [Android](sources/android-touch-target-size.md)
- Anything done by dragging, a path-based gesture such as swiping, or a multi-finger gesture also works with a single pointer, without dragging or a path, such as a tap or click, unless the gesture is essential, as in drawing a signature, or the user agent supplies it; a keyboard route alone doesn't satisfy this. **F** [dragging](sources/wcag-dragging-movements.md), [pointer gestures](sources/wcag-pointer-gestures.md). A drop zone's route is a file picker. **J**
- A modal takes focus, keeps Tab inside, closes on Escape and returns focus where it was. **C** [dialog pattern](sources/apg-dialog-modal.md). A native `Modal` sets `onRequestClose`, so Android Back closes it. **V** [React Native](sources/react-native-modal.md)
- With Reduce Motion on, nonessential animation stops and state changes stay clear. **V** [Apple accessibility](sources/apple-accessibility.md)

## Where judgment takes over

No standard settles visual density or motion style; how agent chat apps show tool calls or queue versus steer; or the right onboarding length. Compare with established products there and say it is judgment. Less friction is the wrong goal in front of a consequential commitment, where a deliberate review step belongs.
