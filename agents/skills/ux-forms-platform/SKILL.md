# UI guidelines: forms, platform and visual system

These items sit under [`ux-guidelines`](../ux-guidelines/SKILL.md), whose status legend, AA obligation and way of judging govern them; read it with this skill.

## Forms and errors

- Every input has a label or instructions. **F** [labels](../ux-guidelines/sources/wcag-labels-or-instructions.md). A placeholder never stands in for a label or holds needed information. **C** [GOV.UK text input](../ux-guidelines/sources/govuk-text-input.md). Format and constraints show before submission. **J**
- Fields for the user's own name, email, phone and address set autofill purpose (`autoComplete`); name, email and code fields turn off spellcheck. **F** [input purpose](../ux-guidelines/sources/wcag-identify-input-purpose.md), **C** [GOV.UK text input](../ux-guidelines/sources/govuk-text-input.md). URL fields turn it off too, and on native, email, code and URL fields also turn off autocorrect and auto-capitalisation. **J**
- A digit identifier such as a code is a text field with a numeric keyboard, not `type="number"`. **C** [HTML note](../ux-guidelines/sources/html-number-input.md), [GOV.UK text input](../ux-guidelines/sources/govuk-text-input.md). A phone number uses `type="tel"`, or `keyboardType="phone-pad"` on native. **J**
- A field isn't marked invalid before the user has finished it, and an error clears once corrected; checking on leaving or on submit both work. **R** [Wroblewski](../ux-guidelines/sources/wroblewski-inline-validation.md), [Baymard](../ux-guidelines/sources/baymard-inline-validation.md), **C** [NN/g](../ux-guidelines/sources/nngroup-errors-forms.md), [GOV.UK validation](../ux-guidelines/sources/govuk-validation.md)
- A switch takes effect at once; a choice committed by Save or Submit is a checkbox. **V** [Material](../ux-guidelines/sources/material-switch.md), **C** [NN/g](../ux-guidelines/sources/nngroup-toggle-switch.md), [Carbon](../ux-guidelines/sources/carbon-toggle.md), [Atlassian](../ux-guidelines/sources/atlassian-toggle.md)
- A submit button stays enabled and reports what is wrong when pressed. **C** [GOV.UK button](../ux-guidelines/sources/govuk-button.md), [Atlassian button](../ux-guidelines/sources/atlassian-button.md). A control that must be disabled says why in visible text. **J**
- Editing that could be lost either autosaves with a visible saved state or warns on leaving with Save and Discard. **V** [Apple](../ux-guidelines/sources/apple-file-management.md) for autosave, **C** [Shopify](../ux-guidelines/sources/shopify-forms.md) for saving. The warning and its Save and Discard pair are **J**; [USWDS modal](../ux-guidelines/sources/uswds-modal.md) shows a warning with different actions
- A failed submission keeps every answer, marks each bad field with how to fix it, and a multi-field form leads with an error summary linking to the fields. **F** [error identification](../ux-guidelines/sources/wcag-error-identification.md), [error suggestion](../ux-guidelines/sources/wcag-error-suggestion.md), **C** [error summary](../ux-guidelines/sources/govuk-error-summary.md), [validation](../ux-guidelines/sources/govuk-validation.md)
- An error names the problem and the way out in plain words; codes and raw output sit behind it as detail. **R** [heuristics](../ux-guidelines/sources/nngroup-ten-usability-heuristics.md)
- Information already entered in the same flow is prefilled or offered for selection rather than typed again, except where re-entry is essential, required for security, or the earlier answer is no longer valid. **F** [redundant entry](../ux-guidelines/sources/wcag-redundant-entry.md)
- No sign-in step needs memory or transcription without an alternative: passwords and one-time codes accept paste and autofill, and a puzzle has a non-puzzle alternative or is object recognition. **F** [accessible authentication](../ux-guidelines/sources/wcag-accessible-authentication-minimum.md)
- Every required field has a reason the task needs it; conditional fields appear only when relevant. **J**, extending [form fields](../ux-guidelines/sources/baymard-checkout-form-fields.md) beyond checkout
- A multi-step flow shows where the user is and what is left, and going back keeps the answers. **C** [task list](../ux-guidelines/sources/govuk-task-list.md), [question pages](../ux-guidelines/sources/govuk-question-pages.md)
- Advanced options can hide behind a disclosure; what the current task needs stays visible. **R** [progressive disclosure](../ux-guidelines/sources/nngroup-progressive-disclosure.md)

## Platform and performance

- Standard shortcuts keep their platform meaning (macOS on Mac, GNOME on Linux). **V** [Apple keyboards](../ux-guidelines/sources/apple-keyboards.md), [GNOME keyboard](../ux-guidelines/sources/gnome-keyboard.md). Every shortcut is discoverable from a menu or visible action. **J**
- Loading content never shifts the control under the pointer. A web change that alters loading or layout, such as new above-the-fold media, data fetched on render or content that arrives late, doesn't make the pages it touches slower to load, respond or settle. Google's Core Web Vitals call a page good when the 75th percentile of real users sees LCP ≤ 2.5 s, INP ≤ 200 ms and CLS ≤ 0.1, which only field data shows. **V** [Web Vitals](../ux-guidelines/sources/web-vitals.md)
- Native content keeps default font scaling, its containers grow with it, and it isn't truncated at the largest iOS accessibility size or Android 200%; navigation chrome such as tab titles may cap with `maxFontSizeMultiplier`. **V** [Apple typography](../ux-guidelines/sources/apple-typography.md), [Android 14](../ux-guidelines/sources/android-14-font-scale.md), [React Native Text](../ux-guidelines/sources/react-native-text.md). The keyboard and safe areas never hide the focused field or the submit control. **J**
- A custom native overlay hides what's behind it from screen readers, with `accessibilityViewIsModal` on iOS and `importantForAccessibility="no-hide-descendants"` on the content behind it on Android, and screen titles use the header role. **V** [React Native accessibility](../ux-guidelines/sources/react-native-accessibility.md); the Android half is **J**
- Filters, sort, tab and selected record live in the web URL, so Back, Reload and a copied link return to them. **R** [Baymard](../ux-guidelines/sources/baymard-back-button.md) for Back, in e-commerce; the rest is **J**

## Visual system

- Colour, type size and spacing come from theme tokens; an arbitrary value states its reason. **C** [Fluent tokens](../ux-guidelines/sources/fluent-design-tokens.md), [Atlassian tokens](../ux-guidelines/sources/atlassian-design-tokens.md), [USWDS tokens](../ux-guidelines/sources/uswds-design-tokens.md)
- Long text stays under about 75 characters a line, at 16 px or more with line height at least 1.5, start-aligned (left in left-to-right languages) and never justified. **C** [USWDS typography](../ux-guidelines/sources/uswds-typography.md), [GOV.UK layout](../ux-guidelines/sources/govuk-layout.md)
- Where the product has no convention, use the values mature systems converge on: a 4 px or 8 px spacing scale, 14 px dense text, 1.4 to 1.5 line height, 50 to 150 ms for hover or press and 150 to 400 ms for transitions, with entrances decelerating. **C** [Fluent layout](../ux-guidelines/sources/fluent-layout.md), [Carbon spacing](../ux-guidelines/sources/carbon-spacing.md), [Atlassian spacing](../ux-guidelines/sources/atlassian-spacing.md), [Fluent type](../ux-guidelines/sources/fluent-typography.md), [Atlassian type](../ux-guidelines/sources/atlassian-typography.md), [Atlassian motion](../ux-guidelines/sources/atlassian-motion.md), [Carbon motion](../ux-guidelines/sources/carbon-motion.md)
