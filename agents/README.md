# agents

Tooling for the coding agents that work on this repository. None of it ships with the product apps.

- `skills/`: the skills, reached through the `.claude/skills` and `.agents/skills` symlinks. The root `AGENTS.md` says when each applies.
- `chats/chats.ts`: `upload claude|codex` records a session's transcript for a background worker to copy to the private `alliance-agent-chats` S3 bucket, `fetch <key>` prints one to stdout, `check` warns the user and the agent when uploads can't get credentials, naming the cause, or are failing, `retry` retries failed uploads now, and `discard <key>` stops retrying one. It runs on bun, and its upload worker takes its lock through perl, as `scripts/lib/worktree-lock.sh` does; the repository already needs both. The hooks in `.claude/settings.json` and `.codex/hooks.json` run it at session start, after every turn, before compaction, and at session end. `skills/provenance/SKILL.md` says how a task lists its sessions and how to read a transcript.
- `hooks/block-pkill.sh`: a Bash `PreToolUse` hook, in both `.claude/settings.json` and `.codex/hooks.json`, that denies `pkill`, `killall`, any pgrep inside `$(…)` or backticks, and `pgrep … | xargs kill`, and tells the agent to find the PIDs with `pgrep -fl` first. It matches these anywhere in the command, so a command that only mentions them, such as `rg killall` or a commit message, is denied too.
- `desktop/`: Alliance agent, the Electron app employees work with coding agents through. `docs/provenance/01a1a949-c8f1-7000-9631-5610045dff02-alliance-agent-desktop-app/` holds its spec and PR plan. It is its own package, installed with `bun install` inside it after the root install, and imports nothing from outside the folder except `eslint/shared-rules.mjs`, whose own imports resolve from the root `node_modules`, and `common/src/result.ts`, so removing the app is deleting the folder plus the edits that spec lists and the removal edits recorded by later tasks naming that directory. `bun run dev` opens it, running the `claude` and `codex` on PATH, or those `ALLIANCE_AGENT_CLAUDE_EXECUTABLE` and `ALLIANCE_AGENT_CODEX_EXECUTABLE` name, each of which must be its supported version (`CLAUDE_CODE_VERSION`, `CODEX_VERSION`), until the app bundles its CLIs; each conversation runs on Claude or Codex, and each agent signs in on its own, the first time a conversation needs it; the Alliance repository it works on is the copy saved in its user data, else the main checkout of the copy a development build runs from, else `~/alliance/workspaces/alliance`, which it clones by itself when that folder is free (`src/main/repository/`), and its Playwright tests replace all three with a fixture through `ALLIANCE_AGENT_REPOSITORY_SOURCE` so none clones from GitHub; `bun run test` runs its bun unit tests, then builds it and runs its Playwright tests under Node, since Playwright can't launch Electron from Bun before 1.4.4 and its launch under 1.4.4 is untested on Linux. `.github/workflows/desktop.yaml` runs its typecheck and tests, outside `scripts/test-all.sh`, and `bun scripts/codex-protocol.ts check`, which fails when the Codex app-server protocol types in `src/main/agent/codex/protocol/` differ from those `CODEX_VERSION` (`src/main/agent/codex/version.ts`) generates; after changing that version, regenerate them with `bun scripts/codex-protocol.ts generate`. The Codex adapter's stub, `src/main/agent/codex/testing/stub-codex.ts`, replays its captures from `src/main/agent/codex/testing/captures/<version>/` the same way as Claude's below; after changing that version or the requests the adapter sends, re-record them with `bun src/main/agent/codex/testing/capture-codex.ts`, which checks that the `codex` on PATH, or `ALLIANCE_AGENT_CODEX_EXECUTABLE` where PATH finds a wrapper such as a terminal's shim, is that version, deletes the `config.toml` of `Alliance agent (dev)/codex` in the OS app data folder, the development `CODEX_HOME` `src/main/dev-app-data.ts` names, so trust starts from scratch, runs real sessions on the developer's ChatGPT subscription, signing in first if needed, saves the main checkout's `.codex/hooks.json`, the one Codex ran, beside the captures for the replay tests' checkout, and then checks the transcript upload as Claude's run does. The Claude adapter's test stub, `src/main/agent/claude/testing/stub-claude.ts`, replays captured CLI traffic, choosing the capture by its command-line arguments, and the adapter's captures live in `src/main/agent/claude/testing/captures/<version>/`; after changing the supported version (`CLAUDE_CODE_VERSION`), the CLI's arguments (`claudeSessionArgs`) or what the adapter writes to its stdin, re-record them with `bun src/main/agent/claude/testing/capture-claude.ts`, which checks that the `claude` on PATH is that version, runs real sessions on the developer's subscription and signs in first if needed to `Alliance agent (dev)/claude` in the OS app data folder, the Claude config folder `src/main/dev-app-data.ts` names, which every checkout's unpackaged app shares unless launched with `--user-data-dir`, replaces every older version's captures, which the Playwright tests in `e2e/` also replay and quote, then checks the transcript upload, which needs your `alliance-dev` login (see Set up uploads below) and is skipped when `ALLIANCE_AGENT_CHATS=off`.

## Trust the hooks in Codex

Run `/hooks` in a Codex session and trust the repository's hooks, and again whenever `.codex/hooks.json` changes. Codex skips new or changed hooks until then, `block-pkill.sh` included. In a worktree, Codex runs the main checkout's `.codex/hooks.json` and the scripts it names, not the worktree's, so a worktree gets each hook only while the main checkout's branch has it.

## Set up uploads, once per machine

Uploads use your `alliance-dev` AWS login; `docs/local-secrets.md` has the setup. Both CLIs run `chats.ts check` at session start, which warns the user and tells the agent when uploads can't get credentials, naming the cause, such as an expired or missing login. `bun agents/chats/chats.ts fetch claude/none.jsonl` checks your login against the bucket: `NoSuchKey` means it works. Each upload hook records its transcript in `~/.alliance-agent-chats/requests/` and starts a background worker, which uploads it with your login. One worker runs at a time, holding a lock on `~/.alliance-agent-chats/lock`, and writes its output to `~/.alliance-agent-chats/worker.log`. A transcript whose upload fails stays recorded with the cause and retries at the next session start or upload hook in any session; `aws sso login` alone doesn't start a retry, and `bun agents/chats/chats.ts retry` retries now and prints what is left, naming every failed transcript's key. Until it goes up, the session-start check and each `Stop` hook warn the user with its last error; the session-start check leaves out a login failure once the login works again. A deleted transcript stays in that warning until the file is restored or `bun agents/chats/chats.ts discard <key>` drops it.

Anyone without a login, such as an outside contributor, sets `ALLIANCE_AGENT_CHATS=off` in their shell environment to skip the uploads and the warning.
