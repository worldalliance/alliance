# agents

Tooling for the coding agents that work on this repository. None of it ships with the product apps.

- `skills/`: the skills, reached through the `.claude/skills` and `.agents/skills` symlinks. The root `AGENTS.md` says when each applies.
- `chats/chats.ts`: `upload claude|codex` records a session's transcript for a background worker to copy to the private `alliance-agent-chats` S3 bucket, `fetch <key>` prints one to stdout, `check` warns the user and the agent when uploads can't get credentials, naming the cause, or are failing, `retry` retries failed uploads now, and `discard <key>` stops retrying one. It runs on bun, and its upload worker takes its lock through perl, as `scripts/lib/worktree-lock.sh` does; the repository already needs both. The hooks in `.claude/settings.json` and `.codex/hooks.json` run it at session start, after every turn, before compaction, and at session end. `skills/provenance/SKILL.md` says how a task lists its sessions and how to read a transcript.
- `hooks/block-pkill.sh`: a Bash `PreToolUse` hook, in both `.claude/settings.json` and `.codex/hooks.json`, that denies `pkill`, `killall`, any pgrep inside `$(…)` or backticks, and `pgrep … | xargs kill`, and tells the agent to find the PIDs with `pgrep -fl` first. It matches these anywhere in the command, so a command that only mentions them, such as `rg killall` or a commit message, is denied too.
- `desktop/`: Alliance agent, the Electron app employees work with coding agents through. `docs/provenance/01a1a949-c8f1-7000-9631-5610045dff02-alliance-agent-desktop-app/` holds its spec and PR plan. It is its own package, installed with `bun install` inside it after the root install, and imports nothing from outside the folder except `eslint/shared-rules.mjs`, whose own imports resolve from the root `node_modules`, and `common/src/result.ts`, so removing the app is deleting the folder plus the edits that spec lists and the removal edits recorded by later tasks naming that directory. `bun run dev` opens it; `bun run test` runs its bun unit tests, then builds it and runs its Playwright tests under Node, since Playwright can't launch Electron from Bun before 1.4.4 and its launch under 1.4.4 is untested on Linux. `.github/workflows/desktop.yaml` runs its typecheck and tests, outside `scripts/test-all.sh`. The Claude adapter's test stub, `src/main/agent/claude/testing/stub-claude.ts`, replays captured CLI traffic, choosing the capture by its command-line arguments, and the adapter's captures live in `src/main/agent/claude/testing/captures/<version>/`; after changing the supported version (`CLAUDE_CODE_VERSION`), the CLI's arguments (`claudeSessionArgs`) or what the adapter writes to its stdin, re-record them with `bun src/main/agent/claude/testing/capture-claude.ts`, which checks that the `claude` on PATH is that version, runs real sessions on the developer's subscription and signs in to the app's private config folder first if needed, replaces every older version's captures, then checks the transcript upload, which needs your `alliance-dev` login (see Set up uploads below) and is skipped when `ALLIANCE_AGENT_CHATS=off`.

## Trust the hooks in Codex

Run `/hooks` in a Codex session and trust the repository's hooks, and again whenever `.codex/hooks.json` changes. Codex skips new or changed hooks until then, `block-pkill.sh` included. In a worktree, Codex runs the main checkout's `.codex/hooks.json` and the scripts it names, not the worktree's, so a worktree gets each hook only while the main checkout's branch has it.

## Set up uploads, once per machine

Uploads use your `alliance-dev` AWS login; `docs/local-secrets.md` has the setup. Both CLIs run `chats.ts check` at session start, which warns the user and tells the agent when uploads can't get credentials, naming the cause, such as an expired or missing login. `bun agents/chats/chats.ts fetch claude/none.jsonl` checks your login against the bucket: `NoSuchKey` means it works. Each upload hook records its transcript in `~/.alliance-agent-chats/requests/` and starts a background worker, which uploads it with your login. One worker runs at a time, holding a lock on `~/.alliance-agent-chats/lock`, and writes its output to `~/.alliance-agent-chats/worker.log`. A transcript whose upload fails stays recorded with the cause and retries at the next session start or upload hook in any session; `aws sso login` alone doesn't start a retry, and `bun agents/chats/chats.ts retry` retries now and prints what is left, naming every failed transcript's key. Until it goes up, the session-start check and each `Stop` hook warn the user with its last error; the session-start check leaves out a login failure once the login works again. A deleted transcript stays in that warning until the file is restored or `bun agents/chats/chats.ts discard <key>` drops it.

Until the rollout finishes, `ALLIANCE_SECRETS_ENV_FALLBACK=1`, set in the shell environment that starts Claude Code or Codex, switches uploads back to the `alliance-agent-chats` IAM user: `AGENT_CHATS_AWS_ACCESS_KEY_ID` and `AGENT_CHATS_AWS_SECRET_ACCESS_KEY` in `.env.devtools`, which whoever runs terraform reads with `terraform -chdir=terraform output -raw agent_chats_access_key_id` and `agent_chats_secret_access_key`. The worker uploads every session's transcripts with the environment of the session that started it, so give every Claude Code and Codex session on a machine the same setting.

Anyone without a login, such as an outside contributor, sets `ALLIANCE_AGENT_CHATS=off` in their shell environment to skip the uploads and the warning.
