- `useCommentThread` in `shared/lib` owns a comment thread and every write to it: it composes `useLoadComments`, `useDeleteComment` and `useCommentLikeMutation`, and adds create, edit and pin as TanStack mutations. `setComments` no longer leaves it, so nothing outside the hook writes the thread.
- The thread stays in `useLoadComments`' state rather than moving under a query key. That hook documents why: a feed card seeded with `initialComments` and the screen over it show the same thread from different sources, and one cache entry would let whichever wrote last take comments off the other. Its retry and screen-reader state is also tied to its own requests.
- Create resolves as soon as the server accepts the comment and starts the thread reload without waiting for it, as web did. Waiting, as mobile did, would hold the composer, with nothing saying the comment went up, for as long as a reload hangs, and the client sets no timeout. A reply refused with 404 likewise starts its reload without waiting.
- Both platforms take web's edit handling: the request runs with `throwOnError: false` and a refusal reads through `refusalMessage`, so mobile now says why an edit was refused (for example an expired session) instead of always "Failed to save your edit". The edited comment takes the submitted content; web's leftover `id: -1` on it goes.
- A create that never reaches the server is reported to `captureException` on both platforms; only web did before.
- Create, edit and pin run with `networkMode: "always"`, so a write made offline fails its form at once, as the raw SDK calls did, rather than pausing until the device reconnects.
- Pin stays web-only, as before. Mobile has no pin control.
