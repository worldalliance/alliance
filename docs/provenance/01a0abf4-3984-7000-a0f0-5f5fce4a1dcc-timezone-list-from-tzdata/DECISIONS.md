# Decisions

- **The mobile list is a `FlatList` whose rows share one computed height.** A plain `ScrollView` rendered all 313 rows and guessed a 55px row height to open on the saved zone, which put Europe/Berlin about 3,000px off-screen. `getItemLayout` needs one row height, so both lines truncate to one line, as they already do on web. The height comes from the OS text size and line heights set on the row's two lines, since a fixed 62px row cut the text off at iOS's largest accessibility size (checked on the simulator). `FormModal` takes `scrolls={false}` so the list isn't nested in its `ScrollView`. Typing scrolls the list to the top, where the best match is. The list opens with the saved zone second from the top, but no higher than lets the last row sit at the bottom, since React Native doesn't clamp the initial scroll and a zone near the end opened on blank space. The list's height rounds down to a whole number of rows, since otherwise no starting row puts the last row at the bottom and a zone in the last row opened mostly hidden at most text sizes other than the default. The floor is one row, so a row taller than the cap leaves a row on show rather than an empty list.
