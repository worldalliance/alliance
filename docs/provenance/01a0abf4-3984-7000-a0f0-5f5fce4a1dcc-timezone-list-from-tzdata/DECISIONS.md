# Decisions

- **Source: `countries-and-timezones`, not `Intl.supportedValuesOf("timeZone")`.** The server already depends on the package (`server/src/geo/us-membership.ts`). Bun's Intl lists 18 zones under old names (`Asia/Calcutta`, `Europe/Kiev`) that the server doesn't store, Hermes support for `supportedValuesOf` is unverified, and Intl carries no country names.
- **Rows are the package's current zones that belong to a country, plus `Etc/UTC`.** The other country-less zones are `Etc/GMT±N`, whose sign is inverted from what the name suggests, and `Factory`. Nobody should pick those; UTC is a real choice.
- **Label: Intl's generic name and the city on the first line, country names on the second.** The second line always lists every country, even where the first line already names it ("India Standard Time — Kolkata" over "India"). Hiding the repeats took a word-stem comparison, which is more code than a repeated country name costs. With no Intl name, the first line is the city alone. Countries are separated by " · ", since tzdata names one "Saint Helena, Ascension and Tristan da Cunha". Antarctica shows only on the Antarctica/\* zones: on Singapore, Riyadh, Auckland and Port Moresby it read as one more country.
- **Search covers the first line, the country names, and what the IANA name says after its area.** The per-row `searchTerms` go. The area is dead weight in a query: with it, "pacific" answered with 30 `Pacific/*` islands ahead of Pacific Time and "indian" with the Indian Ocean. The segments between the area and the city are places, so "dakota" still finds the North Dakota zones and "argentina" Buenos Aires.
- **Search results keep offset order, except that rows the query names come first: a query equal to the row's city, to the zone's Intl name without its trailing "Time", or to a name of the first country tzdata lists for the zone, then one equal to a name of any other country the zone lists.** On web, Enter saves the first row, and without the rule "india" opens on the Indiana zones and "uk" on Puerto Rico, whose row lists "Virgin Islands (UK)". The rule matches whole names, not a word inside one, so "samoa" opens on Apia rather than American Samoa, a day off Samoa, and "georgia" on Tbilisi rather than South Georgia. The zone's own name counts because Intl hands "Mountain Time" to Denver and "Mountain Standard Time" to the zones beside it that skip DST, so "mountain" leads with the seven zones the name belongs to instead of with Dawson Creek, and "pacific" with Los Angeles. The first-listed country ranks above the rest because a country's `timezones` list in `countries-and-timezones` names every zone listing it, so it can't tell Vietnam's own zone from Bangkok's; with one tier "vietnam" opened on Bangkok, and "germany" opened on Berlin over Zurich only by label order. The second tier keeps countries that tzdata lists first on none of their zones reachable: "netherlands" opens on Brussels, not Puerto Rico. For every country tzdata lists first on some zone, the first row is one of those zones. Since matches are whole names, "United States" is one of the US's other names.
- **Rows tied inside a rank lead with a country's principal zones** (`PRINCIPAL_ZONES`). Nothing in tzdata separates Denver from Boise or Chicago from Beulah, North Dakota, so the zones a country's own members pick are written down: six for the US, six for Canada, one each for the 16 other countries the package splits into several zones. Without the table "usa" opened on Honolulu with New York 11 rows down, "central" on Beulah, "canada" on Dawson Creek and "china" on Urumqi. The table only reorders rows a query matched, and only inside a rank, so the unfiltered list stays in plain offset order and "usa" lists the six US zones west to east. A test fails when a listed zone stops being a current zone of its country. CLDR's `primaryZones` was no use here: 11 countries, and none of the US, Mexico, Brazil or Russia.
- **Enter on web saves a row only when the query ranks it alone.** The first row starts active when it outranks the second or is the only match; otherwise no row is active, and Enter does nothing until the member moves to a row. Without this, Enter on "usa" saved Honolulu, and the server places a member in the US by their zone's country. "pacific" leads with Los Angeles and still saves nothing, since Vancouver and Tijuana rank with it. An empty query leaves no row active either.
- **The active row is an override on the leading row, not a reset.** The reset ran in an effect, which landed after the trigger's ArrowDown and wiped the row it had just asked for, so a keyboard member pressed ArrowDown twice before Enter did anything. A row the member arrowed or hovered onto now holds until they type or the picker opens again.
- **Opening the picker clears the last search.** The query survived a close, so a second open could show 1 row out of 313, and the mobile list opened on the saved zone only when the stale query happened to match it. Closing leaves the query alone: a React Native modal keeps rendering while it fades out, and clearing on the way out repopulates the list behind the fade.
- **The mobile trigger gives the clock its own text beside the country line, and the country line shrinks.** Sharing one truncated line put the clock past the cutoff wherever a zone lists several countries (Berlin, Lagos, Puerto Rico). React Native leaves `flexShrink` at 0, unlike CSS, so the country line took the whole row and pushed the clock off it on a device while react-native-web, where the default is 1, looked right. Checked on react-native-web at 390px; the shrink is from the Yoga default, not a device.
- **The second line keeps tzdata's country order whatever the query matched.** One line can cut off a matched country, as with the Congos on the Lagos row. Reordering the countries per query and per saved zone was dropped with the ranking tiers.
- **A saved or device zone under an old name selects the current zone's row** (`Asia/Calcutta` → Asia/Kolkata), using the package's `aliasOf`. `GMT`, `Greenwich` and the other aliases of `Etc/GMT`, which has no row, select the UTC row. The stored value is untouched until the member picks a row.
- **The `group` field goes.** No UI reads it.
- **Search also knows a few countries by names tzdata doesn't use** (`ALSO_CALLED`): UK and England for the United Kingdom, USA, Turkey, Holland, Burma, and so on. It covers common short forms and names that tzdata has changed. Adjectives ("indian") stay out, per ALL-1093. The table is keyed by `CountryCode`, so a typo in a code fails typecheck. These names count as the country's own for the first-row rule, which puts London first for "uk".
- **The mobile list is a `FlatList` whose rows share one computed height.** A plain `ScrollView` rendered all 313 rows and guessed a 55px row height to open on the saved zone, which put Europe/Berlin about 3,000px off-screen. `getItemLayout` needs one row height, so both lines truncate to one line, as they already do on web. The height comes from the OS text size and line heights set on the row's two lines, since a fixed 62px row cut the text off at iOS's largest accessibility size (checked on the simulator). `FormModal` takes `scrolls={false}` so the list isn't nested in its `ScrollView`. Typing scrolls the list to the top, where the best match is. The list opens with the saved zone second from the top, but no higher than lets the last row sit at the bottom, since React Native doesn't clamp the initial scroll and a zone near the end opened on blank space. The list's height rounds down to a whole number of rows, since otherwise no starting row puts the last row at the bottom and a zone in the last row opened mostly hidden at most text sizes other than the default. The floor is one row, so a row taller than the cap leaves a row on show rather than an empty list.
- **Search finds a zone by the cities tzdata links to it.** Africa/Kinshasa, Europe/Stockholm and Asia/Calcutta are links to Africa/Lagos, Europe/Berlin and Asia/Kolkata, so they have no row, and without this "kinshasa" or "stockholm" found nothing. The last segment of every link under an Area/City folder (Africa, America, Europe, …) joins its zone's search text. Links outside those folders, like Brazil/West and Mexico/General, are left out: their last segment is no place, and "west" opened on Manaus with nothing on the row saying west. Australia/North, South and West are inside a folder and stay. These cities don't count as the zone's own for the first-row rule.
- **A closed picker builds no list.** The full list costs Intl about three formatters per zone, roughly 940, on every screen mounting the trigger (71ms cold under Bun; Hermes on Android is untested and likely slower). The closed trigger labels itself from the saved zone alone (11ms cold under Bun), and the list builds when the picker first opens. It stays built after that, since a React Native modal on iOS keeps rendering its content until it finishes animating closed, and an emptied list would show "No matches" in the fading sheet. Read from React Native 0.86's `Modal.js`, not checked on a device.
- **"Standard" in the requirement to display and select time zones the standard way means what CLDR recommends and what the OS pickers do.** CLDR (UTS #35) says time zone selection lists can use the generic location format ("Los Angeles Time", "Argentina (Córdoba) Time") instead of the generic non-location format ("Pacific Time"), which one name gives to several zones. iOS, Android and macOS set the zone from the device and fall back to picking by city. The OS behavior is from memory, not checked.
