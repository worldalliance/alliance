# Decisions

- **Which checks can throw** (agent decision, from the code at `0fad1c1d91`): on the submit path every database read and condition evaluation already fails the request. The one check that hid an error was a custom validator: `MemberVisibilityService.memberExtras` caught any error from looking one up or running it, logged it and counted the validator as failed, which hides what it gates and strips those answers. That is the variable framework spec's EVIDENCE.md, "Errors versus unknowns today", "Server submit". The fix is that catch: on submit, a throwing or missing validator now rejects the submission with a 500 that names the validator, and the global exception filter reports it to PostHog.
- **A 500, not a 400** (agent decision): the member can't fix a broken validator, and `assertConditionKindsSupported`, the sibling refusal on the same path, already answers 500 for a form the server can't evaluate. The response names only the validator; what it threw goes to the server log and the exception's `cause`, since the body reaches members and anonymous callers.
- **Refusing on every validator the schema names** (agent decision, implementing the requirement on validators gating hidden content): `memberExtras` runs every validator the schema names before visibility is evaluated, so refusing there covers a validator whose element sits on a page hidden by another condition without changing the shared evaluator in `common/`, which the client also runs.
- **The admin preview keeps counting errors as failed** (agent decision): `profiles`, behind `POST /tasks/visibilityProfiles`, passes `preview: true`, which skips unsaved validators and logs each failing validator once instead of refusing. The requirements cover submissions only, and a preview that 500s on one broken validator would hide every other group. One flag covers both behaviours because the preview is the only caller that wants either.
- **Saving a form with an unsaved placeholder validator, one naming a validator that doesn't exist, or one whose type needs an id argument it lacks, is still accepted** (agent decision, keeping to the narrow submit-path requirement): such a form can now never be submitted, but rejecting it at save is a change to the save path, filed as ALL-2194.
