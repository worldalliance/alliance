- The hook is `useMemberReliabilityWindowAdmin(weeks)` in `apps/admin/src/lib/`, keyed `queryKeys.memberReliabilityWindowAdmin(weeks)`. It follows `usePlatformTenureCohortAdmin`, the stats hook keyed on a week count the admin applies: `weeks` is `null` until the first apply and the hook passes `skipToken` then, so the card still loads nothing until "View reliability" is pressed. No write touches the window, so the hook holds one query.
- The rule both hooks share, keeping the previous result on screen while the next week count loads unless that previous load failed, moves into `keepPreviousUnlessFailed` in its own commit first, so the two cards can't drift apart on it.
- The card reads the hook through `useAppliedQuery`, which `PlatformTenureCohortCard` also uses, so both cards share what an admin sees around a load. Applying the week count already applied refetches it, since setting the same state changes no key; every apply loads, as before, so a failed load can be retried in place.
- Input validation stays in the card as local state with its existing copy. A load failure comes from the query error through `adminRefusalMessage` with the card's existing fallback copy, so a session expiry or refusal now says so specifically. While the query is in error the card shows no rates, as it did before, and the failure message is hidden while a fetch runs.
- The button's "Loading..." state follows `isFetching`.
