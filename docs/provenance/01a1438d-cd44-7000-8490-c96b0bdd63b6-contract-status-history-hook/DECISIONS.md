- The hook is `useContractStatusHistoryAdmin(range)` in `apps/admin/src/lib/`, wrapping `analyticsGetContractStatusHistoryAdmin` for the "Members over time" chart. It is the only StatsPage analytics load parameterized by user input, so it gains the most from a keyed cache, and it mirrors `useInviteFunnelAdmin`: the range is part of the key `queryKeys.contractStatusHistoryAdmin(range)`, and `keepPreviousData` keeps the old chart up while a new range loads, as the page's local state did.
- The other direct loads on the page (aggregate stats, retention cohorts, time to churn, platform tenure cohort, member reliability window, missed actions) stay as they are; each would be its own cache and hook.
- A failed load shows "Unable to load members over time." (through `adminRefusalMessage`) instead of the empty-state "No contract status data in this date range.", which the page used to show after logging the error to the console. This follows the repo's fail-loudly rule and the page's existing invite-funnel and reminder-click-rate error states.
- The `parsedDate` mapping stays in the page; moving it into the hook is not needed for the cache migration.
