- `useMissedActionsAdmin` lives in `apps/admin/src/lib` beside the stats page's other one-endpoint hooks (`useAggregateStatsAdmin`, `useDailyStatsAdmin`), under `queryKeys.missedActionsAdmin()`. Nothing writes missed actions, so the hook has only the read.
- The hook takes `{ enabled }`, the shape `useWaitlistEmailPreviewAdmin` uses, so the card keeps loading only once "View actions" is clicked. A later click calls `refetch()`, keeping the card's reload-on-every-click behavior. The hook turns off refetching on window focus and reconnect, and retries, so each click sends exactly one request, as it did before: `AnalyticsService.getMissedActions` reads every action and every active member, too costly to rerun unasked.
- A failed load or reload shows "Unable to load missed actions." (or the session-expired message, through `adminRefusalMessage`) in place of the member lists, even when an earlier load succeeded, as the card did before by clearing its data on failure. It no longer logs to the console.
