# Evidence

## Experiments

- **psql reads a variable set on stdin inside an included file**, 2026-11-16, psql 18.3 (Homebrew) against a local Postgres: `psql -X -v ON_ERROR_STOP=1 --single-transaction -At -f -` fed `\set password_hash '<synthetic bcrypt hash>'` and `\i '<file>'`, where the file runs `select :'password_hash'`, printed the hash unchanged, `$` signs included.
- **curl takes its URL from `--config -`**, 2026-11-16, curl on macOS: `curl --config - -w '%{url_effective}' <<<'url = "http://127.0.0.1:9/hc/fail"'` reported that URL as the one it tried.
- **psql finds anonymize.sql's includes and word lists in a copy of `scripts/anonymize` once it `\cd`s there**, 2026-11-17, psql 18.3 (Homebrew) against an empty throwaway local database, started from another directory: stdin `\set password_hash 'x'`, `\cd '<copy>/anonymize'`, `\i anonymize.sql` ran `scrub_contacts.sql` and sent each `\copy`, with no "No such file" error. The same copy run by `\i '<copy>/anonymize/anonymize.sql'` without the `\cd` failed with `first_names.txt: No such file or directory`.
- **anonymize.sql's `in_anonymize_dir` fallback serves both sync scripts**, 2026-11-17, psql 18.3 (Homebrew) against an empty throwaway local database, with the fallback's `\cd` path pointed at a scratch stand-in for `~/nest-backend`, psql started in `/`. The call main's sync script makes, which is what meets this file on the host since main squash-merges the branch, `psql -v password_hash=x -f <stand-in>/scripts/anonymize/anonymize.sql`, opened every word list (the `\copy` lines reached the server; only missing tables failed), and the same file with the `\if` block removed failed with `first_names.txt: No such file or directory` for each list. The new script's stdin (`\set in_anonymize_dir`, `\cd '<copy>/anonymize'`, `\i anonymize.sql`) opened every word list with the stand-in moved away.
