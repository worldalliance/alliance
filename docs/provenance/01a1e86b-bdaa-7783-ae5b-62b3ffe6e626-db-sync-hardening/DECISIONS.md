# Decisions

1. **CI shellchecks the three scripts by name (requirement 4)** rather than switching to `scripts/*.sh`, which would also pull in the worktree scripts and their sourced libraries, each needing directives or `-x`. The sync's one finding, SC2016 on the bcrypt regex, gets a directive. Agent decision.
2. **The implement skill's shellcheck command now points at the CI step** instead of repeating its file list, which had already drifted (it lacked `scripts/with_db_env.sh`). Agent decision.
3. **ALL-2262 and ALL-2243 stay out of this PR**, to keep it to the sync's exposure and race fixes. Agent decision.
4. **The password hash reaches psql on stdin as `\set password_hash '…'` followed by `\i` of `anonymize.sql` (requirement 1)**, not by `\getenv` as ALL-2240 suggested. `\getenv` needs psql 15 or later on the staging host, whose version wasn't checked; `\set`, `\i` and `-f -` work in every supported psql and leave `anonymize.sql`'s `:'password_hash'` as it is. The single quotes are safe because the script already rejects any value not matching the bcrypt pattern, which allows no quote or backslash. Agent decision.
5. **curl gets its URL from `--config -` on a here-string (requirement 3)**, as ALL-2242 proposed. The script refuses to start unless both are http(s) URLs with no `"`, `\` or whitespace, which curl's config quoting would interpret or a line break would turn into another option. Agent decision.
6. **The deploy race (requirement 5) is closed by copying, not by holding the lock longer.** During the existing startup window under `~/migrate.lock`, the sync copies `scripts/anonymize` whole from `~/nest-backend` into `~/sync_prod_to_staging.files/`, replacing any earlier copy, `\cd`s into the copy, sets `in_anonymize_dir` and runs `anonymize.sql` from there. Copying the whole folder keeps `\ir scrub_contacts.sql` resolving, and the word lists `anonymize.sql` `\copy`s are now relative paths, since `\copy` resolves against psql's working directory and takes no variables. Holding `~/migrate.lock` from before the anonymize step through the swap, the issue's other option, would make every deploy that lands during that window wait out the anonymize step, against the deploy's `flock -w` limit. The copies are not secret, so a fixed directory (runs serialize on the sync lock) needs no cleanup on exit. Agent decision.
7. **`anonymize.sql` `\cd`s into `~/nest-backend/scripts/anonymize` when `in_anonymize_dir` is unset**, so a sync script from before decision 6 still finds the relative word lists: a sync already running when this deploys, and every run after a deploy whose install of `~/sync_prod_to_staging.sh` fails, which the deploy only warns about. The root `AGENTS.md` breaking-changes rule asks for this expand step, since the running script can't switch with the deploy; main squash-merges, so splitting the change into two commits on this branch would not stage it. The fallback carries `BACKCOMPAT(anonymize-cwd)` and its removal is a follow-up. Agent decision.
8. **The RDS bundle is in the copy of decision 6 too (requirement 2).** libpq opens `PGSSLROOTCERT` on each connection, including the cleanup's `DROP DATABASE` after a failed step, so pointing it at `~/nest-backend` would reopen requirement 5's race. Agent decision.
