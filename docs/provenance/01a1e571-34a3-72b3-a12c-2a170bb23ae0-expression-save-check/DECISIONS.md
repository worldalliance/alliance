All entries are agent decisions unless they say otherwise. Spec references are to `docs/provenance/01a1c8da-8f1b-7459-9652-87f613c8693c-variable-framework-spec`; "the first PR" is `docs/provenance/01a1d107-5251-70f7-a755-312c076b4a53-expression-core`.

## Delivery

- **Source maps ship here**, with their only consumer, the save check's diagnostics (`docs/provenance/01a1e0d4-77bc-7761-b4a8-94fd3f7d7ed0-expression-dependencies`, DECISIONS.md, Delivery).
- **Built on the merged PRs.** This branch was written beside the first two PRs and rebased onto them as merged, so it follows what their reviews changed, as the entries below say where that touched this PR's code.
- **Scope checks in `convert-scope.ts`.** The source maps would take `convert.ts` past the repository's 500-line limit, so `checkScope`, `readsAsName` and `STRICT_RESERVED` move to `convert-scope.ts` ahead of them, the split a read-only codex review recommended: they check the scope a caller passes and share no state with the recursive converter, which stays whole.
- **Printing a deleted named expression.** The first PR's printer throws for a named-expression id with no name, since printing the id would read back as another name. The save check prints such an id only in text it rejects as using a named expression that no longer exists, where the text only spans that message and nothing reads it back.
- **A catalog name that isn't an identifier.** The first PR's `checkScope` rejects it before the save check compiles the catalog, so the check's test expects that message.

## Save check

- **One `tsc` program per check.** `checkExpression` writes the declarations generated from the catalog, each named expression the checked expression reaches (in dependency order, one script file each), and the expression itself into one language service, with `strict` and `noUncheckedIndexedAccess` over the old formula library. A named expression is declared as a `const` through a generic identity whose return type widens a literal as `let` would, so a named constant `"US"` is a string that its readers may compare with `"EU"` and a later save may change, while `isUnknown` still narrows it inside a function, which it wouldn't for a `let`. A check reports problems inside a named expression it uses under that expression's name, so a dependency broken by a catalog change fails every expression that reads it. Each check has its own document registry ("TypeScript's document registry across language services", EVIDENCE.md), and names starting with `__` are the check's own, so a catalog that uses one is a host bug and throws, as the scope check does for an input, function or named expression called `eval`, `arguments` or `globalThis`, which `tsc` can't declare as globals. A function parameter or the result that asks for a record also rejects text, numbers, yes/no values and lists, which `tsc` would let pass for a record whose fields they have, as the interpreter doesn't; lists are told apart by a symbol-keyed property the check declares on every list, which no record field, being text, can name, so an empty list fails and a field named `"0"` passes. Messages leave that property out, saying "A list isn't a record." where it is what failed. A record nested in unions three deep, or one whose choice value or field name holds a parenthesis, keeps the parentheses `tsc` put around it, which only reads oddly, where matching them past quoted text would mean parsing `tsc`'s type syntax. Problems are located in the text checked: the admin's own when they typed it, otherwise the tree printed. A reference to a deleted named expression, or a read of an input the catalog no longer has, is reported under the expression that holds it, since the printed text would read whatever now has that name, and so is a read of an input or named expression, or a call of a function, inside a function whose parameter has its name, since the text would read the parameter. A parameter read outside any function that has it is reported the same way, since the text would read the input or named expression of that name. A read of a method without its call, such as `"x".trim`, is reported, since `tsc` types it as a function and the interpreter can't read a method as a value. `tsc`'s messages go through the old formula checker's rewording (`common/src/forms/formula-messages.ts`), so a mistake reads the same in both editors.
