- "Ready to merge" means what the skill's **CI** section already calls done on an open PR: `MERGEABLE`, with no failed, cancelled or pending check. The per-commit review rounds finish before the push, so CI is the last gate. Interpretation of the requirements; agent decision.
- The loop is done when the PR's CI passed and it is marked ready for review, since marking it ready is now the step CI leads to. This supersedes "the loop is done when the PR is open and its CI passes" in `docs/provenance/01a18e9e-a7d2-7000-a3e4-aeaf86a67297-automatic-review-loop/REQUIREMENTS.md`. Agent decision.
- A PR already marked ready goes back to draft before any later push, because the commits about to land have not passed CI, so the ready state would otherwise be false for the length of the run. The conversion comes before the push so there is no window where new commits sit on a ready PR. Agent decision.
- A PR already marked ready also goes back to draft as soon as **CI** finds a failing check or a conflict, before the fix and before asking the user about `main`, so a PR the loop knows cannot merge does not stay ready, including when the user declines the update. A cancelled or pending check leaves it ready, since a rerun or a further wait settles those. Interpretation of the requirement that the PR is a draft while it is not ready to merge; agent decision.
- The skill calls `gh pr ready` and `gh pr ready --undo` without reading `isDraft` first, because both are no-ops on a PR already in that state (`EVIDENCE.md`). Agent decision.
- `.github/actions/open-superseding-pr` stays as it is: it opens PRs from a CI action, outside the review loop. Agent decision.
