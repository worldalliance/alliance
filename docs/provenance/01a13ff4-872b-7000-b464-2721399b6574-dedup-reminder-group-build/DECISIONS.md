- `reminderGroupFieldsFromDto` (dto → group fields) and `attachSendableDeadlineEvent` (deadline attached, then `assertReminderGroupSendable`) in `ActionEventReminderService` are the shared implementation. Validation needs the deadline attached, so it runs at the same point on every path: in `saveUnderLiveParents` for create and update, and before planning for the preview.
- The member-action status check moves into `reminderGroupFieldsFromDto`, so it runs on all three paths. The preview should refuse what create refuses. Update cannot change the group's event, so the check only fires there when the event's status has changed since the group was created; in that case the group cannot send anyway, so a 400 beats saving it.
- The suite stays outside the shared builder. Update ignores `dto.suiteId` and keeps the group's suite. The preview loads the suite with its actions because it computes the task scope, while create stores only the reference. Changing update's suite handling is out of scope.
- Timing columns the dto leaves unset are saved as `null` on every path, as the preview already treated them. Update previously left stale values from an earlier timing mode in place. Those columns are unread under the new mode, so clearing them changes no sends.
- The preview keeps its `id: 0` and placeholder name. Planning queries already-notified users by group id, and `0` matches none.
- The worker e2e test for clearing a timing anchor now gives the dependent action its own deadline. Without one, clearing the anchor leaves a `from_deadline` group that can never send, which saving now rejects.
- `assertReminderGroupSendable` also checks the timing rules the `reminder_group` check constraints enforce: each mode's columns are set, and a send range or relative range, whenever both of its ends are set, starts no later than it ends. The ordering checks apply in every mode because the constraints do, and the dto's other timing columns reach the row unchanged. Without this, the preview accepts groups that saving fails on with a 500.
