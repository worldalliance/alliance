# Decisions

- **Lift the list's height cap while a period is edited, and scroll the edit form into view.** The away period list on the member page is capped at `max-h-48` (192 px) with its own scrollbar, and the edit form alone (Start, End, Reason, Note, Save and Cancel) is taller than that, so bringing it into view inside the box would still clip it. The cap goes away only while `editingAwayRangeId` is set, and the form then calls `scrollIntoView({ block: "nearest" })`, with `scroll-mb-3` leaving a gap below Save, so the page scrolls only when the form is off screen. Dropping the cap for good was the other option. It was rejected because a member with many periods would then push "Schedule time away" far down the page, and the sibling Tags and Form submissions sections keep the same cap. (agent decision)
- **Focus moves into the form when it opens and back to the row's Edit button when it closes.** Opening the form unmounts the pencil button that had focus, and closing it unmounts the form, so before this change focus fell to `body` both times (seen in the browser). The first input (Start) takes focus with `preventScroll`, so the `scrollIntoView` call decides the scroll position. After Save or Cancel, focus returns to the Edit button of the period that was being edited. The return waits until no mutation is pending, because the Edit buttons are `disabled` while one runs. In jsdom and Chrome the mutation has already settled by then, since the hook's `onSuccess` awaits the refetch, but TanStack Query doesn't promise that ordering. (agent decision)
- **The edit form is a `role="group"` named "Edit away period".** It gives the fields a group name for screen readers, and lets tests tell its Start field from the "Schedule time away" form's Start field. (agent decision)
