# Decisions

- Narrowed the guard in `ActionsService.update()` (server/src/actions/actions.service.ts) to only throw when the change tightens obligation (`action.optional === true` and `rest.optional === false`), not when it relaxes it (`action.optional === false` and `rest.optional === true`). Rationale traced from the codebase: "obligation" (`canMissActionDeadline`, suspension tracking in `buildSuspendPlanContext`, reminder exclusion, pill status) is computed live from the current `optional` flag, while "admission" is fixed by the saved `ActionCohortDecision` rows and unaffected by `optional`. Flipping mandatory→optional only forgives already-passed deadlines and drops the action from suspension tracking; flipping optional→mandatory retroactively manufactures missed deadlines for members who relied on the action being optional, which can trigger suspension for past behavior that was fine when it happened. See `(root)/docs/provenance/.../REQUIREMENTS.md`. (agent-proposed, user-approved — this is the exact direction the user asked for in conversation)
- Kept the existing message copy's intent but reworded it to name the still-blocked direction specifically, since the general "can't change" framing is no longer accurate.
