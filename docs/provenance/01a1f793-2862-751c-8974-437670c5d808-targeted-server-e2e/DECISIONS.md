# Decisions

- The rule lives under **Checks** in `agents/skills/implement/SKILL.md`, where agents choose what to run, and `server/AGENTS.md` points there instead of naming `bun run test:e2e`, which agents read as the instruction to run the full set. One place keeps the rule from drifting.
- The rule tells agents not to raise `--timeout`, and to treat a setup timeout on a loaded machine as load but one that recurs on a quiet machine, or hits `health-db.e2e-spec.ts`, as the change breaking the e2e test app's startup, since a hang in `createTestApp` fails the same way. Transcripts showed agents raising it to 100s or more instead (EVIDENCE.md, **Transcript measurements**), which hides the load and makes each timeout cost more.
- How an agent finds the suites covering a change is left to its judgement; no file-to-suite mapping script, since none exists yet and the agent can search the suites' imports.
- Agent proposals not done in this task, left for separate work: give suite setup its own named timeout so a timeout names the suite and phase instead of surfacing as an `afterAll` TypeError on `ctx.app`; time each setup phase; if the per-suite `synchronize(true)` dominates, build the schema once per run or clone a template database.
- A `bun.lock` change runs only `health-db.e2e-spec.ts` locally, not every suite as Nx does by default (EVIDENCE.md, **Research**): a dependency bump most likely breaks the e2e test app's startup or the database connection, which that suite catches cheaply, though its `createTestApp` loads fewer modules than `AppModule`, and CI runs the rest. The root `package.json` is not a trigger; the user's chosen rule names only `bun.lock`.
