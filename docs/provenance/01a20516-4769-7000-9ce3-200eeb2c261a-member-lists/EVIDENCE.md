# Evidence

## Lists that rules reference (researched 2026-11-22 by a research subagent)

- Rules name a list by a fixed id or key. LaunchDarkly's `segmentMatch` clause holds segment keys, and the segment's name is editable separately ([target rules](https://launchdarkly.com/docs/eu-docs/home/flags/target-rules), [managing segments](https://launchdarkly.com/docs/home/flags/segment-management)); GrowthBook sends a saved group once and rules reference it ([targeting](https://docs.growthbook.io/features/targeting)). Vendor documentation.
- Deleting a list in use is blocked: LaunchDarkly "You cannot delete a segment if one or more flags is using it" ([managing segments](https://launchdarkly.com/docs/home/flags/segment-management)); Unleash allows it only at zero projects and flags, pending change requests counted ([segments](https://docs.getunleash.io/reference/segments)); GrowthBook won't archive a saved group in use ([publishing](https://docs.growthbook.io/features/publishing-and-approval-flows)). Vendor documentation. Statsig's and Customer.io's behaviour weren't found.
- Editing membership: Statsig takes typed or pasted ids and CSV ([ID lists](https://docs.statsig.com/segments/add-id-list)); GrowthBook text input or CSV ([targeting](https://docs.growthbook.io/features/targeting)); LaunchDarkly one context at a time by search, plus CSV ([list-based segments](https://launchdarkly.com/docs/home/flags/list-based-segments)); Customer.io CSV matched by id, email or phone ([manual segments](https://docs.customer.io/journeys/segmentation/manual-segments/)). Vendor documentation; common practice across them.
- Versioned membership: GrowthBook records every saved-group change as a revision that can be compared and reverted ([revisions](https://docs.growthbook.io/features/publishing-and-approval-flows#saved-group-revisions)). None of the vendors found lets an evaluation pin an older membership. SQL:2011 system-versioned tables model history by time ranges ([SQL Server temporal tables](https://learn.microsoft.com/en-us/sql/relational-databases/tables/temporal-tables)); Postgres core lacks them ([feature matrix](https://www.postgresql.org/about/featurematrix/detail/temporal-constraints)). Formal standard (SQL:2011), vendor documentation.
