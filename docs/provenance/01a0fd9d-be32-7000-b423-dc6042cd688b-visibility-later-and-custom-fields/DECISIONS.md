- **Custom component conditions are "is answered / is not answered" only.** A custom component's value shape depends on the component, so one condition kind works for all of them without knowing which component it is. The existing `hasValue` condition kind covers it.
- **Inline marking instead of a confirmation dialog.** A "Later in form" group in the picker plus a warning under the condition stays visible every time the form is opened. A dialog warns once and is easy to click through.
- **Later references limited to the same page.** Fields later on the same page re-evaluate live as the member answers. A field on a later page is answered only after the member has passed the dependent element, so the dependent element would appear only if they went back.
- **Pages and output-view blocks unchanged.** `validateFormSchema` already requires page conditions to reference strictly earlier pages, because a page skipped while hidden can't be revisited usefully. Output blocks have their own `outputBlockVisible` references and cycle check.
- **Self and descendants left out of the picker.** If an element depended on its own field or one inside it, hiding the element would strip that answer (`stripHiddenAnswers`), so it could never become visible again.
- **No runtime change.** `evaluateConditionResults` in `common/src/forms/visibility.ts` already resolves references regardless of position, and handles cycles by falling back to value-only evaluation. Web and mobile need no changes.
- **Cycle check scope.** `collectCycleErrors` in `common/src/forms/form-schema-validate.ts` is generalized to a shared search and given one edge per in-form field condition (element → referenced field). Loops that run through group membership (a child depends on its group's visibility, a group on its children) are left out, to keep the logic small. The runtime fallback keeps any missed cycle from crashing.
- **Existing cycles were possible before this change**, through drag-reordering or JSON edits. Blocking them on save is accepted as the fail-loudly default.
- **Unchanged:** the "required if" formula (`requiredIfFormula`) has no admin editor today and only gets its references remapped in `FormBuilder.tsx`.
- **Later fields travel as a `laterFields` prop beside `previousFields`.** Every field and display-block editor already threads `previousFields` to its wrapper, so adding a sibling prop keeps the data flow explicit, in place of a context the picker would read implicitly. `conditionSourceFields` (`apps/admin/src/lib/conditionSourceFields.ts`) computes both lists from the element's position, replacing the inline `previousFields` computation in `FormBuilder.tsx`. A group child's later fields are its later siblings followed by the page items after its group.
- **Custom component fields are also selectable in cross-form and page conditions.** Both pickers share the same controller filter (`isConditionalController`). Page conditions still accept only earlier pages, and `hasValue` already resolves against another form's answers, so no extra code keeps them out.
- **The cycle error names element ids**, e.g. `Visibility conditions form a cycle: f1 -> f2 -> f1`, matching the existing output-block cycle message. Graph nodes are question field and list sub-field ids, since only fields can be referenced. An element whose visibility reads its own field counts as a one-element cycle.
- **Warning text:** "This field comes later in the form, so this element can appear or disappear above where the member is answering."
- **Option value renames reach conditions anywhere on the controller's page.** `applyOptionValueToConditionalVisibility` in `FormBuilder.tsx` used to skip items up to the controller, since only later elements could reference it. It now scans the whole page. Earlier pages still need no scan, because conditions on other pages only read earlier pages.
