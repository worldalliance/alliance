# Decisions

- Bun 1.4.4 stores `process.env.X = undefined` as the string `"undefined"`, as Node does; 1.3.6 kept it `undefined`. `common/src/set-env.ts` `setEnv` deletes the key for `undefined`, so tests can restore a variable that was unset. (agent decision)
- Every test restore that could receive `undefined` goes through `setEnv`, including the hand-rolled delete-or-assign blocks it replaces. Restoring an unset variable by assignment leaked `"undefined"` into later tests on 1.4.4: admin's `HostedDocsPage` read `VITE_ALT_APP_URL` as an invalid URL, and server tests after `action-update-email.spec.ts` read `ALT_APP_URL` the same way. (agent decision)
- No lint rule enforces `setEnv`. A type-aware rule flagging possibly-undefined assignments to `process.env` needed type-aware lint in every package, a root `tsconfig.eslint.json` and about 25 test cases, too much friction under the requirement's condition. (agent decision)
- `node:timers` copies `globalThis.setTimeout` when first loaded, on 1.3.6 and 1.4.4 alike. `shared/forms/useFormDraftSync.test.ts` swaps that global during its tests, and on 1.4.4's file order some module first loaded `node:timers` while the stub was in place. engine.io, loaded later by `shared/lib/messagingSocket.integration.test.ts`, then got the stub, which returns a timer without `refresh()`, and that test failed. Loaded after `register()` with no stub, `node:timers` holds happy-dom's timers, which lack `refresh()` too. `shared/lib/testing/preload.ts` loads `node:timers` before both, and `preload.test.ts` checks its timers have `refresh()`. (agent decision)
- `sharedweb/forms/FormRenderer.savedDevice.test.tsx` assigned `window.innerWidth`. happy-dom's setter keeps an assigned width as an override in place of the viewport width, and writing the old width back keeps the override, so later `happyDOM.setViewport` calls stopped changing the width, and `sharedweb/lib/useMediaQuery.test.tsx` failed whenever it ran later, on 1.3.6 and 1.4.4 alike; 1.4.4's file order runs it later, 1.3.6's did not. The test resizes through `happyDOM.setViewport`. (agent decision)
- `server/test/e2e-test-utils.ts` `createTestApp` binds the app with `listen(0, "127.0.0.1")` rather than `init()`, on loopback because the tests connect only over loopback. Handed an unbound server, supertest calls `listen(0)` on it and never closes it on Bun, since it closes only a server with a `_handle` and Bun's `node:http` Server has none. The specs that needed a URL then called `listen(0)` a second time. Bun 1.4.4's `node:http` throws `ERR_SERVER_ALREADY_LISTEN` on that, as Node does, where 1.3.6 accepted it. (agent decision)
- Why 1.4.4: `test-unit (scripts)` hung in CI on 2026-11-05 (runs 41938377806, 41976051464, 41978135855) inside `spawnSync` in `scripts/lib/worktree-fixture.ts`. Stuck local `bun test` processes showed the signature of [oven-sh/bun#34069](https://github.com/oven-sh/bun/issues/34069): a zombie child, and a main thread busy-spinning in `kevent64` under `spawnSync`. [oven-sh/bun#44581](https://github.com/oven-sh/bun/pull/44581) fixes it and first ships in 1.4.3; 1.4.4 is the latest release. The Linux report, [oven-sh/bun#43697](https://github.com/oven-sh/bun/issues/43697), is still open, so CI may still hang occasionally. (agent decision)
- `version: "1.3.6"` in `apps/mobile/app.config.js` and `common/src/mobileFingerprints.gen.ts` is the mobile app's own version, not Bun's, and stays. (agent decision)
- `server/package.json` `engines.bun` rises to `>= 1.4.4` to document the minimum. Bun enforces it neither at install nor at runtime; the pinned versions in CI and the deploy host installs are what guarantee 1.4.4. (agent decision)
