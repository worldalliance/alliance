# Decisions

- **Capture events.** `Stop`, `SubagentStop`, `PreCompact` and `SessionEnd` in both CLIs. `Stop` after every turn keeps the stored copy at most one turn stale, `SubagentStop` catches a subagent's own transcript, named by the payload's `agent_transcript_path`, `PreCompact` catches the transcript before compaction, and `SessionEnd` catches a turn an interrupt or `/clear` ended without a `Stop`. Claude runs `Stop`, `SubagentStop` and `PreCompact` `async` so an upload never holds a turn, and gives `SessionEnd` 10 s. Codex runs its hooks synchronously with a 10 s `timeout`, bounding how long an upload can hold a turn; its `SessionEnd` keeps Codex's 3 s maximum. Codex 0.163 does run `async` hooks in the background, but `codex exec` cancels one still running when it exits, losing the last turn's `Stop` upload, and an async failure shows nothing, while a synchronous one shows as a failed hook, Codex's only sign that uploads are not set up.
- **Whole-file upload every time.** The transcript changes every turn, so a change check would always pass. Versioning plus a 7-day expiry of overwritten versions bounds the cost of per-turn overwrites and keeps a week to recover from a truncated upload.
- **Tool name as an argument.** Both CLIs send the same payload fields, so the hook config passes `claude` or `codex` rather than the script guessing.
- **Key layout.** `<tool>/<session>.jsonl`, a subagent at `<tool>/<session>/<file>`. No repository prefix: the bucket belongs to this repository's hooks.
- **Fixed bucket name.** `worldalliance-agent-chats` instead of the `random_id` suffix the other buckets use, because the hook and the provenance skill need the name without terraform state. A name collision at `terraform apply` means renaming it in `terraform/agent-chats.tf`, `agents/chats/sync.sh`, `agents/README.md` and `agents/skills/provenance/SKILL.md`.
- **Credentials.** A dedicated `alliance-agent-chats` IAM user with put, get, list and multipart abort, used through an AWS profile of the same name. The existing `alliance-dev` user's keys sit in GitHub Actions secrets, which would give CI access. Per-person identities would need IAM Identity Center, which the account doesn't run, and the `aws login` sessions people use expire, which would fail an unattended hook. The fixed profile name keeps the hook off whatever default profile a person has active.
- **Archive semantics.** `force_destroy` stays off and the policy omits `s3:DeleteObject`, so the shared key cannot remove a transcript. It can overwrite one, since every `Stop` overwrites the same key; the replaced version stays recoverable for 7 days. Tamper resistance against a key holder would need per-person credentials, ruled out under **Credentials**.
- **Incomplete uploads.** Transcripts past 8 MB upload in parts, so a lifecycle rule aborts incomplete multipart uploads after 3 days, as the other buckets do, and the policy grants `s3:AbortMultipartUpload` so the CLI can clean up its own failures.
- **Failure handling.** An upload failure exits 1 with a message naming `agents/README.md`; exit 2 would block the `Stop` in both CLIs. A payload with no transcript file, as under `--no-session-persistence`, exits 0 with `{}`, which both CLIs accept as a no-op. Claude's async hooks show the user nothing when they fail, so a `SessionStart` hook checks for the profile's key and warns with a `systemMessage` naming `agents/README.md`; a rotated key still fails silently until `SessionEnd`. It also warns when `jq` is missing, since `sync.sh` needs it. It runs on every machine, since a session that uploads nothing should say so; `ALLIANCE_AGENT_CHATS=off` skips both the warning and the uploads for people without the keys, such as outside contributors, who would otherwise see a failed upload after every Codex turn.
- **Codex script path.** Codex in a worktree runs the main checkout's `.codex/hooks.json`, so its commands find `sync.sh` through `--git-common-dir`, in that same checkout, rather than `--show-toplevel`, which names the worktree, whose branch may predate the script.
- **Overlapping uploads.** Claude's async uploads of one key can overlap when a turn ends before the previous turn's upload does, and the older snapshot can land last. The script takes no lock, keeping it simple: the next `Stop` or `SessionEnd` upload replaces the stale copy, so a newer turn is lost only in a session killed before either runs, and then only once its overwritten version expires.
- **Raw transcripts.** The root `AGENTS.md` rule to redact captured artifacts exempts the uploaded transcripts, since the requirements store them raw with no redactor and accept secrets in them; incidental personal information a session saw, such as PostHog replays or database rows, is stored with them.
- **Object metadata.** `user=<git user.email>` records who ran the session, since the shared IAM user hides it; email rather than name because S3 metadata is ASCII.
- **Reading guidance.** The provenance skill names where the text lives in each format and leaves the filter to the reader, per the requirement for no committed reader.
- **`.claude/hooks/trim-comments-reminder.sh` stays put.** Moving it under `agents/` is a separate tidy-up.
