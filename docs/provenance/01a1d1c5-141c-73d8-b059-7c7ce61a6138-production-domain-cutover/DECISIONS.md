# Decisions

The user asked for ALL-2140 as filed and was not asked about each of its points. They come from `01a1ccef-8e76-75bb-9655-d39c48ef9c28-finish-thealliance-move` and the mechanism from `01a1ce3b-28ec-7672-900a-c9fc06dca218-staging-domain-cutover`, and are followed in full unless an entry below says otherwise.

- Production's `DOMAIN_NAME` becomes `thealliance.org` and `ALT_DOMAIN_NAME` `worldalliance.org`, the swap the staging task made the whole config change. (forwarded source)
- With both environments cut over, the opt-in state goes: `DomainMove`, the `DOMAIN_MOVE` deploy output and the `__DOMAIN_MOVE__` key of nginx's `$moved_host` map. `domainMove()` now throws unless `ALT_DOMAIN_NAME` alone is legacy, so a config that swaps back fails the deploy's config step instead of redirecting nothing. Without the partial redirect lists the opt-in state would have meant "no page moves", a third behaviour nothing asked for. Rolling production back means reverting this change and the cutover's, not editing one value. (agent decision, reading the issue's "remove what only the opt-in needed")
- nginx's invite location (`location ~ ^/(signup)?$`) is removed with `$invite_redirect_host`: without its `301` it was `location /` repeated. A browser opening an invite link on the legacy domain gets the catch-all `302`, as the staging task's decision foresaw. With `$static_page_redirect_host` gone too, only navigations leave the legacy domain: a request with no browser headers, such as a link previewer, now gets the legacy page for an invite link rather than a `301`, and for a public page such as `/people` rather than a `302`. (agent decision)
- `useFullLoadOnNewBuild` no longer keeps navigations to the formerly redirected pages in-app, since `apps/frontend/src/lib/newDomainPages.ts` mirrored the removed nginx lists. A stale tab on a legacy host moves, signed out, at its next page navigation, as the staging task already accepted. (agent decision)
- Stopping the `switchedDomainAt` writes removes `UserService.markDomainSwitched`, its only writer, and the opt-in modal, the endpoint's only caller; the mobile app never called it. `POST /user/switch-domain` stays as a no-op under `BACKCOMPAT(ALL-2200)`: a web tab loaded on a legacy host before the deploy still runs the modal, and per the root `AGENTS.md` breaking-changes rule the endpoint goes only once no running client calls it. The no-op lets that tab's switch button sign the member out and send them to thealliance.org rather than show an error toast. ALL-2200 removes it once the access logs show no calls. (agent decision)
- `sharedweb/lib/domainMigration.ts` keeps `newDomainUrl`, `redirectToNewDomain` and `redirectAlreadyTried`, which the legacy-host sign-in handling in `AccountStep` still uses until ALL-2152 removes that block. Only the modal's helpers (`isSnoozed`, `snooze`, the `isLegacyDomain` re-export) go. (agent decision)
- For ALL-2138, the production Twilio account's Alliance number had its SMS webhook moved from `https://worldalliance.org/api/mms/inbound` to `https://thealliance.org/api/mms/inbound` through the Twilio API with the local server credentials. No number points at staging. Mailgun was left unchanged: the user found both sending domains' webhooks already on `https://thealliance.org/api/mailgun/handle-event` (EVIDENCE.md, Mailgun webhook configuration), so another engineer had moved them before this task. The repository holds only the Mailgun signing key, not an API key. (agent action)
