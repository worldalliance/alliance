# Decisions

- **Rebase onto `main` keeps PR #963's parameter-drift role and drops only visual regression.** #963 and #989 changed `terraform/ci-oidc.tf`, `docs/ci-secrets.md` and `.github/actions/aws/action.yml` after this commit was written. The resolution keeps `alliance-ci-parameter-drift`, its `ci_parameter_names` policy and its paragraph in `docs/ci-secrets.md`, so the role table lists seven roles. Origin: agent decision.
- **Terraform's `db_password` and `staging_db_password` come from Parameter Store `/alliance/prod/server/DB_PASSWORD` and `/alliance/staging/server/DB_PASSWORD`,** piped into `TF_VAR_*` by a script. With them the plan has no change to either RDS instance. `PROD_DB_PASSWORD` in the staging host's `~/db-sync.env` belongs to the read-only `staging_reader` user the nightly sync uses, not the RDS master user, and planning with it changes the production master password. Origin: agent decision, from the plan.
- **#969's `mms-media/` changes ship in this apply rather than separately.** #969's PR notes say to apply them before its code reaches production, since until then stored member media is readable through the public CDN; its code is in `production` and they were never applied. On 2026-11-14 `mms-media/` held no objects or object versions in either assets bucket. The changes only restrict access: the prod policy denies all but `alliance-ec2-role`, the prod host's role, and the staging policy denies only CloudFront, so neither server loses access. Origin: agent recommendation.
- **The commit leaves `terraform fmt` reformatting to separate work.** Whitespace changes from when it was first written are dropped, so its Terraform diff holds only the removals. Origin: agent decision, from review.
