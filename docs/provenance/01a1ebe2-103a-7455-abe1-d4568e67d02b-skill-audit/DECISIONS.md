# Decisions

Agent decisions unless marked. Evidence sections are in `EVIDENCE.md`.

1. **Method.** Six Claude subagents audited the skills in groups against every uploaded transcript from 2–17 November 2026; a Codex subagent checked their claims against the code and transcripts; two further checks answered questions with data instead of asking the user (EVIDENCE: audit, Codex beside Claude, splitting). Proposals the Codex check called wrong or unsupported were not applied.
2. **Scope.** This change edits skill text, root `AGENTS.md` pointers, one helper script, and the focus outline of the admin button `ux-guidelines` cites as its `aria-disabled` example, and deletes the trim-comments reminder hook with its settings entry. Problems wording can't fix became Linear issues: ALL-2333 (checked-in Linear and PostHog query scripts), ALL-2334 (desktop minimum window size and reflow), ALL-2335 (a shared pending button that keeps focus), ALL-2336 (the review loop's mechanics as a program), ALL-2339 (rewriting `ux-guidelines` under the 5,000-token re-attach limit, with lint and axe taking over checkable rules). The `friend` migration noise already had ALL-1544; the `migrations` skill now names its one-line repair, verified in the `agents` worktree (EVIDENCE: friend repair). Codex opt-out files for user-only skills stay with ALL-2327, since adding them could change how Codex reviewers pick up `review-base`.
3. **Left as they are:** `personas`, `meeting-notes`, `demo-engagement`, `bro`, `review` (apart from the waiver line item 16 drops), `action-ideation`, `consult` (apart from the second-opinion fallback) and `writing-for-agents`. The first three had no runs in the window, so there is no evidence to edit against; `review` and `bro` showed working use; `action-ideation`'s run-freezing text warns agents before `rank` rejects a changed run; the last two were rewritten on 17 November.
4. **Splitting commits and per-commit correctness stay as they are.** The user recalled the split rule's purpose as revealing more findings, which nothing written recorded; the data supports it, mostly through the extra reviews a split brings (EVIDENCE: splitting). The audit's claim that fixers dropped splits because `main` squash-merges was wrong, so nothing argues for loosening "each commit passes on its own". Reviewers re-filing a split the fixer already dropped stays the fixer's to triage from the ledger, since stopping reviewers from raising it would conflict with every re-review being full and independent (user-originated in `automatic-review-loop`).
5. **Codex reviewers.** The hub prompts a Codex reviewer with the plain-text form of the `/review-base` brief and saves its result as `<sha>.codex.json`, as the hubs that ran dual rounds did. Codex reviewers count toward the loop's limit of four reviewers at a time (`review-loop-time`). Where only one CLI is set up, only its reviewer runs. A Codex run stopped by its usage limit is a failed review, never clean, per the existing failed-review rule.
6. **Review loop state and status.** The hub keeps its state in `.scratch/review-loop/<branch>/state.md`, recording which section of the skill the loop is in, so a session continuing a loop paused during CI or a question doesn't redo a push or PR, and rewritten whenever anything it records changes, and before each run it lists starts so a session ending just after a launch still lists it, rather than at listed points, which review kept finding gaps between, and gives a one-line status as each round starts without ending its turn, since 37 sessions resumed from hand-written handoffs and the user asked for progress 12 times (EVIDENCE: review loop sessions). The state lists running reviews, fixers and checks with their log paths, and a check with its command, which a continuing session reruns without the context that chose it. It lists the commits due a review that hasn't started rather than those due next round, since a pause can leave a round's reviews queued, and the commits the fixer named can't be recomputed from patch-ids. A continuing session that finds any listed as running goes to the user with them before acting, since a session that ended without a pause, such as on a usage limit, can leave them going, and nothing the hub can check reliably shows whether they or processes they started still run: a subagent can outlive the wrapper shell whose command line names its log, and a force-killed subagent's detached rebase holds no handle on its log, so a process search and an `lsof` on the log each missed a live writer in review. Once the user says they have stopped, or at once when none is listed, it aborts any rebase left in progress, since the state never lists the hub's own rebase in **`main` moved on**, reruns each check, which writes no `.exit`, and handles each review or fixer with no `.exit` file as that step's failed run, so a reviewer's worktree and a fixer's branch get the same cleanup, without counting it toward the two-failure limits, since a run that finished after its wrapper died writes none either; a rerun fixer continues from the round's ledger section. A pause or hand-off stops any CI watch at once, starts nothing new, such as a queued review, and waits for what is running to finish, rather than listing when it may happen, so the state never describes a half-done step, and keeps the reviewer worktrees for the session that continues, and the reply names them for removal if none does. The round-start line supersedes the 'or to report' part of `docs/provenance/01a1d21a-5ffb-71c2-8655-1b10986ee1e4-review-loop-time/DECISIONS.md`; its reason for not stopping between rounds (a report that ends the turn leaves the branch waiting) is kept.
7. **Base checkout in reviews.** A reviewer the loop's prompt places in its own reviewer worktree checks the base out there rather than building another worktree; any other reviewer keeps the isolated checkout, since only the prompt tells a loop worktree from a person's. Creating and removing one took a median 46 s per review in 705 of 1,842 reviews since 13 November (EVIDENCE: review loop sessions). The reviewer reads the review instructions before checking the base out, since the checkout swaps them for the base's versions.
8. **trim-comments.** `keep-test.md` had one consumer, so it merged into the skill; its "Corrections replace" section already lives in `writing-for-agents` and was not carried over. The `/** */`-versus-`//` rule stays: the Codex check found the evidence showed enforcement, not harm. Deleting the reminder hook (REQUIREMENTS) leaves nothing for the move under `agents/` that `docs/provenance/01a19e0b-aa3d-7000-8fcd-136f2b217cd7-agent-chat-archive/DECISIONS.md` left for later. The skill stays, applied through the root `AGENTS.md` rule: the user asked whether it is still needed and left that open, and it keeps agents from reading comments that have gone stale.
9. **implement** keeps its discovery and verification procedure, which `implementation-workflow` records as user-approved; only the two facts agents kept getting wrong were added.
10. **Token minting** has one script, `agents/skills/playwright/mint-token.ts`, which runs from `server/` through `scripts/with-secrets.sh`, so Bun loads the server's env files and secrets as the server does, contributors' `.env.local` included, checks `DB_NAME` against the worktree's database as the server does, and takes an optional expiry in whole hours for mobile runs; `playwright`'s recipe omitted `sessionGeneration` and `demo-action`'s script failed on team checkouts.
11. **provenance.** Spawned sessions stay in `SESSIONS.md`, marked with their role, instead of being dropped (the user deferred this to the agent): the second opinion judged their transcripts still explain repository changes. The role is `REVIEW_LOOP_ROLE`, which `subagents` sets on every spawn, rather than a label each session picks, after a hand-written role drew review findings twice. The fixer prompt asks for the fixer's bullet, since twelve of the first fifteen fixers on this task left theirs out. A handed-over point reuses an approved requirement only where that requirement still stands, checked per entry as supersession works; that is how the requirement's 'a task no later task superseded' is read, its 'the user' is the user the earlier task's `REQUIREMENTS.md` names, so a coworker's approval is asked about rather than reused, its 'already approved' covers requirements the user stated, which `REQUIREMENTS.md` holds beside approved ones, and its 'before writing code' is read as before editing, since a docs or skill task's gaps cost review rounds too. Origin labels are given a preferred form rather than a closed vocabulary, so existing clear labels don't draw findings. Provenance placement across a branch's commits is left unsaid: the Codex check found branches can ship a prefix, so placement can matter.
12. **The admin principle** is recorded in `ux-guidelines` in the user's words from the variable-framework spec, without an added consistency clause, which would be the agent's interpretation. It covers the whole admin panel because the user stated it for admins in general, "in general, admins should be allowed to do almost anything (but with warnings shown, and with type to confirm boxes for very important stuff)" (claude:31d963bf), which the spec records among its own requirements. It takes a new **U** status, an Alliance product requirement the user set, which `SOURCES.md` links to its provenance, since none of **F**, **V**, **R**, **C** or **J** describes one. Where a block's stated reason goes, the change's provenance, is the agent's addition, marked **J**, since the spec's reasons live in its own files.
13. **UX source index.** `SOURCES.md` lists sources per item, since three source names (Apple, Baymard, NN/g) each name several files. The merged skill measures 6,210 tokens; after compaction Claude Code keeps its first 5,000, which end around line 80, in Forms and errors, so the later Forms items, Platform and performance, Visual system and the closing section would be lost. The old `ux-guidelines` half alone measured 5,415, so the split never met that limit either. A wording-only tightening reached 6,018 and broke `SOURCES.md`'s opening-word keys, so it was reverted; the skill tells whoever adds an item or changes one's opening words to update its key. Shipping at full length rests on no session that loaded a UX skill having compacted (EVIDENCE: token counts, compaction in UX sessions). The later rewrite the agent proposed: enforce what lint and axe can check, keep only Alliance decisions, repo facts and recurring misses, mark rules required or default, and keep it under about 4,000 tokens (ALL-2339).
14. **UX rules agents misapplied** (EVIDENCE: audit). Colour emulation runs where a surface shows meaning by colour, not as a routine step; the visual-system values are defaults, not minimums; a one-off value is fine where no token fits and becomes a token at its second use, an Alliance judgement no cited source sets; the focus item names `disabled` on a focused button as the usual cause, with the `aria-disabled` recipe. The Codex check called each sound. These change rules, so they ship apart from the merge, which moves items unchanged.
15. **Subagent read-only flags.** A must-not-write task runs codex with `-s read-only` or claude with `--permission-mode plan --disallowedTools Bash`, so the fallback to the CLI a machine has keeps it read-only. Plan mode alone refused to write a file when asked, but still runs the Bash commands any settings file allows, such as builds and tests (EVIDENCE: read-only flags).
16. **review-base's User instructions section** and the closing waiver line of `review` and `debug` are dropped: the user's instructions already outrank a skill's, so they only restated that.
17. **`--verbose`.** The subagent command passes `--verbose`, since `claude -p` refuses `stream-json` without it unless settings enable verbose (EVIDENCE: audit). This supersedes the 'needs no `--verbose`' decision in `docs/provenance/01a18a15-4192-7000-b8aa-f5c09af28d86-subagents-via-cli/DECISIONS.md`.
