# Decisions

- **Delete the stored `CustomExpression` rows in a data migration** (agent decision). Staging, and so production, holds three (ids 29, 30, 31). With the type gone and the rows left behind, `checkValidator`'s `default` branch would warn and pass them, a silent guess. Deleted, validator 31 on the old snapshots 54 and 93 of form 67 takes the existing missing-validator path: `runValidator` fails and the visibility path logs an error and reads it as false. Read-only responses replay their saved `visibilityValidatorResults` without running validators (`shared/forms/useVisibilityValidatorResults.ts`), so old responses render as submitted. No foreign key references `custom_validator`, so the rows are hard-deleted.
- **Keep the `expression` column for one release** (agent decision). The running release selects it, and `scripts/deploy_backend.sh` migrates before the old backend stops, so dropping it in the same release breaks the old backend mid-deploy. This release stops exposing and writing it; the entity property is marked `BACKCOMPAT(custom-validator-expression)`, and a follow-up drops the column once this release is deployed.
- **Reject unknown types and fail on them** (agent decision). `CreateCustomValidatorDto.type` only checked `@IsNotEmpty()`, so `createCustomValidator` still stored a `CustomExpression` row after the enum lost it, and `checkValidator`'s `default` branch warned and passed an unknown stored type. The dto now validates with `@IsEnum(CustomValidatorType)`, and the `default` branch throws, per the root `AGENTS.md` **Fail loudly**.
- **Edit `citesting/fixtures/seed_dataonly.sql` by hand rather than regenerate it** (agent decision). `citesting/src/seed-database.ts` loads the seed after running migrations, so the delete migration never reached its `custom_validator` rows 29-31; the change removes them from the seed. Its snapshot 19, form 67's current schema in the seed, gated a display block on validator 31, so that condition becomes the built-in `firstContractSigned` condition staging's current snapshot of form 67 (2680, checked 2026-11-10) uses in its place, and its `hash` becomes the edited schema's `hashFormSchema`, since `findOrCreate` dedupes snapshots on it; staging has no current snapshot referencing validators 29-31. `citesting/scripts/reseed.sh` would also carry the 19 migrations the seed lags behind, burying these two edits in unrelated drift, so the seed and `seed_migration_timestamp.txt` otherwise stay as they were; the seed still loads after all migrations.
