- `useForumPosts` in `shared/lib` owns the list under `queryKeys.forumPosts()`, following `useAllGeneralUpdates`: it throws on a failed request and reports `didFail` through `failedToLoad`. A shared hook holds up, since both screens read the same endpoint with no parameters.
- `staleTime: 0`, so every mount reloads the list as both screens did before; mobile's client default is five minutes.
- Web drops the route loader. A failed load shows "Couldn't load forum posts." with a retry (`LoadFailed`, as `GeneralUpdatesPage` does) where the page previously rendered nothing. A first load shows a spinner under the create card, hidden once the load fails so a retry doesn't swap it in over the failure, as `FriendsTab` guards it.
- Mobile keeps its spinner, "Failed to load forum posts" box with Retry, and pull-to-refresh. The box shows on `isError`, so a failed reload or refresh replaces the list with the error, as before.
- A screen now shows the cached list before its reload lands, so a removed post would linger there for a round trip. `useForumPost`'s remove drops it through `dropForumPost`, which lives beside the list query in `useForumPosts.ts` so every write to the list cache sits in one module. It cancels a list reload in flight first, as remove does for the post itself. Create and update leave the list alone: the reload on mount picks them up, and the update response is not guaranteed to carry what a list row shows.
