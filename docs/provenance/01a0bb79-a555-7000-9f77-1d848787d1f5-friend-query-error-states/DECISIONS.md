- These changes come from seven reviews of "Fail a friend query when the server refuses it". Each time the user asked for every finding to be fixed, including the nits, and asked that no REQUIREMENTS.md change; the fourth, fifth and sixth asked for `web-client-default` to be filed in Linear instead of fixed. There is no REQUIREMENTS.md here because nothing in this work came from the user beyond those instructions.
- Finding `body-status`: the retry rule read `statusCode` out of the body `@hey-api/client-fetch` throws, which is a NestJS convention and not anything HTTP guarantees. A refusal shaped by anything else fell through to the retry branch and still cost four requests: measured against `serveApi`, four attempts each for a 400 bodied `{ message, errors }`, a 401 with an empty body, and a 401 answered in plain text. The first is what NestJS returns for an exception built from an object literal, which drops `statusCode` — `tasks.service.ts:276` and `actions.service.ts:1340` do that today — and the other two are what a proxy in front of the API answers with. `registerErrorStatus` puts `response.status` on the error from the client's error interceptor, the one place that still holds the response, so the rule reads a status that is always there. It is the first commit of the task, ahead of the rule that reads it, so no deploy has the rule trusting a field that can be missing. The provenance directory starts here.
- This was ALL-1111's second half, "worth doing at the same time" as the `throwOnError` sweep. It is split off because it preserves object bodies and adds the response status. Non-object bodies stay under `body` for logging, which `errorMessage` ignores so a proxy's HTML error page leaves the caller's fallback intact. The sweep stays in ALL-1111, since it changes what 79 call sites return.
- Registered from each app root and from `serveApi`, rather than from `createClientConfig`. That function runs while `createClient` is still building the client, so there is no `interceptors` to register on yet. `serveApi` takes it so a test sees the error every app ships; four assertions on the old shape took the status code, in `serveApi.test.ts` and `useBackfillTimeZone.test.ts`.
- `useDeleteComment` and `useLoadComments` pass `throwOnError: false` to hold on to the response their `refusalMessage` call reads the status off, and say so in a comment. The interceptor makes that unnecessary, and they are left alone: rewriting them is a second change, and neither is part of the friend queries this task covers.
