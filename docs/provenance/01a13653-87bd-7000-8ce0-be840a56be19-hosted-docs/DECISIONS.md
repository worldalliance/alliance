## Decisions

- Modeled on custom links (`server/src/custom-links/`, `apps/admin/src/pages/CustomLinksPage.tsx`): a new entity, an `AdminGuard`-protected CRUD controller (`HostedDocsController`, `/hosted-docs`), a `@Public()` serve controller (`DocsController`, `/docs/:slug`), and an admin page under the sidebar's Links folder. Custom links are the closest existing admin-managed, publicly resolved resource. The controller names make the generated client read `hostedDocsFindAllAdmin`, like `customLinksFindAllAdmin`.
- The document ID is stored in `HostedDoc.slug` as `citext`, with a unique index where `deletedAt IS NULL`, the same way `User.email` is declared. A deleted ID can be reused, lookups by any casing hit the index, and both fit in TypeORM decorators, so `migration:generate` produces the index instead of a hand-written `lower()` expression index. The serve endpoint compares the stored casing with the requested one to decide on the 301.
- Shared ID and notes rules (`hostedDocFieldsSchema`, `hostedDocSlugFromFileName`) live in `common/src/hostedDocs.ts`, used by the server service and the admin page, as `customLinkFieldsSchema` is. The server parses with them in the service; the DTOs only check that the fields are strings.
- Class-validator decorators sit on `CreateHostedDocDto`/`UpdateHostedDocDto` rather than the entity. The repo's lint requires a validator on every entity property once any has one, and the entity has internal columns (`s3Key`, user ids) that no input should carry.
- Files go in the existing `ASSETS_BUCKET` under `docs/<uuid>.pdf`, through `S3_CLIENT`. Each upload gets a new key and the row points at it; on replace, the row is updated under a row lock, then the old object is deleted. If the DB write fails after an upload, the new object is deleted.
- The response `ETag` is the key's UUID, not S3's ETag. A fresh key per upload makes it change on replace, and the server can answer `If-None-Match` with a 304 from the row alone, via Express's `req.fresh`, without calling S3. A request whose `If-Range` differs from that ETag gets the whole file, since its range would splice bytes of the replaced file onto the client's copy of the old one; it counts as a view like any other full read.
- Soft delete leaves the S3 object in place, per the deletion requirement; only replacement removes an old object.
- nginx (`deploy/nginx/alliance.conf`) gets a `location /docs/` block proxying to the Nest server. Without it, `/docs/...` reaches the frontend SSR server, whose catch-all `/:customLinkSlug` route would try to resolve it as a custom link. The frontend's Vite dev server proxies `/docs/` the same way, and `docs` is added to `CUSTOM_LINK_RESERVED_SLUGS` so a custom link cannot shadow the prefix.
- `client_max_body_size` goes from 50M to 51M. A 50 MB PDF plus multipart framing exceeds 50M, so nginx would 413 a file the API accepts.
- Upload is multipart (multer `FileInterceptor`, 50 MB `fileSize` limit), as in `server/src/videos/`, not the base64 JSON used by `/images/uploadImage`: a 50 MB PDF as base64 is about 67 MB. `bodyParser: false` in `main.ts` only affects JSON/urlencoded parsing; multer reads multipart on its own.
- `pipeS3Object` takes optional `range` and `filename`. It passes `Range` to S3 `GetObject` and forwards a 206 with `Content-Range`, plus `Content-Length` and `Accept-Ranges` on every response; S3's `InvalidRange` becomes a 416. Images and videos now also send `Content-Length`.
- The view counter is a `views = views + 1` increment fired without awaiting it, so the response does not wait on it; a failure is logged. A request is counted when it has no `Range` header or one starting `bytes=0-`, which includes HEAD requests and 304 revalidations.
- Uploader and last replacer are nullable foreign keys to `User` with `ON DELETE SET NULL`; the admin list shows "Deleted admin" when the user is gone. Upload time is `createdAt`; replacement time is `fileReplacedAt`.
- The admin page builds a document's public URL from `getInviteBaseUrl()`, as Custom Links does, so staging and dev copy their own site's URL. In production that is `VITE_ALT_APP_URL`, the `thealliance.org` site.
- Replacing a file asks for confirmation, since the previous file is deleted and cannot be restored.
