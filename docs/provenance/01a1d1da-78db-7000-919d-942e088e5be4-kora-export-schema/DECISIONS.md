# Decisions

- `propertyOrder` is renamed `x-propertyOrder`. It is not a 2020-12 keyword, and Ajv's strict mode rejects unknown keywords; an `x-` name signals a vendor annotation. A strict Ajv still needs `ajv.addKeyword("x-propertyOrder")`. Agent decision.
- `comprehension_answer` is null exactly on practice pairs, enforced both ways. The user's draft enforced only that non-practice pairs have an integer, while its description already said practice pairs carry null. Agent decision.
- `$id` uses `https://thealliance.org`, the domain the repo uses everywhere, instead of the legacy `worldalliance.org` (root `AGENTS.md` naming). Agent decision.
- The description's list of rules the schema cannot check gains `completed_at` not before `started_at`, `pairs_completed` matching the judgement rows, and `total_time_ms` being the sum of `time_ms_pair`. Agent decision.
- `maxItems: 26` on `opt_out_risks` is dropped; `uniqueItems` over the 26-value enum already caps it. Agent decision.
- The array conditionals on `children_age_bands` carry `type: array` so Ajv's `strictTypes` accepts the schema. Agent decision.
- `docs/kora/` over `server/src/kora/` or `kora-review/`: nothing reads the schema yet, and the review tool exports a different, per-assignment shape (`kora-review/src/schemas.ts`), so the contract isn't the tool's. It can move next to a server exporter once one exists. Agent proposal, approved (see REQUIREMENTS.md).
- The export schema's spec citations (sections, Annexes B–D, A- and E-numbers) were checked against KORA_SPEC.md v5.2 and match it. That spec is not in the repository yet (see REQUIREMENTS.md), so the citations point at a document readers cannot open until it is published. Agent decision.
- Known gap, not addressed here: the review tool does not yet record comprehension answers, attention pairs, the six screen timers, `first_time_on_risk`, share units, `last_login_at` or a skips table, so no current export can fill this schema. Reconstructed from existing code.
- The export schema stays at `docs/kora/kora_export.schema.yaml` and the pair schema sits beside it, rather than both moving into a `docs/kora/schemas/` folder, to keep the location already approved. Agent decision.
- `kora_pairs.schema.yaml` gains an `$id` on `thealliance.org`, matching the export schema, and `type: integer` beside the `child_age` bounds in its three age-band conditionals so Ajv's `strictTypes` accepts it. Its remaining notes that named `validate_pairs.py` now say an import validator checks those rules. Agent decision.
- The pair-schema test compiles with Ajv strict mode except `strictRequired`, because the schema's conditionals require fields declared at the pair level, which is valid JSON Schema; redeclaring them in every branch would rewrite KORA's file for a lint. Agent decision.
- The conversion test covers all 20 examples, now that the tool knows every risk. Agent decision.
- The 20 examples were read for personal information before being committed: the children are fictional and first-name only, the places are generic towns and cities, and the one full name in a failing AI answer (a "Danish naturalist") is the invented misinformation the example tests. Each carries the note "Generated fixture, for platform testing only". Their author is not recorded in the files. Agent decision.
- The amended spec in `.scratch/kora_spec/KORA_SPEC.md` is kept alongside an unamended copy, `KORA_SPEC.v5.2-as-received.md`, so the amendment can be diffed before it goes to KORA. Agent decision.
- Categories are listed in Annex C taxonomy order, and `KoraCategory` follows it, so the existing 10 moved from their old order. A test (`kora-review/test/categories.test.ts`) reads the taxonomy file and fails if the tool's ids, their order or the warning flags drift from it. Agent decision.
- Two `responsible` lines start with "Be", which doesn't read as "Does the AI be…", so those two guides open "Is the AI [honest…" and "Is the AI [straight…". The others open "Does the AI [" with the line's first letter lowercased and its full stop dropped. Agent decision.
- The content-warning descriptions for the 8 hard risks follow the subjects A4 of the spec lists ("self-harm / sexual content involving a minor / abuse / severe distress"). Agent decision.
- `SCHEMA_VERSION` stays 2. Widening the category enum leaves every stored version-2 export valid, while a bump would make the tool and server refuse saves already stored. Agent decision; it departs from the `schemas.ts` note to bump on any shape change, because nothing that was valid becomes invalid.
- The id lists moved from `kora-review/src/schemas.ts` into `kora-review/src/risk-ids.ts`, re-exported from `schemas.ts`, which took `schemas.ts` back under the 500-line limit. A read-only codex subagent proposed splits; this is the smallest, taken from its first proposal, because the lists change with KORA's taxonomy rather than with the schema's shape. Agent decision.
- The frontend landing page keeps its own 10-risk list (`apps/frontend/.../riskCategories.ts`); widening it is outside this change. Agent decision.
