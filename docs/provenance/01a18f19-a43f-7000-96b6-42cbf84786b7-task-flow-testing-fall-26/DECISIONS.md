## Decisions

- **TN-25: one screen per page, aligned by index.** `buildFlowScreens` maps every page to a screen, empty pages included, so a screen's index is its page's index. An empty page never shows because `visibleFlowScreenIndices` skips screens with nothing visible.
- **TN-25: the first header block anywhere on the page is the title.** It's lifted out of the page's content, even when content comes before it, so an author's title never shows twice. The authoring guide asks for it at the top of the page.
- **TN-25: saved screens restart.** Saved positions were screen indices under the old splitting, which now point at different pages. The storage key moved from `taskflow-screen:` to `taskflow-step:`, so a member's saved position from before resumes by page from their draft instead of landing on the wrong page.
- **TN-25: a header's section ends at the next header.** `withoutEmptySections` drops a header block whose blocks, up to the next header block, all hide, and keeps a header with no blocks under it, which an author placed on purpose. A step whose only showing block is such a header doesn't show. Before one step per page, a header started its own step, which was skipped once everything in it hid; this keeps that behaviour within a step. It applies only in the task flow; the classic form renderer is unchanged.
- **TN-17: progress is state, set on each move.** `useTaskFlow` sets it when the flow moves to a step, rather than deriving it from the visible steps on every render, so an answer that shows or hides a page doesn't move the bar. Next and leaving the background page keep the larger of the shown and the new value. Back, opening the flow, and the jumps the flow makes on its own (to an invalid page after a failed submit, or off a step that became hidden) show the exact value.
- **TN-15: one header row for every step.** Withdraw on every step made the close and withdraw row the same on every stage, so `TaskFlow` renders it once (`TaskFlowHeader`) under the progress bar, instead of each page drawing its own. The blocked view shows only the close button.
- **TN-15: the flow owns the `…`, the home card places it.** `TaskFlow` renders the menu, where the form state the withdrawal records is in reach, and shows it only while the flow is closed, so there's one withdraw control at a time. On the home card it goes into the card's header: web portals it into a slot the card provides (`CardMenuSlotContext`), and mobile hands the card the button's action (`CardWithdrawContext`), since React Native has no portals. Outside a card, on the action page, it stays beside Begin. On mobile a modal can't open from inside a hidden one, so the withdrawal sheet renders outside the flow's `Modal` while the flow is closed and inside it while open.
- **TN-3: the first step is wherever the flow opens on.** The note hides on the project background, or on the first question step when the task has none. It shows on every later step and hides again if Back returns the member to the first.
- **TN-19: "Invite a friend" navigates without the close animation.** It navigates straight to `/invites`. Leaving the page unmounts the flow on web, and on mobile it takes focus off the flow's screen, and either one already completes a submitted task. So the panel never collapses into the task card first. The navy is web's existing `--color-navy`, which mobile's theme now also defines, as the new `FlowButtonKind.InverseSecondary`.
- **TN-5: grey for every read-only task.** "View task" is the label of every read-only flow: a submitted task, a missed or closed one, and one the member can't submit. The button is the secondary kind in all of them, not only after completion, so one label never comes in two colours.
- **TN-5: one answers card.** `TaskAnswersCard` on each platform draws the member's avatar, name and city over the output view, and renders nothing when the view shows nothing. The completion screen passes it the answers just submitted, and the task panel passes the stored submission under "View task", with a border since it sits on white.
- **TN-12: the member feed loads authors.** The home card read the task's authors from the member feed (`/actions/loggedIn`), whose query loaded reviewers but not authors, so only experts showed. `MEMBER_FEED_RELATIONS` now loads both.
- **TN-12: the home task card.** "The task card" is read as the card on the tasks homepage, the notes' "preview card". The action page already names the task's authors and reviewers under its title, so it doesn't get a second list. On web they wrap in a row with a 24px gap; mobile keeps one column, since a phone is never a large screen.
- **TN-14: web hint on the icon, mobile hint for the browser.** On web each link in form markdown ends with an external-link icon whose `aria-label` is "opens in new tab", and a big link's existing arrow carries the same label. An `aria-label` rather than hidden text keeps the hint out of `textContent`, which choice options read their labels from. Mobile has no tabs: a link to an app page navigates in the app and closes the flow, and any other link opens the browser. So mobile marks only links that leave the app, with the icon and the screen reader hint "Opens in your browser", in form text blocks and big links, and leaves app links unmarked. The pure check (`leavesApp`) moved to `lib/internalLinks.ts` and the press handler to `lib/linkPress.ts`, which also keeps `AppMarkdownWrapper.tsx` under 500 lines.
