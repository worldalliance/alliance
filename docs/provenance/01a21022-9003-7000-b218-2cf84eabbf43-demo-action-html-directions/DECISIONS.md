# Decisions

- **The API mode stays the default.** A prompt without an HTML-page request runs the skill as it does today. Agent decision: the request adds a mode and says nothing about replacing the existing one.
- **Topic grounding is shared.** The HTML mode reuses the skill's **Topic** step, so the invented action still avoids topics past actions cover and matches their voice. Cohort counting requires an already-running local API; when unavailable, the run reports the prerequisite and stops without a page. It does not start the server, whose bootstrap writes to the database, to preserve the read-only requirement. Agent decision; see `EVIDENCE.md` **Startup and launch constraints**.
- **Prompt gaps are the agent's to fill.** What the prompt leaves out, such as the deadline, categories or time estimate, the agent picks as the API mode does. A request the selected admin path cannot express stops the run with the reason instead of producing a page. Agent decision, per root `AGENTS.md` **Fail loudly**; constraints differ between paths, as traced in `EVIDENCE.md` **Startup and launch constraints**.
- **Not chosen:** step checkboxes, per-step links to the local admin, and an expected-result line per step were offered and not selected, so the page leaves them out. Agent decision.
- **Times go in the zone each input takes.** The proposal behind the Pacific requirement assumed every admin date input is Pacific. The project action page's release form is, but the action's Event Management tab, the default path's scheduling step, uses the browser's zone and names it in its label. So the skill says to give each time in its input's zone, with Pacific beside it when they differ.
- **Cohort counts come from `POST /actions/evaluate-cohort`.** It is the admin's own evaluator and writes nothing, so the count matches what the cohort builder shows. Completions don't live in `user_action` (empty locally), so a hand-written query would undercount. See `EVIDENCE.md` **Trial run of HTML-page mode**.
- **The form is entered as JSON.** The Task Form tab's **Edit form JSON**, **Apply** and **Save Form** take a whole schema in one paste, and saving links the form to the action (`useFormSave` calls `setTaskFormId`). Building fields one by one in the drag-and-drop builder would be most of the page. To meet the per-field copy requirement, the page also lists each question with its own copy button, for checking or building by hand. Agent decision.
- **The skill doesn't ship a renderer.** The trial run left `.scratch/demo/render-directions.ts`, which turns a JSON spec of steps and copy blocks into the page. The skill already says to reuse scripts in `.scratch/demo/` or write them there, and `.scratch/` is per-checkout and never committed, so committing a renderer would wait until a second user needs it. Agent decision, per root `AGENTS.md` **Less is more**.
