# Decisions

- **Link copy.** "Reply from Needs reply." becomes "Reply in the thread on Texts.", with "the thread on Texts" linking to `/texts/<threadId>`. The link text names the admin page because the event log shows the message as plain text, without the link. (agent decision)
- **Opted-out numbers keep their alert unchanged**, "The number has opted out of texts." with no link, since staff can't reply to them. The issue asked only to retarget the existing link. (agent decision)
- **`userId` only when exactly one live member holds the number.** The event log has one `userId` column, and a number shared by several members (possible until the unique index of ALL-2259 lands) has no single owner, so it stays `null`. The alert still names every member. (agent decision)
- **The thread id is read, not created, in `MmsUnsubService.logUnhandledMessage`.** `MmsInboundService.recordInbound` creates the number's thread before the alert is sent, so the lookup uses `findOneByOrFail` and a missing thread goes down the existing lookup-failure path, which logs an error and skips the alert. (agent decision)
- **The shared-number tests move to `server/test/mms-shared-number.e2e-spec.ts`**, with the app and event-log setup both files need in `server/test/mms-inbound-app.ts`, because this task's tests took `server/test/mms.e2e-spec.ts` past the repo's 500-line limit. A read-only subagent proposed three splits; this is its smallest, and ALL-2259, which forbids two live accounts on one number, then deletes one file instead of a block. Its recommended three-way split, which would also move the alert tests into their own file, was left for when the keyword file grows again. (agent decision)
