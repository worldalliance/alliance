## Decisions

- **The withdrawal menu is the shared `Modal`.** `WithdrawalMenu` renders `sharedweb/ui/Modal` (centered, backdrop, close button, Escape, focus return) instead of an anchored `Dropdown`, so every web caller gets the centered popup: the home task card's `…`, the task flow header's `…`, and `FormRenderer`'s inline form. The modal portals to `<body>` at `zIndex.modal`, so nothing in the card can stack over it. The trigger only opens it; the backdrop covers the trigger while it's open.
- **No backdrop dim inside the task flow.** Opened from the flow's header, the modal is nested in the flow's base-ui dialog, and base-ui skips a nested dialog's backdrop. Forcing it in `Modal` would double-dim every modal opened from another modal, so the flow case shows the panel and its shadow alone.
- **The top bar outranks the flow panel at md and up.** The profile menu can't portal out of the fixed top bar without rewriting its hover, walkthrough and mobile behaviour, and a fixed element's children never stack above a sibling that outranks it. While the nav is immersive, the bar takes `md:z-35`, between `zIndex.drawer` (the flow panel) and `zIndex.modal`. From md the panel starts below the bar, so raising the bar covers nothing; below md the panel covers the whole screen, the bar included, so the bar stays at its usual tier there. The collapsed rail's logo overhangs the bar, so while immersive the rail takes `md:z-36`, a step above the bar, keeping the logo whole.
- **A compact checkbox size for the hide toggle.** `CheckboxSize.Small` already has the smaller box but is used for answer options, whose labels stay at body size, so `CheckboxSize.Compact` pairs the 20px box with `text-sm` label text. The toggle uses it wherever the mobile app shows it, in the task flow and the inline form alike.
