# Decisions

- **Mapping goes through the existing auto-extract path.** Textarea and file fields gain the same `autoExtractUserData: boolean` the phone, time, timezone and city fields have, and the checkbox extraction targets gain `textNotifications` and `emailNotifications`. `FormProfileAnswersService` applies them on submit, alongside the existing extractions. A boolean, not a target object, for textarea and file, because each has one target today. (agent decision)
- **Answers apply on submit, not live.** Unanswered or hidden fields leave the account alone, as for the existing extractions. The "saves immediately" answer the user gave for a whole profile block applied to a block the user then dropped in favour of an image upload element; the image upload is a form field like the city and bio fields beside it, so all three save on Complete. (agent interpretation)
- **The image upload, toggle and time picker are new field kinds** (`image`, `toggle`, `timePicker`; "Image Upload Field", "Toggle Field" and "Time Picker Field" in the builder) rather than new looks for the file, checkbox and time fields, so the existing fields' code is unchanged and no existing form changes. Each mirrors its counterpart wherever kinds are handled: drafts, validation (a required toggle must be on), conditions, response tables, filters, statistics, exports, output views and the account mappings (image to profile photo, toggle to a target like a checkbox, time picker to reminder time). They are top-level fields only, not list sub-fields. An installed app that predates them meets a kind it does not know, and the existing unknown-kind check blocks that form rather than rendering it wrong. The new image upload shares no code with the file field's picker, which keeps a copy of the same upload handling, so the file field stays untouched. (user-originated: net-new elements, existing ones unchanged; implementation agent decision)
- **The time picker is a custom wheel** built without a native library so it ships over the air: hour, minute and AM/PM columns that snap to rows behind a grey selection band, with faded edges, as on iOS. It is 12-hour with one-minute steps, like the iOS default, and its wheels stop at their ends instead of looping; looping is left for a later iteration. Each column is a spinbutton on web (arrow keys, Home, End) and an adjustable element on mobile, which also ticks a selection haptic on each change. Answers stay `HH:MM`, so the reminder-time mapping is unchanged. (agent decision)
- **A time picker's default is 9:00 AM, seeded with the form's other defaults** (`resolveFieldDefaultValue`), so what the member sees is what Complete saves, and opening a form with one is not an edit that starts the form or writes a draft. A field's own `defaultValue` overrides it. (agent decision)
- **The toggle commits on Complete, like a checkbox.** `ux-forms-platform` prefers a checkbox for a choice committed by Submit and a switch for one that takes effect at once; the user asked for a toggle element for on/off inputs in forms, which takes precedence. (agent decision)
- **At least one notification toggle on, and the text toggle's visibility, are form configuration.** The email toggle is required if NOT (the text toggle is on), and the text toggle shows only when the member has a phone number (`userPropertyHasValue` on `phoneNumber`); a hidden text toggle has no answer, so email is then required. Both toggles default on with `defaultValue: true`. (agent decision)
- **The notification toggles set the channel defaults** (`textByDefault`, `emailByDefault`) through `NotificationSettingsService.update`, the code the Settings page's Defaults rows use, so per-kind overrides keep precedence as they do there. (agent decision)
- **The photo is re-processed from the uploaded image.** A form upload is stored as one image without the thumbnail a profile photo needs, so the server reads the upload and runs it through the profile photo processing, before any other side effect of the submission. (agent decision)
- **The server does not check who uploaded the photo.** Any upload key can become the submitter's photo. Upload keys are random and uploaded images are served publicly, so a key grants nothing its image does not already show. (agent decision)
- **The completion subtitle is `completionSubtitle` on the form schema**, edited in the admin's Output views editor, where the completion card's contents are configured. (agent decision)
- **A member's accepted submission reloads the signed-in member and invalidates their notification settings**, so the completion card shows the photo the submission just set and Settings shows the toggles' values, even within mobile's five-minute stale time. Like the location invalidation beside it, it runs even when the session changed mid-submission, which only reloads the current member. (agent decision)
- **`form-schema.ts` was split** into `field-schemas.ts` (field definitions) and `form-value.ts` (answer values), re-exported from `form-schema.ts`, before adding to it, per the file-size rule. (agent decision)
- **`variables.ts` was split** into `variable-input-mode.ts` (the field kind to formula input table, which grows with every field kind) and `variable-answers.ts` (reading answers as formula values), re-exported from `variables.ts`, before adding the new kinds to it, per the file-size rule. Chosen directly, since the codex CLI the rule names was unavailable in the session. (agent decision)
- **A notification checkbox or toggle always answers on current clients only.** The client seeds its answer (off unless on by default), so an unchecked box turns the channel off. An installed app that predates this sends no answer for an untouched checkbox without a default, which the server reads as "leave the setting alone"; toggles are new kinds old apps refuse to show, and the onboarding task's toggles default on, so the gap only reaches a checkbox mapping without a default on an old build. Moving the rule to the server would need the visibility the validation step computes; left for later. (agent decision)
