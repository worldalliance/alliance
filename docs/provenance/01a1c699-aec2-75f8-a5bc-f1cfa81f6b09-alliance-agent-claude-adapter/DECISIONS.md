## Adapter

File paths from here on are relative to `agents/desktop/src/main/agent/claude/`.

- **Supported version.** `CLAUDE_CODE_VERSION` in `protocol.ts` is 2.1.322, the installed version the captures came from. Each backend runs `claude --version` before its first launch and refuses any other version with an error naming both, since stream-json changes between releases. The check gives up after 10 seconds, so an executable that hangs fails the launch instead of holding it. Until ALL-2029 bundles the CLI, a developer whose CLI auto-updates re-records the captures and bumps the constant (agent decision).
- **Executable.** The backend takes the executable's absolute path from its caller; nothing resolves it yet, since ALL-2029 supplies the bundled one and the capture script passes `which claude` (agent decision).
- **Environment.** `claudeEnvironment` passes on the app's environment except every variable whose name starts with `CLAUDE` or `ANTHROPIC_`, and `OPENAI_API_KEY`, then sets `CLAUDE_CONFIG_DIR` and the three variables the "Agent processes" section of the desktop-app task's DECISIONS.md lists for turning off nonessential traffic, feedback and updates. The desktop-app task's Credentials decision removes `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN` and `OPENAI_API_KEY`. Those two prefixes are the CLI's own configuration namespaces: they hold every credential and endpoint variable that outranks a subscription sign-in or reroutes traffic (EVIDENCE.md), the internal names the 2.1.322 binary reads such as `CLAUDE_CODE_API_BASE_URL` and `CLAUDE_CODE_GATEWAY_TOKEN`, and the markers and messaging token a parent Claude Code session sets (`CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_MESSAGING_TOKEN`), which reach the CLI whenever the app, its tests or the capture script start from an agent session and would make the CLI treat the session as nested. Dropping the whole namespaces, rather than the names found so far, stops a later CLI version's new name from getting through. An allowlist of the variables the CLI needs was the alternative and was rejected: the CLI's agents run git, gh, bun and the developer's other tools, which need the user's shell environment (`PATH`, `HOME`, locale, `TMPDIR`, `SSH_AUTH_SOCK`, `GH_TOKEN`, proxy and CA-certificate settings, toolchain variables), an open-ended set that differs per developer, and a missing name would break a tool inside the agent with nothing pointing at the cause. The provider credentials outside the two namespaces (`AWS_*`, `GOOGLE_APPLICATION_CREDENTIALS`, `AZURE_*`) take effect only with a `CLAUDE_CODE_USE_*` switch, which is dropped. Settings files can still set them, which Known gaps lists. The cost is that the CLI ignores a developer's own `CLAUDE*` and `ANTHROPIC_*` settings, such as a model override, which the app is the place to set. They move here from ALL-2029, as Scope from the Linear issues says, because every run of the CLI needs them, the installed one included (agent decision).
- **Mapping.** Per the measurements in EVIDENCE.md: `text_delta` stream events become AssistantTextDelta, each `assistant` text block AssistantText, each `tool_use` block ToolStarted, each `tool_result` ToolFinished (text parts joined), and `result` ends the turn, with an Error first when `is_error` is set, its message taken from `result`, then `errors`, then the subtype. An `assistant` message flagged `is_api_error_message`, which wraps a failed API call, maps to nothing, since the `result` ending the turn reports the same failure as its Error (EVIDENCE.md). Thinking blocks and other event types map to nothing, so the CLI can add types without breaking the app. A subagent's messages, which carry a non-null `parent_tool_use_id`, are left out, so the chat shows the main conversation only; showing subagent progress waits for the UI to need it (agent decision). A line that isn't JSON, or a used event in an unexpected shape, is logged, and reported as an Error during a turn that hasn't been interrupted or closed, per the root `AGENTS.md` fail-loudly rule.
- **Interrupt.** `interrupt` writes the stream-json `control_request` with subtype `interrupt`. The CLI then ends the turn with an `is_error` result, which the adapter drops, as `agents/desktop/src/main/agent/session.ts` requires.
- **Exit.** A CLI that exits mid-turn reports `Claude Code exited (code N).` with its stderr tail, then TurnEnded. One that exits between turns keeps that message for the next send, followed by "Resume the session to continue.", because the CLI reports a missing session as it starts, before any send, then exits (EVIDENCE.md), so the cause would otherwise be lost. A process the CLI started can hold its output open after it exits, so the adapter, and `runClaude` for sign-in and the version check, close its pipes a second after it exits rather than wait for that process (agent decision).
- **Resume.** A session id becomes a command-line argument, so `resume` rejects anything but a UUID, which a value such as `--help` could otherwise exploit. Live sessions are tracked by their pending launch, so concurrent resumes share one process, and an entry is dropped when its launch fails, its CLI exits, or `close` is called on it; closing a stale handle whose CLI already exited changes nothing. A resume of a session being closed waits for its CLI to exit before starting a new one, so two CLIs never run on one session id.

## Close (ALL-2090)

`close()` ends stdin, which exits an idle CLI with code 0 (EVIDENCE.md). With a turn running it also sends SIGTERM at once, since a CLI mid-turn would otherwise finish the turn first (agent judgement, unmeasured), and SIGKILL if the CLI is still running 15 seconds later. An idle CLI still running 15 seconds later gets SIGTERM, a signal it can handle, then SIGKILL 2 seconds after that; 15 seconds is past the 10-second timeout of the repository's SessionEnd transcript-upload hook, so a SIGKILL never cuts that upload short (agent judgement). The per-turn Stop hook runs the same upload but can't stand in for it: it doesn't run for an interrupted turn, which a close mid-turn is, and in `-p` mode an async hook still running at teardown is killed (EVIDENCE.md). Ending stdin and SIGTERM both let the CLI's SessionEnd hooks run to completion, idle and mid-turn (EVIDENCE.md). The running turn ends with TurnEnded and no Error, since the stop was asked for, as interrupt does. The session stops being live when `close` is called rather than when the CLI exits, so a resume never hands back a session that is shutting down. The fake backend drops the turn's remaining events, and its resume of a closed session gives a new session with the same id that continues the script from the turn the closed one reached.

## Captures and tests

The real-path-first task requires raw CLI output captured per version and replayed by the fake backend. Here the capture covers both directions: `testing/record-claude.ts` stands in for the executable during `testing/capture-claude.ts`, which drives the real CLI through the adapter itself, so the run that records the captures is also the live check of the thin path, of the issue's done criteria (a file edited in a worktree, the transcript upload hook firing, a check skipped when `ALLIANCE_AGENT_CHATS` is `off`, resume in a new backend as after a restart), and of image input. `testing/stub-claude.ts` stands in for the executable in tests and replays the capture whose arguments match its own, waiting at each recorded stdin line for one of the same type and failing on stdin the recording didn't have, so the adapter's real spawn, line reading, interrupt and close paths run in CI without a login (agent decision). It never runs the real CLI, so it is not the real-path-first plan's conditional tier of the pinned CLI against a stub model endpoint, which Known gaps lists as open. The fake backend replaying these captures, so the Playwright tests can use them, waits for the stacked UI PR, its first caller.

The missing-session capture is not kept, since its records' order against the first send is a race; its test writes the measured sequence by hand. Captures replace, in each line's decoded JSON strings, so a JSON escape before the account name can't hide it, and in the text a content block streams across lines (such as a tool call's input, sent in fragments of a few characters) and in stderr, which the recorder keeps in the chunks it arrived in, the repository path, and the main checkout's, which the CLI prints when recording from a worktree, with `/repo`, the home folder with `/home/user` and the account name, as a whole word, with `user`, and drop the recording account's claude.ai connectors (`mcp_servers` entries with source `claudeai` or a name starting `claude.ai `, and their `mcp__claude_ai_*` tools), which are personal and differ per recorder. `redactCapture` in `testing/redact.ts` does all of it and is exported, so committed captures can be redacted again without re-recording. It fails when a redaction changes what the parser reads from a line or what the test stub matches (a start record's arguments, a stdin line's type and subtype), as an account name that is a stream-json key, event type or CLI flag would, when a redacted key collides with another key in its object, and when a line still mentions claude.ai after the lists are cleaned, as a recording that called a connector would, or other text naming claude.ai, which the message says to check; a common-word account name still rewrites prose, such as model text, which shows in the re-recording's diff. The script redacts every recording before it replaces the committed captures, so a failed redaction leaves them as they were. A test checks that each tool call's streamed input joins to the input the call ends with, which a path redacted in one place but not the other breaks.
