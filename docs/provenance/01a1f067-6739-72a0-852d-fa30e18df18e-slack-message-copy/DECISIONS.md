# Decisions

- Formatters live in `server/src/eventlog/event-messages.ts`: `EventPayloads` maps each event type to a typed payload, and a mapped-type table forces a formatter per type. A formatter returns text and links once; `renderEvent` renders the stored admin `message` (link labels only) and the Slack line (escaped text, `<url|label>` links) from it, so the two can't drift. This follows Sentry's split of content from Slack rendering (`EVIDENCE.md`, Structuring notification code). (agent decision)
- Plain mrkdwn text, no Block Kit: mobile notifications show only `text` anyway (`EVIDENCE.md`, Slack message formatting), and one line with links meets the requirements. Revisit if buttons are wanted. (agent decision; the second-opinion agent agreed)
- The stored `message` column stays, holding the rendered plain text; old rows keep their old wording. Re-rendering old rows from `blob` was dropped: many rows have `blob: null`. (agent decision)
- `JoinRequest` has no formatter: nothing writes it, and the snapshot test renders no sample of it. (agent decision)
- Messages are full sentences ending in a period, the member is linked to their admin page, and a referrer is shown as "(invited by …)" or "(via the … campaign)", carried over from `memberWithReferral`, which this task removed. Free text someone typed (a reply, a note, a deletion reason) is quoted, so its own punctuation doesn't run into the sentence's. (agent decision; quoting the deletion reason from review)
- Automatic suspensions say how many action suites the member missed in a row, from the streak the suspension service already computes, instead of its dedupe key. (agent decision)
- Opt-outs take a typed source (`OptOutSource.Keyword` with the text, or `OptOutSource.Staff` with the admin id) instead of a reason string; the stored `MmsOptout.reason` values (`stop_keyword`, `marked_by_staff:<id>`) are unchanged. `OptOutSource` lives in `server/src/mms/opt-out-source.ts`, so mms code needn't import the event-log formatters. (agent decision)
- Actionable lines where the data already allows it: deletion requests point to the member's admin page, inbound texts from members link Needs reply unless the members have opted out, which Needs reply omits, delivery failures link Twilio's error page, and the waitlist cap names the env var that raises it. (agent decision under the "if feasible" requirement)
- A send failure links the phone number to the member's admin page by id rather than loading the member's name, so the failure path adds no query. (agent decision)
- Admin links use `ADMIN_URL` directly. Deployed configs already set it on the new domain, so preferring the new domain between it and `ALT_ADMIN_URL`, as `siteBaseUrl()` does for the app, never changes the result. (agent decision, from review)
- Comments link to the app's comment URL via `siteBaseUrl()`, replacing the direct `APP_URL` read, so they follow the preferred domain like other app links. (agent decision)
- The production-only check around the action comment event stays as it was; changing which environments write event-log rows is outside this task. (agent decision)
- Action opt-outs pass the withdrawal option and whether an admin recorded it; the formatter picks the wording ("An admin recorded that … opted out of …"). An account deletion's screenshot shows its URL, so the stored event-log text keeps it. (agent decision, from review)
- Name lookups for a Slack line stay off the paths they could break: the inbound-text alert runs after the text is recorded and logs a failed member lookup instead of failing Twilio's request, and a staff opt-out loads the admin, and an action comment its action, before anything is saved, so a failed lookup errors before anything commits. A comment on an action that doesn't exist gets no Slack line. (agent decision, from review)
