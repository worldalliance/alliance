# Decisions

- **Built from the two commits on `sms-settings-refusal` (572404d330, 4e7f06c63e), with the re-entry fix ALL-2280 describes.** That draft cleared the refusal only in `setSavedProfile`, so a re-entered refused number showed the cached refusal and was never sent until settings remounted; `updateEditableUser` now clears it whenever the update carries `phoneNumber`. The phone inputs (`shared/lib/usePhoneNumberField.ts`) call `onChange` only when the normalized number changes, so focus and blur don't clear it. (agent decision)
- **The draft's entry in the verify-member-phone `DECISIONS.md` is dropped**; that task is merged, so this directory records the work. (agent decision under `agents/skills/provenance/SKILL.md`)
- **`PhoneNumberTakenException` reads its message from `PHONE_NUMBER_TAKEN_MESSAGE` in `common/src/phone.ts`**, which the clients use as the fallback copy, so the two can't drift. (agent decision)
- **Changing the country alone doesn't clear the refusal.** The refusal is matched against the entered number normalized under the current country (`enteredNumberRefusal`), so a country change that changes the number already stops matching it. (agent decision)
- **Installed mobile builds without this change keep failing every save while a refused number is entered once ALL-2259 ships.** Production had no shared numbers on 2026-11-14 (verify-member-phone `EVIDENCE.md`), so a member has to type a number another live account holds to hit it; ALL-2259 can wait for a mobile release carrying this, or accept that. (agent judgement, left to the ALL-2259 PR)
