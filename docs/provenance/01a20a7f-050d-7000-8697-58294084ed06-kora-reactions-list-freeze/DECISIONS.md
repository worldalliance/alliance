# Decisions

- **Measure a reply's lines once per pass in the reactions list.** `groups()` and `passageContext()` in `kora-review/src/engine/reaction-list.ts` looked up each line's paragraph through a helper that called `lines(v)` per lookup, and `lines(v)` reads every word's `getBoundingClientRect`. That made one render cost paragraphs × lines × words layout reads (EVIDENCE.md, **Firefox profile** and **Layout reads per reaction**). The helper now takes the already measured lines. Agent decision.
- **The `dmn_chk_…` cookie warning is left alone.** posthog-js sets that cookie for 3 seconds on each parent domain to find the widest one that accepts cookies, and Firefox logs each rejected attempt; it does not affect the page. Agent decision.
- **Measure each reply once per `passages()` call, and compute passages once per reactions-list render.** `passages()` in `kora-review/src/engine/reactions.ts` called `lines(v)` for every 👎 passage, and the reactions list called `passages()` once per reply, so each passage added a full measure of its reply per reply on the page. `passages()` now keeps each reply's measured lines for the call, and `renderReactionList` passes one `passages()` result to `rowsOf` and `passageContext`. Agent decision.
- **Caching `lines(v)` across a whole render is left out.** Once passages stop multiplying it, a reaction measures a reply's words a fixed number of times, linear in words, and took under 50 ms on a 2,800-word reply. Agent decision, per YAGNI.
- **A regression test counts layout reads per reaction** (`kora-review/test/mount-review.test.ts`), bounded at 25 per word, so a lookup that re-measures per line fails it; a second test fails if a reaction with two 👎 passages in a reply reads more than one with a single passage. Agent decision.
