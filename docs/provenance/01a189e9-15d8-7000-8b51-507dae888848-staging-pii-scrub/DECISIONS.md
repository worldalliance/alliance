# Decisions

- Free text keeps its shape: each personal email becomes `redacted@example.com` and each phone number becomes `+15550000000`, in `event_log`, `form_response.answers` (including answers whose field the schema no longer has), `form_response_draft.answers`, and the free text members, applicants, and partners write: messages, notifications and unread content, push, AI-detection input, profile descriptions, rendered mail, invites, waitlist reasons and nominations, SMS opt-out replies, ambassador interactions, away notes, activity comments, and partnership responses and notes. Organization and government addresses are matched as `worldalliance.org`, `thealliance.org`, and any `.gov` domain. Numbers match as `+` and 8-15 digits with any separators, or as a North American number with separators between its groups; `+1555` numbers are already stand-ins. Bare digit runs stay, since campaign and other IDs look the same, except a form answer that is only a North American number, which is a phone number even when its field is gone from the snapshot. jsonb is scrubbed per string value, since its serialized escapes such as `\n` would hide a contact next to them. `ai_detection_result.rawApiResponse` is a jsonb string holding serialized JSON, so it is parsed first and rewritten only when a contact changed. The functions live in `scripts/anonymize/scrub_contacts.sql` so the e2e suite can test them against Postgres. Rows stay, so staging keeps exercising the screens that list them.
- Contact columns no code sends to (`oauth_account.email`, `action_partnership_response.contact`) get `<kind><id>@example.com` stand-ins rather than NULL, since both are NOT NULL. `waitlist_mail_allowance` holds only per-address rate-limit state, so it is truncated. `prefill_user` and `onetime_invite_request` are legacy contact tables nothing reads, so they are truncated too.
- The mail guard matches `@example.com` only. That is what the sync writes, and tests address mail to `example.org` when they expect it sent.
- An anonymized recipient takes the same path as sending being off: `sendMail` records a Pending `Mail` row, `sendUnrecordedMail` reports `Unavailable`. Callers already handle both.
- The anonymize SQL moved verbatim into `scripts/anonymize/anonymize.sql` to bring `scripts/sync_prod_to_staging.sh` under 500 lines. The sync runs it from `/home/ec2-user/nest-backend/scripts/anonymize/`, beside the name lists it already reads, which the backend deploy already ships.
