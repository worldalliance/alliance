- Hardcoded links to site pages became bare paths, which the browser resolves against the host the reader loaded, `staging.` included. This matches what `siteHref` already does for authored markdown links.
- URLs shown as text (the ambassador invite message, the talking points, the AI privacy flyer) use `useAppOrigin`, so SSR and the first client render agree and the text switches to the current origin after mount. `useAppOrigin` moved out of `sharedweb/lib/oauth.ts` into its own module now that it has callers unrelated to OAuth.
- Frontend share and copy URLs come from a new `getSiteUrl()` in `apps/frontend/src/lib/config.ts`: the browser origin, or the build-time URL in dev and SSR. This mirrors the existing `getApiUrl` there. `getInviteBaseUrl` is untouched because it deliberately always hands out the alt domain.
- The admin gets its own `getSiteUrl()`, built on the existing `altAppOrigin()`, which already maps `admin.<domain>` and `admin.staging.<domain>` to the matching site apex for API calls. It replaces `getBaseUrl()` in admin links to the site. `memberProfileUrl` had only admin callers, so it moved from `sharedweb/lib/config.ts` to the admin config, built on `getSiteUrl()`.
- The admin's copied invite and referral signup URLs use `getInviteBaseUrl()`, like the frontend's, so they always hand out the alt domain wherever the panel was loaded. This follows the existing invite rule rather than the admin's domain; a review flagged the mismatch.
- `AuthoredLinkProvider`, which left authored links to either domain untouched in the admin, became `SiteOriginLinkProvider({ origin })`. It points those links at the admin's site origin, so an authored `worldalliance.org` link opened on `admin.thealliance.org` goes to `thealliance.org`.
- Left as they are: email addresses (per the user); the mobile app, which has no current domain; SSR social-preview meta, whose canonical URL must match between server and client render; `LandingTestPage`'s absolute image URL, which is an image source rather than a link; and the admin reminder form's example URL, which is sample text.
- Server: links are built from the `APP_URL` / `ALT_APP_URL` env vars, since emails and notifications have no page domain to follow. Two hardcoded domains remain: the forum export brand link (`thealliance.org`) and the link-preview User-Agent (`worldalliance.org`). Both are reported to the user, not changed.
