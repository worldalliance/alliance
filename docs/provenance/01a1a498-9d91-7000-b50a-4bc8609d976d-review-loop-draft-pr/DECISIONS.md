- "commit review" on a PR marked ready checks out the PR's head commit rather than GitHub's merge commit, so it reviews the branch tip as a push would. It skips PRs from forks, which get no secrets, and `auto-fix/**` heads, matching the push trigger's exclusions.
- A push's gate also skips review when its PR was marked ready after the push (the PR's last `ready_for_review` event is later than the push event's `repository.pushed_at`), since that ready run reviews the same head; the gate reads draft state when its job starts, seconds or more after the push. The gate skips heads whose message contains "Merge branch" on both paths, reading the message from the push payload or, on the ready path, the API, since the workflow reviews a head against its first parent.
