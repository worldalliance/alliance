- "commit review" on a PR marked ready checks out the PR's head commit rather than GitHub's merge commit, so it reviews the branch tip as a push would. It skips PRs from forks, which get no secrets, and `auto-fix/**` heads, matching the push trigger's exclusions.
- A push's gate also skips review when its PR was marked ready after the push (the PR's last `ready_for_review` event is later than the push event's `repository.pushed_at`), since that ready run reviews the same head; the gate reads draft state when its job starts, seconds or more after the push. The gate skips heads whose message contains "Merge branch" on both paths, reading the message from the push payload or, on the ready path, the API, since the workflow reviews a head against its first parent.
- The loop fixes its base once, as a SHA, when it starts, from state any session can see: the SHA in `.scratch/review-loop/<branch>/base`, which the loop writes before its early push and deletes once the draft records the base, so a session that ends between the push and `gh pr create` doesn't leave the next one an empty `@{u}..HEAD`; its merge base with `origin/main` when the branch has no upstream, the base recorded in an open draft's description (the `origin/main` merge base when it records none), and its merge base with the upstream otherwise. A ref name would drift, since every round's force push moves the upstream. Keying it to the PR's state alone would let a no-PR loop rewrite commits it already pushed, and a draft opened on an already-pushed branch would lose those commits' protection on re-entry; keying it to the loop's own last push would leave a fresh session unable to tell which push that was. The draft records the base as an HTML comment, which the rendered description hides; opening a draft only on an unpushed branch was the alternative, but it breaks the requirement that the loop opens a draft. A loop that starts on a ready PR opens no draft and pushes once at the end with `git push -u origin HEAD`; a plain `git push` is rejected on a branch that tracks `origin/main`, as one made with `new-worktree.sh --from origin/main` does.
