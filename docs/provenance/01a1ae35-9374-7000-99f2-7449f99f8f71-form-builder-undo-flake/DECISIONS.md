# Decisions

- **Cause.** `EditableContractField` defaults the field's contract from a `useEffect`, through `withoutStep` (the derived-write context), and its `onUpdate` replaces the whole schema with one built from the schema its render closed over. When the current-contract query lands in a render whose passive effects haven't run yet, and Undo is clicked first, React flushes that effect while processing the Undo. The effect's amendment is reduced after the undo, so the stale schema overwrites the undone present and the removed question comes back with Undo disabled. This is a history bug, not only a test bug: a browser leaves the same window between commit and passive effects. A gated copy of the test reproduced it deterministically (`.scratch` experiment, not kept), while 50 runs of the file alone and 50 under load did not, so the CI failure was this window opening by chance. (agent decision)
- **Amendments name an epoch.** `DraftHistory` counts undos, redos and resets in `epoch`, and the reducer drops an `Amend` carrying an epoch other than the current one. An `Amend` without one applies as before. Commits and `mapAll` also replace the present but leave the epoch alone, so an amendment made before one still applies after it; dropping those is ALL-2066's to settle, not this flake's. Alternative rejected: comparing the amendment's base draft by identity would drop the second of two derived writes in the same effect flush, which an epoch leaves alone. (agent decision)
- **Fix in the history.** `withoutStep` tags its amendments with the epoch of the last committed render, read in a layout effect so it is set before that render's passive effects run, so the reducer drops one an undo, redo or reset has overtaken. Plain `amend` (save's schema sync, conflict handling) stays untagged, since it doesn't come from a render's closure. Alternative rejected: making `updateElementAt` functional would apply the update by index to whatever element sits there after undo. (agent decision)
- **Test waits on the default.** The test waits for the contract's markdown ("I pledge"), which the preview shows only once `contractId` is on the field, instead of the select's "Pledge", which shows as soon as the contract list loads because a select with no matching value displays its first option. The undo then really undoes a question that has its default, and the assertions after the synchronous click need no tick. The other `nextTask()` calls in the file separate commits into distinct undo steps, which a microtask boundary does deterministically, and no async data feeds them, so they stay. (agent decision)
- **Regression test** at the hook level (`useDraftHistory.test.ts`): an undo and a derived write in one act, before a rerender, leave the undone draft; a derived write after the rerender still applies. It fails without the fix. (agent decision)
- **Dropped derived writes are written again.** A derived write the epoch drops isn't lost: every undo, redo and reset goes with `reloadEditors`, which remounts the sidebar editors (keyed on `schemaLoads`), so the dropping action's next render runs their effects again. The contract field's default also re-checks on every run (below), and the markdown-sync and custom-component effects already re-check their data. Re-defaulting after an undo to a past draft without a contract amends that draft and adds no step. (agent decision)
- **Contract default re-checks on every run.** `EditableContractField` defaults its contract whenever its effect runs with the field's contract missing and the current contract loaded, rather than once per mount, so a default that didn't land is written again on the effect's next run. That run comes from a dependency change, which in the form builder is every render, since `FormBuilderSettings` passes a fresh `updateElementAt(index)` as `onUpdate`. The once-per-mount guard lost no default on its own: undo, redo and reset remount the sidebar editors (keyed on `schemaLoads`), which reset it. (agent decision)
- **Out of scope:** a stale derived write still overwrites an ordinary commit made in the same window, which predates this branch; filed as ALL-2066 with the fix of patching the element in the current draft by id. (agent decision)
