# Decisions

- **What counts as answered** (agent decision): an answer counts unless it is missing, JSON null, `false`, a blank or whitespace-only string, `[]` or `{}`. So an unticked checkbox, a cleared text box or an upload with no files doesn't count, and a number `0` does. One SQL rule covers every field kind rather than mirroring each kind's required-field check in `shared/forms/fieldValidation.ts`, which runs per field in the client.
- **Eligible questions** (agent decision): any question outside a list on the counted form's current version, lists included, mirroring aggregate counts' rule against reading inside a list. The builder lists every such question for this input, not only the questions a formula can read a value from, since a file upload has no readable value but can be counted.
- **Reuse of the aggregate pipeline** (agent decision): members-who-answered sources travel with aggregate sources through the same endpoints, hook, loading gate and `VariableResolutionContext.aggregates` map. The map keys them as `answered:<formId>:<fieldId>` (`answeredSourceKey`) so they can't collide with an aggregate on the same question. Both share one latest-submission CTE on the server (`LATEST_ANSWERS` in `server/src/tasks/variable-aggregates.ts`), so the withdrawal, guest and ordering rules stay one implementation.
- **Wire shape** (agent decision): the endpoints' response gains `answered: { sourceFormId, fieldId, count: number | null }[]` beside the unchanged `aggregates`, and the admin request gains a required `answeredSources`. Installed app builds ignore the new response field, and they fail an `answeredCount` input as an unknown kind, so they show the variable unresolved, never a wrong number. An admin tab opened before the deploy gets a 400 on previewing a form with aggregate inputs until it reloads; that is limited to admins and clears on reload, so the request field has no fallback.
- **Builder sample** (agent decision): the preview takes one sample number, reusing the random input's whole-number field (moved to `NumberSample.tsx`).
- **Local verification data** (agent action, local only): local form 166's `num_completions` now reads members who answered "Upload your photos here:" with formula `input1`, since the question text already supplies "members". Staging still needs the same change made in its admin.
