# Evidence

Research by this session and three rounds of research subagents, all checked 2026-11-23 unless marked. "Read" means the page was fetched; "search summary" means only a search result was seen. The Variable framework spec's EVIDENCE.md (`docs/provenance/01a1c8da-8f1b-7459-9652-87f613c8693c-variable-framework-spec/EVIDENCE.md`) already covers expression languages, rule authoring, what "previous answer" means, and SDC's external-dependency guidance; that is not repeated here.

## External research

### Form formats compared

- **A2UI** (Google; vendor documentation, v1.0 spec read): a JSON message stream from an agent to a renderer. Messages create surfaces, update a flat list of components by id, update a JSON data model by JSON Pointer, and delete surfaces; the renderer sends `action` messages back carrying values bound from the data model. The renderer registers a catalog of allowed components; a reference to an unknown one fails. Built-in checks (`required`, `regex`, `length`, `email`, `and`/`or`/`not`) disable a button while failing; the part of the spec read has no conditional-visibility rule beyond `@accessibility.hidden`. Official renderers: React, Lit, Angular, Flutter, SwiftUI; Apache-2.0. [Site](https://a2ui.org/), [v1.0 spec](https://a2ui.org/specification/v1.0-a2ui/), [repo](https://github.com/google/A2UI).
- **W3C XForms 1.1** (formal standard, read): `readonly`, `required`, `relevant`, `calculate` and `constraint` are all XPath expressions on `bind`; the abstract describes separating "presentation, purpose and content", with device-neutral controls such as "select one". [XForms 1.1](https://www.w3.org/TR/xforms11/).
- **ODK / XLSForm** (vendor documentation, read): `type` sets what is stored and `appearance` how it shows ("The `type` and `appearance` of a question determine the widget"); new widgets arrive as appearances, not types. One XPath language serves `relevant`, `required`, `constraint`, `calculation`, `default`, `choice_filter`, `trigger` and `repeat_count`; defaults are "evaluated exactly once on form load", other expressions re-evaluate, constraints run on moving to the next screen. Groups and repeats nest. [XLSForm](https://xlsform.org/en/), [form logic](https://docs.getodk.org/form-logic/), [question types](https://docs.getodk.org/form-question-types/), [ODK XForms spec](https://getodk.github.io/xforms-spec/).
- **HL7 FHIR R5 Questionnaire** (formal standard, read): a tree of items with a `linkId` unique within the questionnaire; types `group`, `display` and question types; `enableWhen` with `enableBehavior`; `answerOption` or `answerValueSet`; responses link answers by `linkId`. [Questionnaire](https://hl7.org/fhir/R5/questionnaire.html).
- **HL7 SDC 4.0.0** (formal standard, trial use, read): "SDC only uses three languages: FHIR queries, FHIRPath and CQL", used for `variable`, `initialExpression`, `calculatedExpression`, `enableWhenExpression`, `answerExpression`, `answerOptionToggleExpression` and `targetConstraint`; simple limits stay declarative (`minValue`, `maxLength`). `itemControl` picks a control from those valid for an item's type. [Expressions](https://hl7.org/fhir/uv/sdc/en/expressions.html), [behavior](https://hl7.org/fhir/uv/sdc/en/behavior.html), [rendering](https://hl7.org/fhir/uv/sdc/en/rendering.html).
- **SurveyJS** (vendor documentation, read): one expression syntax for `visibleIf`, `enableIf`, `requiredIf`, `choicesVisibleIf`, `calculatedValues`, `setValueExpression`, `defaultValueExpression` and triggers; `{name}` placeholders pipe values into text; an `expression` validator fails when its expression is false (that validators share the visibility syntax is inferred, not stated). [Conditional logic](https://surveyjs.io/form-library/documentation/design-survey/conditional-logic), [validation](https://surveyjs.io/form-library/documentation/data-validation).
- **JSON Forms** (vendor documentation, read): a JSON Schema for data plus a separate UI schema; rules only HIDE/SHOW/ENABLE/DISABLE on a JSON Schema condition over a scoped value, with no required-if or calculation; custom renderers attach widgets to unchanged data types. [Rules](https://jsonforms.io/docs/uischema/rules), [custom renderers](https://jsonforms.io/docs/tutorial/custom-renderers).
- **Typeform and Google Forms APIs** (vendor documentation, read): Typeform keeps `logic` as a top-level array apart from `fields`, with validations as per-field properties; Google Forms has no expression language and encodes presentation in the type (`ChoiceQuestion.type` RADIO, CHECKBOX, DROP_DOWN). [Typeform](https://www.typeform.com/developers/create/reference/create-form/), [Google Forms](https://developers.google.com/workspace/forms/api/reference/rest/v1/forms).
- **No study found** comparing one expression language with separate mechanisms for form authors, or showing that separating type from widget matters; the evidence is what the standards do. Per-renderer gaps in appearances fail silently in ODK (map appearance works "in ODK Web Forms… but not in Enketo"), and no source requires a client to reject or fall back on an unknown appearance.

### Results views and write-back

- No standard covers results or aggregate views inside a form definition. FHIR and Google Forms define none; the SurveyJS Dashboard is a separate library fed the definition plus responses ([overview](https://surveyjs.io/dashboard/documentation/overview), vendor documentation). Respondent-facing end screens do live inside definitions: SurveyJS `completedHtmlOnCondition`, Typeform `thankyou_screens` (vendor documentation).
- Write-back is declared in the definition: SDC definition-based extraction (`item.definition` naming a profile element, trial use) and ODK Entities (`save_to` per field, an entity list declared once). [SDC extraction](https://hl7.org/fhir/uv/sdc/en/extraction.html), [ODK Entities](https://docs.getodk.org/central-entities/).

### Versioning definitions

- ODK Central: a new form version leaves "all the previous submissions" unchanged, and a published field's data type can't change (vendor documentation, [forms](https://docs.getodk.org/central-forms/)). Form.io shows a submission in the revision it was captured in ([revisions](https://help.form.io/form-building/form-revisions), vendor documentation). FHIR's R3→R4 changed structure and logic in one release with machine-readable conversion maps ([version maps](https://hl7.org/fhir/R5/questionnaire-version-maps.html), formal standard, as precedent only).
- No source says whether a format should change structure and logic together, or how to migrate stored definitions.

### Copies and lineage

- REDCap repeats one instrument across events; a field keeps one variable name, read as `[event][variable]`, and earlier-answer lookups stay inside one project (first and last event limited to the current arm). `[previous-event-name]` with a field returns the closest previous event where the field's instrument is designated, which does not cover a participant who skipped such an event. Vendor documentation, read. [Smart Variables](https://redcap.icts.uiowa.edu/redcap/redcap_v16.1.5/Design/smart_variable_explain.php).
- FHIR R5 `derivedFrom` names questionnaires one is based on, with no usage rules, and warns data from different versions is "often not comparable" (formal standard, read). SDC modular forms SHOULD add `assembledFrom` pointing at source versions ([modular](https://hl7.org/fhir/uv/sdc/en/modular.html), trial use, read). DDI-Lifecycle 3.2 `BasedOnObject` records what an object is based on ([schema](https://docs.ddialliance.org/DDI-Lifecycle/3.2/xmlschema/schemas/reusable_xsd/elements/BasedOnObject.html), formal standard, read).
- Typeform, Jotform and Datadog copies carry a "(copy)"-style name and no source link (vendor documentation, search summaries); Qualtrics separates one-time copies from live reference surveys ([reference surveys](https://www.qualtrics.com/support/survey-platform/survey-module/survey-flow/advanced-elements/reference-surveys/), read). Oracle Clinical One's form API returns a `source` with the copied form's id ([API](https://docs.oracle.com/en/industries/life-sciences/clinical-one/coapi/op-ec-designer-edc-svc-rest-v20.0-studies-studyid-versions-version-forms-post.html), read; what reads it is not stated).
- No product or standard found reads earlier answers by following copy lineage.

### Names for member facts

Vendor documentation, read unless marked: LaunchDarkly "context attributes" ([docs](https://launchdarkly.com/docs/home/observability/context-attributes)); Braze "custom attributes" and "standard attributes" ([docs](https://www.braze.com/docs/user_guide/data/activation/custom_data/custom_attributes)); Segment "traits" ([identify](https://www.twilio.com/docs/segment/connections/spec/identify)); Customer.io "attributes" ([docs](https://docs.customer.io/journeys/attributes/)); SDC `launchContext` and `variable` (trial use). No naming standard exists; "attributes" is the most common term, and none calls a fact a "validator".

### Steps completed elsewhere, and checks at submit

- Stripe Connect: the `return_url` redirect "doesn't mean that all information has been collected"; the app fetches the account or listens for `account.updated`, and its iOS sample syncs with the backend when the browser closes. Vendor documentation, read. [Hosted onboarding](https://docs.stripe.com/connect/hosted-onboarding).
- DocuSign: the redirect's `event` "should only be used as a hint"; confirm by API (polling no more than every 15 minutes) or, preferably, Connect webhooks. Vendor developer blog, read. [Has my envelope been signed](https://www.docusign.com/blog/developers/dsdev-has-my-envelope-been-signed).
- Google Workspace domain verification: add the record, return, press **Confirm**, which checks then. Vendor documentation, read. [Verify your domain](https://knowledge.workspace.google.com/admin/domains/verify-your-domain-with-a-txt-record).
- Appcues recommends completing checklist steps by event or attribute rules over click-to-complete because rules "confirm the user did the task"; Intercom reopens a checklist when a step completes itself. Vendor documentation, read. [Appcues](https://docs.appcues.com/en_US/checklists/add-content-to-your-checklist), [Intercom](https://www.intercom.com/help/en/articles/6661022-design-your-checklist).
- Moodle updates activity completion when the action happens (a forum post calls `update_state`). Vendor documentation, read. [Activity completion](https://moodledev.io/docs/apis/core/activitycompletion).
- HL7 SDC: "All 'error' constraints SHALL evaluate to 'true' before setting a QuestionnaireResponse to complete", and validators "SHOULD check validity… based on the date of QuestionnaireResponse completion". Formal standard, trial use, read (behavior and expressions pages above).
- SurveyJS runs server validation on moving to the next page and on completion ([server validation](https://surveyjs.io/form-library/examples/javascript-server-side-form-validation/documentation), vendor documentation, read). CWE-367 (time-of-check to time-of-use) advises keeping the gap between a check and its use short or re-checking ([CWE-367](https://cwe.mitre.org/data/definitions/367.html), read).
- No source found freezes a check that gates completion. No standard covers a "check again" control or re-checking on return.

## Measurements

### Staging copy (local database, a staging copy whose newest form is dated 2026-10-13; queried 2026-11-23)

- Forms and copies: 127 forms, 9 titled "(Copy)"; 109 actions, 1 named "(Copy)". Duplicating renames both (`useActionCommands.ts:73,88`), so admins rename copied actions and leave the forms. Titles repeated up to 7 times, such as "Provide feedback on an Alliance introductory video form" and "Review chatbot transcripts to help make chatbots safer for children form".
- Projects: 14, with 2–5 actions each. Only project 27 ("Multiprong food waste pact campaign", 5 actions) has field ids shared across its forms (52 shared ids).
- Step gates (`customValidatorId` on a field) by validator type: `IsPhoneNumberValid` 2 fields on 2 forms, `RepliedToForumPost` 2 on 2, `RepliedToForumPostOrChild` 2 on 2, `SignedContract` 1 on 1. None gate on tag, community or has-phone checks.
- Kinds the new format drops, in each form's current snapshot: the `custom` kind on 15 forms, by component `action-share-url` 12, `share-info-publicly-toggle` 2, `share-url` 1; an `html` block on 1 form.

### Code read (main at `1fd0cad0cf`)

- `common/src/forms` is 18,446 lines including tests. Rule mechanisms in it: `visibleIfFormula` (named conditions plus an AND/OR/NOT tree, 12 condition kinds), `requiredIfFormula`, `rowCondition` (5 kinds), the formula language for `variables` and `optionsFormula`, `#{var}` interpolation, and one-offs (`customValidatorId`, `atLeastOneOnWith`, `outputBlockVisible`, `prefillFromPreviousAnswer`, `defaultValue`).
- Field kinds that differ only in presentation: `checkbox`/`toggle`, `time`/`timePicker`, `radio`/`select`/`multiselect` with `dropdown`, `file`/`image`; plus `width` and `checkboxPosition`. `autoExtractUserData` takes three shapes (a boolean, `{ target }` from the checkbox targets, `{ target }` from the custom-component targets) (`common/src/forms/field-schemas.ts`).
- Duplicating an action copies its form schema unchanged, keeping field ids (`apps/admin/src/pages/action-dashboard/useActionCommands.ts:58-75`); a form belongs to one action (unique `taskFormId`, `server/src/actions/entities/action.entity.ts:84`); forms record no source (`server/src/tasks/entities/form.entity.ts`).
- Step gates run on the client when the member presses Next (`shared/forms/useFormValidation.ts:137-176`, `POST /tasks/runValidator/:id`); the submit path never checks a field's `customValidatorId` step gate and checks required fields, option membership, selection and ranking counts, and list sizes, but not text or number limits (`server/src/tasks/form-submission-validation.service.ts`). At submit, the server runs only the validators visibility conditions name, to decide visibility (`server/src/tasks/member-visibility.service.ts`). Separately, a cron (`server/src/actions/forum-action-completer.worker.ts`) finds a forum-participation action's forum-reply validator among its form's validators, step gates included, and shortly before the deadline completes the action for members who replied, rather than when the reply is posted.
- `atLeastOneOnWith` (added in `f7cd07344d`): naming another toggle keeps at least one of the pair on, and the server refuses both off.
