# Decisions

- **A step is done once the member's resume point is past every visible page under its header.** (Agent decision) The resume point is the flow's saved screen when it is visible, otherwise the draft's page, the same places Begin reopens at. A header shared by several pages turns done only after its last page, so a split step isn't marked done halfway. Done state changes only the dots, so it updates live without moving Begin. The outline stays pending until the saved screen loads, so a finished step never appears grey and then turns green. This supersedes the "no done or current markers" decision in `01a1cc92-722f-7000-8dfe-0357e84660bc-task-outline`.
- **A done step differs from the others by colour alone, a departure from `agents/skills/ux-guidelines` that the user's requirement takes precedence over.** (Agent decision) The guidelines bar colour as the only cue (WCAG 2.2 SC 1.4.1, use of colour), and the user removed the check mark that met it. Screen readers still hear "done" after the step on web and mobile. `Timeline` takes `doneIndices` on web and mobile for the green.
- **The off switch is `taskOutline: false` on the form schema, set by a checkbox above the form builder's page list on task forms.** (Agent decision) The outline is built from the form's pages, so the setting lives with them, covers each form variant separately and needs no database migration. The server validates saved schemas against `formSchema`, so it deploys with or before an admin that saves the field. Installed mobile builds from before this ignore the flag and keep showing the outline until they update.
