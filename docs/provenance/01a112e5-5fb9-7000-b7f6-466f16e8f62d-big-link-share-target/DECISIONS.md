# Decisions

- **Codes come from the existing external-target share row.** The block resolves its member URL through `POST /share-urls/get-share-link` with `{ externalTargetId }`, the same call and `ShareUrl` row the `share-url` custom component uses. A member has one code per target, listed at `/share-links`.
- **External-target codes have no prefix, for every component.** The code belongs to the (user, target) row, so whichever component first creates it cannot choose its format. Action and invite codes keep `share-`; existing rows keep their stored codes. No lookup depends on the prefix: `sid` lookups are exact matches and notification CIDs travel in a separate `cid` parameter.
- **`url` holds the target's base URL alongside `externalTargetId`.** Older clients ignore the unknown key and follow `url`; signed-out and admin views follow it too, so they need no new endpoint exposing targets to non-admins. The copy can go stale if the target's URL changes later; re-selecting the target in the editor refreshes it.
- **Who gets a coded link is decided per app, not per form.** The form renderer's `user` prop is the respondent, not the viewer, and the API only mints the caller's own code. A sharedweb context says whether the viewer gets their own code: the frontend sets it from sign-in state, the admin never does (admins viewing responses get the base URL), and mobile reads its own auth state. A signed-in member viewing someone else's output sees their own code, which is the link they would use.
- **No `#` icon yet; unknown icons fall back to the default.** Installed mobile builds look up `bigLinkIcons[block.icon]` and crash on an unknown name, and form screens have no error boundary. Rendering an unknown icon as the default from now on lets a later release add icons once this build is widely installed.
- **Big Link rendering moves to its own files.** `RenderDisplayBlock.tsx` and the mobile `FormRenderer.tsx` are near or past the file-size guideline, and the share-target logic is a separable unit.
- **The button style applies to every Big Link Block, on web and mobile.** The admin-chosen icon stays on the left and the arrow sits on the right. Loading and error states keep a status line and drop the arrow, since they are not clickable. The admin HTML responses export still prints the URL after the link text, since a printed record has no other way to show where the link goes.
