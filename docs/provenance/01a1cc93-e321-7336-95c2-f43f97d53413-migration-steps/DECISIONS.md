- The rule keeps the name expand-migrate-contract (Martin Fowler's "Parallel Change") and labels the steps with its phases, because the name is the one agents and people recognize; the steps pin the order that name leaves open. Strangler fig was considered and rejected: it names replacing a whole application by rerouting features behind a facade, not migrating a data shape. (agent decision, from memory, not researched)
- The steps say "shape" rather than "system" to match the rule's existing wording, which covers stored data, installed clients, external code, and newly adopted rules. (agent decision)
- Step 4 is labeled the ratchet and says to block the old shape from coming back, carrying over the rule's earlier "with a ratchet so the old shape can't grow back" clause, so the ratchet is stated once and still means enforcement such as a lint rule, not only removing today's writers. (agent decision)
- The condition is stated as a test (a dependent can't switch at the same moment) with examples, rather than a closed list, so it covers cases the list missed, such as a browser tab running the previous frontend bundle, queued jobs, and webhooks. It carries the reason the atomicity note relies on, so that note stays short. (agent decision)
- Each step starts once the previous one is live everywhere that depends on it, installed clients included, shown by a forced minimum version or by no traffic from older builds, so an old client still writing the old shape can't write records after the migration that the contract step then leaves unreadable. The user deferred this choice ("don't care"); a review raised it. (agent decision)
