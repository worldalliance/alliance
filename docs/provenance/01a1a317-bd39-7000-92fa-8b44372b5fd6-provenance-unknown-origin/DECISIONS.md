Behavior a task records without the user's approval, such as behavior in existing code, goes in DECISIONS.md as an assumption; the task's own choices stay ordinary decisions. DECISIONS.md already holds what a later agent may reconsider, which fits behavior nobody asked for, and keeping it there preserves the record that the behavior exists without making it binding.

The provenance skill says so in its DECISIONS.md section, and its REQUIREMENTS.md section says the file holds only requirements the user stated or approved, which covers approved points from third-party material, and its frontmatter names the task as the user set it, since a target the agent picked within that task is the agent's choice. The old "Record unknown origins explicitly." read as permission to add an unknown-origin entry to REQUIREMENTS.md under a label, so the skill now names where such behavior goes rather than how to label it.

The skill's REQUIREMENTS.md section has the agent ask about forwarded material's points through the root AGENTS.md **Open questions** format, since that is already how questions whose answers land in provenance are asked. Approved points go in REQUIREMENTS.md, and so does a rejected point, as a requirement against it, since a rejection is the user's statement and an assumption would leave it open to adoption; the rest follow the rule above into DECISIONS.md. An agent that cannot reach the user, such as a subagent, returns the questions in its report for the agent that can, since recording the points itself would adopt them unasked.

Each assumption names its origin where known, such as an agent's proposal or decision or reconstruction from existing code, and is marked unrecorded otherwise, so a later agent deciding whether to reconsider it knows what it rests on.

The migration of existing REQUIREMENTS.md files is left out: across about 110 directories, every review round found more missed entries and wording to fix, so it was not easy. ALL-1986 tracks the existing entries the user neither stated nor approved. Without a migration, a ratchet test would fail on those files, and reviewers kept raising issues with the one that was tried, so there is none.
