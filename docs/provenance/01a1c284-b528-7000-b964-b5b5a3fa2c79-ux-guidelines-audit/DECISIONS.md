## How the rules were chosen

Four research agents audited the skill, a Codex agent brainstormed 65 further rules, and a Claude agent judged those against the standards. Independent Claude and Codex agents then recommended how much to add. The approved set is the Claude recommendation with the two narrower Codex wordings in REQUIREMENTS.md (agent proposal, user-approved). Its test for a rule and its list are in REQUIREMENTS.md, and the checklist writes the extensions as separate bullets, so its bullet count exceeds 23. EVIDENCE.md holds the research.

Left out under that test, with the work that remains tracked in Linear where it is a defect (agent decision): orientation, automated inferences, distressing material, IME Enter and typed dates (each a single instance); one primary action beyond "destructive is never the default", modal restraint, radios versus dropdowns, WCAG 3.2.2 and 2.5.2 (no repository failure shown, and all of AA still binds through the skill's opening); nested scrollers, same-tab links, search scope, progress bars and relative spacing.

## File size

At an estimated 3.2 to 3.5 characters per token (no tokenizer was available), the audited checklist came to about 6,100 to 6,700 tokens in one file, past the 5,000 tokens Claude Code re-attaches of a skill after compaction (EVIDENCE.md). Asked whether to split it, the owner leaned toward two skills and deferred how it is done ("let's try splitting into 2 skills, but i don't really care either way"), so the split is an agent decision following that lean. It departs, at the owner's direction, from the one-file wording REQUIREMENTS.md held before, which no longer requires it; no rule is cut, and each sits in one skill.

The split is by branch. `ux-guidelines` keeps what every UI change needs: the status legend, the AA obligation and how to judge, then **Controls and labels**, **Status and feedback**, **Trust and safety**, **Accessibility and input** and **Where judgment takes over**, at about 15 KB or 4,400 to 4,800 tokens. `ux-forms-platform` holds what only some changes reach: **Forms and errors**, **Platform and performance** (shortcuts, loading, native text scaling and overlays, URL state) and **Visual system**, at about 8 KB or 2,300 to 2,500 tokens. It points to `ux-guidelines` for the legend and obligation rather than copying them, both skills say that judging a UI applies both, and its links reach the one copy of each source in `agents/skills/ux-guidelines/sources/`. Merging them back is the alternative if the second skill is seen going unread on changes that need it.

## Capitalisation rule

The user left open where the capitalisation requirement goes (agent decision). It is one rule in root `AGENTS.md`, because it covers all Alliance copy, including email subjects, push notifications and SMS written outside `apps/`, which the UI skills' triggers don't reach. It names buttons, menu items, tabs and labels beside titles and headings, and states that it holds on iOS and macOS, where Apple's HIG leaves capitalisation to each app but its button and alert pages use title case (EVIDENCE section 8), so a later agent doesn't copy Apple's examples. Neither UI skill states a capitalisation rule, so the rule has one home.

Existing Title Case copy, about 155 grep hits across the apps, is migrated in ALL-2105 rather than in this change (agent decision), keeping this change to the rule itself.

The rule has its own commit, since it depends on nothing in the audit, and shares this task's directory rather than taking its own (agent decision): the provenance skill makes each PR one task, and the user set the rule within this task.

## Source checks that changed an item

Comparing each item with its local copy narrowed these (agent decision): Atlassian's accent role offers red and green for categories and Carbon says only what status colours typically represent, so reserving those colours is **J**, on Apple's line against one colour meaning different things; Apple's primary role means the default button and Carbon gives a destructive step that is the workflow's main action a primary danger button, so the item says never the default, on Apple, and allows that web confirmation, on Carbon; WCAG accepts a non-colour cue or a 3:1 lightness difference, so the colour-only item accepts that difference and an inline link's underline is **J**; the Carbon and Atlassian link pages are web guidance, so the real-link item is scoped to the web; MUI and Kendo both use a tolerance near the bottom, so the chat item says at or near the end; WCAG's alternative to a gesture is any single pointer without a path, so the gesture item says so; Apple and Google Play require report, block and account deletion in the app but not on every surface, in words or in as few steps as joining, so those are **J**; PostHog documents masking and not which screens to exclude, so that choice is **J**, and Apple 2.5.14, which governs recording consent and indication, no longer backs that item and its excerpt is removed; Atlassian's base is 8 px, so the spacing default names a 4 px or 8 px scale; the HTML passage is a note, so its item is **C**; GOV.UK covers spellcheck only and lists reference numbers, names and emails, so URL spellcheck and native autocorrect are **J**; USWDS shows the unsaved-work warning by example only, with "Continue without saving" and "Go back" rather than Save and Discard, so that warning and its pair of actions are **J**; GOV.UK and Atlassian say to avoid disabling a button and neither asks a control that stays disabled to give its reason, so that clause is **J**; React Native documents `accessibilityViewIsModal` for iOS only and `importantForAccessibility` for overlapping views generally, so the Android half is **J**; APG says only that focusing the least destructive action may be advisable, so never giving a destructive action initial focus is **J**;
