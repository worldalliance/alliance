- Scoped the change to `ActionsService.homeFeed` (`GET /actions/homeFeed`), the endpoint whose doc comment describes "friends and group members" — the other feed endpoints (`activities/feed`, global feed, `timeline-feed`, `friendActivity`, `communityActivity`) use different, narrower filters and weren't in scope.
- The "set" the 10-person minimum applies to is friends ∪ group members, excluding the viewer themselves — the viewer's own id is still always added to `allUserIds` afterward, unchanged from prior behavior.
- Filler users are drawn only from users with an active/signed contract (`sqlUserHasActiveContractAt`), matching the existing convention for "real member" random-selection elsewhere in `user.service.ts` (`pickRandomUsersWithProfilePictures`, `getSignupSocialProof`). No explicit requirement covered this; existing code doesn't establish user intent per the provenance skill, so this is a judgment call to keep the fill from resembling account-less/unsigned users, which is the closest read of the request's intent that isn't contradicted by anything the user said.
- Randomness via SQL `ORDER BY RANDOM() LIMIT n`, reusing the only existing random-selection pattern in `server/src` (`user.service.ts`, previously line 866) rather than introducing a new technique. Nothing is persisted — each call re-draws, satisfying "stateless."
- New method `UserService.findRandomActiveUserIds(count, excludeIds)` returns bare ids (not full `User` entities) since `homeFeed` only needs ids for its downstream `IN (:...userIds)` filters; kept public (unlike the private `pickRandomUsersWithProfilePictures`) since it's called cross-service from `ActionsService`.
- Threshold `10` pulled into a named constant `MIN_HOME_FEED_SOURCE_USERS` in `actions.service.ts`, following the file's existing pattern of named constants for feed tuning values (`GLOBAL_FEED_FACEPILE_LIMIT`, `GLOBAL_FEED_WINDOW_DAYS`).
- Added e2e coverage in `server/test/actions.e2e-spec.ts` (new "Home feed random fill" describe block): a spy-based check that the fill is invoked with the right args when the known set is small and skipped when it already meets the minimum, a regression check that a friend's completion still surfaces, and a deterministic direct-call test of `findRandomActiveUserIds`'s exclude/contract-status filtering. Skipped a unit-test file for `UserService` — its constructor takes 23 dependencies with no existing precedent for mocking it in isolation — and skipped an HTTP-level assertion that a specific outsider's activity appears in the filled feed, since with the shared test-file's accumulated users a `RANDOM() LIMIT 10` draw including one specific id isn't guaranteed and would make the test flaky.
