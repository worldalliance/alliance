# Decisions

- `deploy/nginx/alliance.conf` defines `log_format alliance_host`, the package's `main` fields with `"$http_host"` appended, and its 443 server block writes it to `/var/log/nginx/access_host.log`. `$http_host` rather than `$host`: `$host` falls back to the first `server_name`, the legacy domain, when a request sends no Host header, which would count those requests as legacy traffic; `$http_host` logs them as `-`. It is the Host header as sent, so counts match it case-insensitively and allow a port. Appending keeps the leading fields where parsers of `main` expect them. A conf.d file may define a `log_format`: the package's `nginx.conf` includes `conf.d/*.conf` inside `http` (`EVIDENCE.md`). (agent decision)
- The server block also keeps `access_log /var/log/nginx/access.log main;`, since an `access_log` at server level replaces the inherited one and `access.log` would otherwise stop receiving the site's requests (`EVIDENCE.md`). (agent decision)
- Only the 443 server block logs the host. The port 80 block answers the ACME challenge and redirects to HTTPS on the same host, where the request is logged. (agent decision)
- Retention stays the package's: `/var/log/nginx/*.log` covers the new file, rotated daily, 10 kept. The 14-day window is read from two counts, one now covering the first 10 days and one at day 14, rather than adding a logrotate drop-in, which the host-config work (ALL-2301) owns. (agent decision)
- The admin vhosts (`alliance_admin.conf`) are left alone: ALL-2152's condition concerns the main site's `/api`, `/events` and `/socket.io`. (agent decision)
