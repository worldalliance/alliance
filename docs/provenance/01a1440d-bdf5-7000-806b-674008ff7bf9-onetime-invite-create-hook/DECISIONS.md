- The slice is creating a one-time invite from `InviteForm`, on web and mobile. Both forms called `userCreateOnetimeInvite` and handed the result to their page, which wrote it into the `queryKeys.onetimeInvitesOverview()` cache that `useOnetimeInvitesOverview` owns. That hook now also creates, and the pages' `onInviteCreated` no longer carries the invite. The create mutation moves from `useCommunityOnetimeInvites` into `useOnetimeInviteCache`, beside approve, reject and delete, so both lists create through one implementation, each upserting into its own cache.
- The mobile group invites tab's raw `userGetOnetimeInvitesByCommunity` fetch reads a different cache, `queryKeys.communityOnetimeInvites(communityId)`, which `useCommunityOnetimeInvites` already owns on web. It is left for a separate change.
- The pages keep refetching the ambassador dashboard after a create. Moving that into the hook, as `useReusableInvites` does for its links, is a separate change.
- A refused create says "Failed to create invite: " followed by the server's message, or "Unknown error" without one, where it previously showed the HTTP status text.
