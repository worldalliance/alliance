- **"Active but unfinished" is the task flow's Live and Preview modes; ReadOnly shows no outline.** (Agent decision) ReadOnly covers submitted, withdrawn, closed and missed-deadline tasks the member can no longer complete. A task past its deadline that is still completable stays Live, as REQUIREMENTS.md asks. Staff previews show it so staff see what members will see. The rule is the `outline` flag in `TASK_FLOW_MODE_RULES`, so a new mode must opt in or out.
- **A page's header is its first header block, the same one the task flow shows as that screen's title.** (Agent decision) `flowScreenHeading` in `shared/forms/flowScreens.ts` supplies both. It honours per-user content, visibility formulas and `#{variable}` interpolation.
- **The outline still skips a page whose header isn't showing.** (Agent decision) Pages are expected to open with a header, but nothing enforces it: the form schema allows headerless pages, and the admin form builder and the dev console only warn. A header can also be hidden by a visibility formula or per-user content. A header whose text is blank once interpolated and trimmed counts as not showing, and headers are compared trimmed.
- **Hidden pages are left out.** (Agent decision) The outline lists the flow's currently visible screens, so it follows the member's draft answers. It waits for visibility to settle, as the flow's progress and begin do, so it never lists the steps a guest would see, and for the form's variable inputs to load, the gate the flow itself waits behind, so a header never shows a raw `#{name}`. It also waits for the member's saved draft to be restored, whether stored on this device, synced from another or left on a guest visit, so the steps it first lists already follow those answers and don't change under a begin button already showing. Those drafts load alongside the flow's other inputs, not before them. If a draft's fetch fails, from its first failed attempt, or waits offline, the card shows no outline and shows its begin row at once rather than waiting out retries or a reconnect, since a draft landing later could change the steps. Headers are compared after interpolation, so pages share a step only when the member would read the same text. If the variables fail to load, the card shows no outline and its begin button opens the flow's error. If a visibility input fails to load, a previous answer included, visibility doesn't settle unless it loads again, so the card shows no outline and shows its begin row at once, withdraw control included, as it did before the outline. After any of these failures before the outline lists, it stays empty for as long as the card is mounted, even if the input then loads, so it never arrives above a begin button already showing. Once listed, the outline keeps its last listing while an input fails or reloads, as a refetch on window focus can, so it never leaves from above a begin button either. Begin then still waits on that settle, as it did before (ALL-2265).
- **The outline sits in `TaskFlow` above the begin button, on web and mobile.** (Agent decision) `TaskFlow` is what both the tasks-page card and the action page render, so one placement covers both pages on each platform. While the outline waits, the card shows the platform's spinner in place of it and the begin row, the one the task panel shows while the form loads, so the member sees the card loading and the begin button still appears once, with its outline above it; a web withdraw control the card places in its menu doesn't wait; a read-only task, and a task with no header blocks, can have no outline and show their begin row at once. On web both turn invisible while the completion screen shows.
- **The outline renders through each platform's shared `Timeline` (`components/system/Timeline.tsx`).** (Agent decision) That gives it the same filled dots and line as the action events panel and the onboarding graphics, as REQUIREMENTS.md asks. Each platform's `Timeline` draws its line one step at a time, each step joining its dot to the next one's, so the line ends at the last dot however the steps wrap or change after mount. On mobile the outline is one accessibility element read as "Task steps: " and its steps, since React Native gives a label only to an accessibility element and iOS has no list role; the web outline is a group labelled "Task steps".
- **Every step is styled the same, with no done or current markers.** (Agent decision) The request was only to list the steps, so no `currentIdx` is passed and every dot is the timeline's grey.
