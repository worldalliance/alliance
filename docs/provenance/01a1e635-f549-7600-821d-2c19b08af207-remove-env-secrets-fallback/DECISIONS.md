# Decisions

- **`scripts/dev-secrets.json` drops `loadsEnvFile`, and `envFile` becomes optional, present only for a consumer that loads that file itself** (agent decision). Once the fallback is gone, `with-secrets.sh` reads a consumer's env file only for consumers that load it: to refuse static AWS keys in it and to read `ALLIANCE_WITHOUT_TEAM_SECRETS` from it. `devtools`' `envFile` was read only by the fallback, so it is gone. The manifest and the wrapper live in the same checkout, so no reader sees one without the other; `scripts/check-parameter-drift.ts` and `server/src/config/env.spec.ts` read only `secrets`.
- **`scripts/new-worktree.sh` leaves out every key any consumer in `scripts/dev-secrets.json` lists, and the static AWS keys that the deleted IAM users' access keys sat under (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AGENT_CHATS_AWS_*`), from every config file it copies, unless the shell, the source `server/.env` or its `.development`, `.local` or `.development.local` sibling sets `ALLIANCE_WITHOUT_TEAM_SECRETS` to `1` or `true`** (agent decision, for requirement 3). It reads that flag as `with-secrets.sh` does, the shell's value over the files', through Bun's loader, so a value like `$VAR` that the wrapper expands counts here too, a contributor who exports the flag and writes their own values into `server/.env` keeps them, and so does one who sets it in a sibling, where the wrapper and `setup-without-team-secrets.ts` also look for it. The static AWS key names repeat `with-secrets.sh`'s `static_keys`, which the script's comment names, rather than moving three names into a file both read. A value the wrapper refuses stops it, with the wrapper's message, before it creates anything. Commented-out lines are copied as they are: matching them took a second parse whose edge cases, such as an unclosed quote, swallowed or kept the wrong lines in review, and a leftover commented value is one the cleanup section tells owners to delete and ALL-2209 rotates. `scripts/setup-without-team-secrets.ts` writes generated `JWT_SECRET`, `JWT_REFRESH_SECRET`, `ADMIN_USER` and `ADMIN_PASSWORD` into a contributor's `server/.env`, and those names are in the manifest, so leaving them out would stop a contributor's worktree from booting. The manifest is the list of team secrets, so a secret added there is left out without a second list to update. It is a denylist, not an allowlist of `server/.env.example`'s keys: an allowlist would also drop local settings a team member keeps in `server/.env` without saying so, while a secret that has left the manifest, such as one from a removed feature, is a leftover the cleanup section tells owners to delete and ALL-2209 rotates. The script prints the names it left out, so a team member who expected them sees why. `with-secrets.sh` refuses static AWS keys in `server/.env`, so a copied one would also break the worktree.
- **The `docs/local-secrets.md` cleanup section stays as "Old copies in `.env` files"** (agent decision, for requirement 2), since checkouts set up before ALL-1964 can hold the plaintext copies until their owners delete them, and ALL-2209 rotates the ones whose exposure can't be ruled out.
- **The one-time check before `terraform apply` also lists what else each old user holds** (agent decision, for requirement 5). Besides when the access keys were last used, an admin runs, for `alliance-dev` and `alliance-agent-chats`, the read-only list steps of AWS's "Deleting an IAM user (AWS CLI)" procedure (https://docs.aws.amazon.com/IAM/latest/UserGuide/id_users_remove.html), which cover everything `DeleteUser` requires gone: login profile, access keys, signing certificates, SSH public keys, service-specific credentials, MFA devices, inline and attached policies, and groups. The admin removes whatever Terraform doesn't manage before applying the saved plan. Neither user sets `force_destroy`, so any of these left in place makes `DeleteUser` fail after the managed key and policy are gone, stopping the apply partway before the merge. Setting `force_destroy` instead takes a second apply to get it into state first.
