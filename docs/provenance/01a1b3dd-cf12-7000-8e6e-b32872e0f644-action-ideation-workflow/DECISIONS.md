# Decisions

- **Agent decision:** Use a repo-local skill with both Claude's `disable-model-invocation` and Codex's `allow_implicit_invocation: false`. Existing skill symlinks provide discovery; no automatic AGENTS.md trigger is added.
- **Agent decision:** Reuse Bun, Zod, and `common/src/result.ts` for small deterministic sampling and ranking helpers. Generation and qualitative judgment remain agent tasks through the existing subagent skill, so no new model credentials, training, provider integration, or scheduler are needed.
- **Agent decision:** Snapshot editable requirements, atoms, facets, rubric, history and prior runs into each working run. Hash inputs and preserve parent IDs. At sampling, save a checksum of the validated plan, including metadata, combinations, lineage and the input manifest; check it before ranking or loading a prior run. Freeze inputs when sampling finishes; edits require a new run. These local hashes detect accidental changes and association mistakes; they are not a tamper-proof security mechanism.
- **Agent decision (root-agent guidance):** Reuse the frozen-input mechanism for invocation-only requirements and directions, keeping the remedy small and the persistent human-editable requirements list separate. An optional `--directions` file becomes the hashed `directions.md` snapshot read by both generators and reviewers. Omission records no additional directions; a supplied blank or unreadable file fails sampling. Preserve hard versus soft wording and current-run scope so temporary constraints neither disappear at handoff nor become persistent requirements. Existing plan and input verification covers this snapshot without a second integrity mechanism.
- **Agent decision:** Keep operational history, generated candidates and feedback in `.scratch/`; commit curated mechanisms and user-supplied roulette facets. Source action IDs illustrate activities, not demonstrated effectiveness. Mark mechanism extensions explicitly.
- **Agent decision:** Keep scoring separate from requirements. Start with the experiment's subjective 1–5 dimensions and 3:2:2:1 weighting for value, novelty, member experience and feasibility. Preserve equal totals as ties, and rank only proposals that pass the current requirements. Weights are revisable agent defaults, not user constraints.
- **Agent decision:** Require a disposition and independent assessment for every sampled or refined candidate, including generator rejections. Bind each assessment to hashes of the validated candidate fields and plan, so ID reuse cannot retain a different proposal's review. Before completion, changed proposals need fresh reviews. After completion, preserve candidates and assessments by checking their recorded plan and output hashes on reranking and reuse; revisions start a new run to keep human feedback attached to the reviewed output. Feedback remains editable after ranking. Validate complete ID coverage and fail on malformed output rather than dropping candidates.
- **Agent decision:** New-action ingestion is an explicitly invoked maintenance mode, not an automatic hook. Propose bank edits from new evidence without treating every new campaign as a new mechanism.
- **Code inspection:** Completion denominators changed relative to the exploratory snapshot. Preserve raw counts, source timestamps and documented denominator semantics; do not hardcode the earlier chart denominator or interpret completion as causal evidence of impact or enjoyment.
