- The hook matches `pkill` or `killall` as a word anywhere in the command, so it also blocks a command that only mentions them, such as `grep pkill`. For every name the hook matches, a word starts and ends at any character but a letter, digit, `_`, `.` or `-`, so a quoted name such as `"pkill" -f x` or `xargs "kill"`, or an operator written flush against one as in `xargs kill;`, is denied, while a path that only contains the name, such as `block-pkill.sh`, isn't. Parsing shell to tell an invocation from a mention costs more than the occasional rephrase. Matching only in command position, after a separator or a wrapper such as `sudo`, still lets through forms like `if pkill …` and `timeout 5 pkill …`, and a missed kill costs more than a blocked mention. The denial says that a mention trips it and to pass such text through a file.
- The pgrep forms match anywhere, on the same trade-off as the word match, and the xargs form denies `pgrep … | xargs … kill` with any `|` in between, so a pattern like `'vite|bun'` or a `| sort |` stage doesn't slip past. macOS pgrep has pkill's parsing trap, so `kill $(pgrep -f 'bun src/main.ts' -n)` repeats the original incident in one call. The command-substitution forms deny every pgrep inside `$(…)` or backticks, behind a wrapper such as `sudo` too, whatever consumes it, such as `pids=$(pgrep x)`, since telling one that feeds a kill from another means parsing shell.
- The hook lives in `agents/hooks/`, which `AGENTS.md` names as the home for agent hooks, since both CLIs run it. Its test makes `agents` a unit-test package, so it joins `scripts/test-all.sh` and the `test-unit` matrices in `ci.yaml` and `deploy.yaml`.
- Codex reads the same `hookSpecificOutput.permissionDecision: "deny"` output as Claude Code (third-party guides, https://codex.danielvaughan.com/2026/04/15/codex-cli-hooks-complete-guide-events-policy-patterns/; OpenAI's reference at https://developers.openai.com/codex/hooks was not retrieved), so one script serves both.
- `AGENTS.md` and the denial add `pgrep -af` for Linux beside the required `pgrep -fl`: procps pgrep's `-l` prints only the process name and `-a` the full command line (pgrep(1), procps-ng), while macOS `-a` means something else, so one flag pair can't serve both.
