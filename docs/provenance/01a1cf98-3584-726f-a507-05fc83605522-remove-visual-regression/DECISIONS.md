# Decisions

- **citesting's web screenshot code goes with the comparison code.** `take-screenshots.ts`, `screenshot-targets.ts`, `compare-screenshots.ts`, `ai-review.ts`, and `settle-images.ts` with its test are deleted, as are the `take`, `compare` and `ai-review` scripts, per the exact list in the ci-deploy-speed DECISIONS.md. `settle-images.ts` was imported only by its own test. The mobile screenshot tooling, its `take:mobile` script and `seed-database.ts` stay; `take:mobile:ios`, which ran the same command and whose only caller was the deleted iOS workflow, goes. Origin: the ci-deploy-speed spec; agent decision for `settle-images.ts` and `take:mobile:ios`.
- **`@playwright/test` stays in `citesting/package.json`.** Nothing left in citesting imports it, but it is the repository's only copy of Playwright: `.github/pr-screenshots/servers.ts` imports it, and `agents/skills/playwright/SKILL.md` tells agents a bare `playwright` import resolves to the repository's copy. Removing it took `playwright` out of `node_modules`. Origin: agent finding, which corrects the spec's assumption that the web screenshot code was its only user.
- **`glob` is removed from `citesting/package.json` too.** Nothing in citesting imported it before this change. Origin: agent decision.
- **citesting's unit tests run on `ubuntu-latest` and no longer install Chromium.** The `ubuntu-24.04` runner and the Playwright install in `.github/workflows/test-unit.yaml` existed for `settle-images.test.ts`, which launched Chromium. Origin: agent decision.
- **`CI_ASSETS_BUCKET` and `SLACK_DEPLOY_CHANNEL_ID` are removed from `.github/ci.env` as well.** Only the visual regression jobs read them. The dev assets bucket itself stays, since the dev IAM user uses it (`terraform/iam-dev.tf`). Origin: agent decision.
- **The comment in `apps/frontend/src/root.tsx` no longer mentions `citesting take`.** The `import.meta.env.PROD` guard stays, because the Vite dev server also runs without a PostHog key. Origin: agent decision.
- **The Terraform removal is a separate PR, ALL-2169, on local branch `all-2169-visual-regression-infra`.** `deploy.yaml` runs from the deployed commit's own copy, so a deploy run of a commit from before the workflow removal, whether queued, in progress or re-run (a re-run keeps its original commit), still runs the `visual-regression` job, which assumes the `visual-regression` role, syncs the CI storage bucket and reads `ci/visual-regression/*`, and its `checks` job needs that job. A deploy of a commit that contains the removal needs none of them. Terraform is applied by hand from `main` against one shared state, so with the removal on `main`, anyone applying an unrelated change before then would destroy what those runs need. The removal waits until `production` contains the workflow removal, no older deploy run is queued, running or will be re-run, and PR #963 has merged: its Terraform is already applied to the shared state, so a plan from a checkout without its code also destroys its resources. This is the contract step of the root `AGENTS.md` **Breaking changes**. That PR carries out the saved-plan and parameter-deletion parts of **The user applies the infrastructure changes** in `REQUIREMENTS.md`, and changes `docs/ci-secrets.md`'s role table, parameter paths and storage access and the aws action's role list, since they describe the infrastructure. Origin: agent recommendation, from review; the user deferred how the removal ships, not whether ("I don't care"), between this and keeping the commit here with a hold note in `terraform/README.md`.
- **The mobile bundle check is a reusable workflow, `.github/workflows/mobile-bundle-check.yaml`,** called from `ci.yaml` and from `deploy.yaml`, whose `checks` job needs it. This follows how both files already call `typecheck.yaml` and `mobile-fingerprint-check.yaml`. It writes the export to `$RUNNER_TEMP`, and nothing reads that output. Origin: agent decision.
