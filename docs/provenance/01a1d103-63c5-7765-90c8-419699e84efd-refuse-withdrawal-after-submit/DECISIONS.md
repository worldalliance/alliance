# Decisions

- **Reuse the submit guard.** `optoutForm` calls `assertActionNotSubmitted`, the check submit and draft save already use, before it writes anything. The refusal is the same 400 with `FORM_ALREADY_SUBMITTED`. Agent decision: one rule for "this action is already submitted" across the three write paths.
- **Withdrawal checks the form belongs to the action.** `optoutForm` runs `assertAssignedForm`, the `validateFormIdForUser` check submit and draft save use, extracted into a helper in its own commit, before the already-submitted check, answering 403 when the URL's form isn't the member's assigned form for `actionId`. Without it, a request naming a submitted action's form with another action's id passed the check and saved a withdrawal onto the submitted form. Agent decision: the user was asked whether to file this gap separately and hasn't answered; folded in because it bypasses the rule this task adds. Clients already send the assigned variant's id (`server/src/actions/member-actions.service.ts` `applyAssignedFormIds`).
- **A second withdrawal is refused the same way.** `assertActionNotSubmitted` counts any response to one of the action's forms, and a withdrawal stores one, so a repeat withdrawal now gets `FORM_ALREADY_SUBMITTED` before saving. Before, the repeat saved a second response and then failed with "Activity already exists", leaving that response behind. The user was asked whether a repeat withdrawal should get its own message and hasn't answered; it keeps this one until they do. Agent decision, a consequence of the reuse; reconstructed from existing code (`server/src/actions/action-form-variant.service.ts` `findSubmittedFormIds`, `server/src/actions/action-activity.service.ts` `createActionActivity`).
- **Existing withdrawal-after-completion data is left as it is.** The spec's EVIDENCE.md records one such pair on staging. Agent decision: the issue asks only for the server refusal.
- **Clients' handling of the refusal on withdrawal is a follow-up.** Web and mobile show a generic failure when a stale panel's withdrawal is refused as already submitted; filed as ALL-2192. Agent decision: the requirements keep this task server-side.
- **Refusals inside `createActionActivity` are a follow-up.** `optoutForm` still saves the response and deletes the draft before `createActionActivity`, which can refuse (staff preview, contract signing, an existing activity), leaving a response that then reads as submitted. Pre-existing and unchanged by this task; filed as ALL-2193. Agent decision: the requirements keep the fix narrow, and this task already moves its own two refusals ahead of the save.
