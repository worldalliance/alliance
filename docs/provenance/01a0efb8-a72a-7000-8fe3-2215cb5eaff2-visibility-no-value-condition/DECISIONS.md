- Reuse the existing `hasValue` condition kind with `hasValue: false` rather than adding a new kind. `evaluateValueBasedCondition` already treats undefined, null, blank strings and empty arrays as no value for any field, so the web and mobile renderers, schema validation, and saved-response replay need no change.
- Only the admin condition picker changes. Text and number fields already offer "Is empty"; the new "No option selected" choice goes on the dropdowns that lacked one: select, radio, multiselect, range, contract, and formula-backed select/multiselect. A contract's "No" saves `equals: false`, which doesn't match an unanswered contract.
- Checkbox fields are left as they are. An untouched checkbox renders as unchecked, so "Unchecked" is where an admin looks for this, and that option not matching an untouched box is tracked separately as ALL-1289.
- "No option selected" comes after the real options in the select, radio, range, and contract pickers. A controlled `<select>` whose saved value matches no option shows its first option, so putting the new choice first would make a condition on a deleted option read as "show while unanswered".
