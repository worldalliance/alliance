# Decisions

- **Enum lives in `server/src/actions/action-category.ts`**, not in `action.entity.ts`. `project.entity.ts` and `action.entity.ts` import each other, and a column decorator reading the enum mid-cycle could see `undefined`. Clients use the generated `ActionCategory` union, following the `ActionReviewerIcon` precedent. Server-only enum, no `common/` copy.
- **Two Postgres enum types (`action_category_enum`, `project_category_enum`)**, TypeORM's default. Sharing one type via `enumName` made `migration:generate` keep emitting a spurious recreate-the-type diff for one of the two columns.
- **`category` is `ActionCategory[]`, `NOT NULL DEFAULT '{}'`** on both tables. Empty means untagged. DTO validation rejects non-enum values, duplicates, and non-arrays (400).
- **Migration hand edits:** the generated `DROP COLUMN` + `ADD` on `action.category` would have deleted every value. `up` instead fills a temporary `categoryNew` column from the old text (lowercase, trim, split on commas, `tech` → `technology`, `all` → the four goals, `NA`/empty → `{}`, deduplicated, enum order), then drops and renames. Any other token fails the enum cast and rolls the migration back. `down` converts back with `array_to_string(category, ', ')` into `character varying NOT NULL`, dropping the default the generated `down` also lacked. Checked on the local db: every one of the 101 rows mapped as expected. Up → down → up works, and `migration:generate` afterwards reports no changes. Prod/staging values were not checked (user chose the local db).
- **Project categories are edited via `PATCH /projects/:id`**, which now takes `UpdateProjectDto` (optional `name` and `category`), replacing the rename-only body. The SDK function is renamed `projectsRenameAdmin` → `projectsUpdateAdmin`. Create still takes only a name. Categories start empty.
- **Admin placement.** When the action has no project, read-only icons (tooltip + `aria-label` each) sit next to the action name in the dashboard header. When it has one, a toggle picker sits next to the project name in the project panel on the overview tab: selected icons dark, the rest faint. That picker both shows the project's categories and edits them, with no separate edit mode. The action's own categories are edited with the same picker in Action Details, replacing the free-text field, and saved with the rest of the form. The header is shared across dashboard tabs, so the header icons show on every tab.
- **Icon order follows the display map** (environment, poverty, democracy, technology, meta), and the picker stores selections in that order.
- **Admin's status-bucket enum renamed** to `ActionStatusBucket` (`lib/actionStatusBucket.ts`, `ActionStatusBucketFilter.tsx`, `actionStatusBucket()`), with locals renamed from `category` to `bucket`. No behavior change.
- **Fixtures.** Server e2e fixtures with free-text categories (`"Test"`, `"Community"`, …) became `[]`. Client mocks kept their meaning: `"Climate Change"`/`"environment"` → `["environment"]`, onboarding `"community"` → `["meta"]`.
- **Action import:** an export file produced before this change carries a string `category`. Importing one fails at the database instead of being coerced, because import has no DTO validation.
