# Decisions

The user deferred how each of the four points below is done ("I don't care"), so each is the agent's recommendation and may be revised if it causes friction. Research behind them is in `EVIDENCE.md`.

- **One opt-in flag, not one per integration.** A single flag in the contributor's `server/.env` makes `scripts/with-secrets.sh` skip Parameter Store and drops the team-only keys from the development requirements; the server logs at startup that stored files are off and which team-only keys are unset, and the code using each runs without it, as on any server missing that key. Push notifications, for one, go to Expo without an access token; per-integration guards would add a case for each integration, for a state that occurs only on a contributor's dev server. One explicit switch keeps failing at startup the default for team members (NestJS guidance, `EVIDENCE.md` "How a contributor opts in"); per-integration flags would ask contributors to set about eight switches to turn things off.
- **The JWT secrets and the local admin stay required, with random values.** The contributor puts random `JWT_SECRET`, `JWT_REFRESH_SECRET` and `ADMIN_PASSWORD` plus an `ADMIN_USER` into the gitignored `server/.env`; the flag doesn't drop them. Committed fixed values go against OWASP ASVS 6.3.2 and 13.3.1 and CWE-1392, and the dev server listens on `0.0.0.0`; Rails, Django, Laravel and Phoenix generate development secrets (`EVIDENCE.md` "JWT secrets and the seeded admin").
- **Stored files answer 503 in contributor mode; a local S3 container is a follow-up.** Upload and read endpoints report that stored files are off instead of a 500 or a 404. `assetsBucket()` raises it through the same development-only `withoutTeamSecrets` check as the config, since the e2e suite loads the same `server/.env` against a mocked bucket. Image upload, image download and the hosted-doc read resolve the bucket before their catch-alls (a 400 and a 404) and cache headers, so none hides or caches the 503 and their handling of other failures stays as it is; that upload reports a failed S3 write as a bad image is filed as ALL-2217. A local S3-compatible container (SeaweedFS or Garage; MinIO's community edition is archived and LocalStack needs a token) and the silent 404 that `server/src/s3/pipe-s3-object.ts` returns for any S3 error are filed as ALL-2215 and ALL-2214, keeping this PR one step (`EVIDENCE.md` "Uploads without AWS credentials").
- **Google and Apple sign-in are left as they fail today; clearer failures are ALL-2216.** In contributor mode the web button lands on Nest's JSON 503 "Google sign-in is not configured", and mobile shows "Please try again". A clear in-app message was the first pick, but six entry points reach the providers, two of them (`native/browser`, `link/browser`) answer a DTO with no error field, and covering them means a response-shape change, a regenerated client and web and mobile changes, for a state that occurs only on a contributor's dev server. The current failure already names the cause on web, so this PR stays one step (`EVIDENCE.md` "Sign-in buttons when a provider isn't configured"). Letting native sign-in verify with the public client IDs alone was considered and left out: it is optional and widens what a contributor's server trusts.
- **The flag's name is `ALLIANCE_WITHOUT_TEAM_SECRETS`,** prefixed like the wrapper's other switches, read by both `scripts/with-secrets.sh` (from the shell, or for a consumer that loads its own env files, by asking Bun to load them, so expansion and quoting read as the consumer reads them; it then exports the flag, so a consumer loading fewer files, such as the repl's dotenv, agrees) and the server's config schema, which refuses it outside development.
- **Which keys the flag drops is a set in `server/src/config/env.ts` (`teamOnlyKeys`)** rather than read from `scripts/dev-secrets.json`, with a test that it equals that manifest's `server` list less the four generated keys, so a new dev secret fails the test until someone decides whether contributors need it.
- **`with-secrets.test.ts` is split** into a shared fixture (`lib/with-secrets-fixture.ts`), the permanent tests, and `with-secrets-fallback.test.ts` for the `BACKCOMPAT(ALL-1964)` fallback, which ALL-2208 deletes whole. A codex read-only consult proposed this split when the new tests would have taken the file past 500 non-blank lines.
