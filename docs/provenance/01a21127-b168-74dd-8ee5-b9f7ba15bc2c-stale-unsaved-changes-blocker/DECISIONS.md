# Decisions

## It is a race in the page, so the fix is in the code, not the test

The failure is the race ALL-2390 describes (REQUIREMENTS.md), not the fixed 50 ms wait; EVIDENCE.md has the runs. After a save navigates away, the page it left keeps its guard registered until React runs its passive-effect cleanup, and that page still counts as having unsaved changes. A navigation in that gap is blocked on behalf of a page that is already gone. The test's 50 ms wait stays: it asserts that no late navigation happens, so a condition to wait on doesn't exist.

## Fix it in `useLeaveGuard`, not in `FormulaPage`

The task started on `useUnsavedChangesPrompt`; #1028 replaced that hook with `useLeaveGuard` and one shared `LeaveGuard` blocker while this PR was open, and the race survived it, so the fix moved there on rebase. Every caller whose save navigates away through the function `useLeaveGuard` returns has the same gap, so the hook owns the fix. A guard remembers the location key its own unprompted navigation is heading to, and stops blocking while the router is at that location and its page last rendered elsewhere, so a page that navigation has already left can't block. Remembering where the navigation is going, not where it left from, keeps a navigation that never arrived from standing the guard down: one that throws, or that another guard blocked and the admin declined, never commits that key (EVIDENCE.md). When the admin confirms another guard's prompt instead, React Router navigates again under a new key, so the saved page's guard blocks until it unmounts, as before this task: an extra prompt, never lost edits. Marking the formula editor clean before it navigates was rejected: the editor unmounts in the same update without rendering again, so its guard would keep the old dirty state, and the other callers would keep the bug.

A page that stays mounted through a navigation keeps blocking until it renders at the new location, because a dirty page that changed its search params under `allowSamePath` can still lose edits to a navigation in that window (EVIDENCE.md). Blocking only while the router is at the guard's rendered location was rejected for that reason. A page whose leaving the admin confirmed at the prompt still blocks until it unmounts; that gap predates this task, and declining there keeps the admin on the page they chose to leave without losing anything.
