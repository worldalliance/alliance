# Decisions

## Phone step

- **The phone step is the one built on the unmerged `charlie/onboarding-phone-step` branch (commit 3a011cd9a), brought onto `main`.** Its decisions were recorded only on that branch, so they are restated here. (agent decision)
- **The phone step is on web only.** Accounts are created on the web; the mobile onboarding only logs in, with its agreement step off outside development builds. (agent decision, from existing code)
- **"Get started" is enabled only for a whole, valid number** (canonical E.164 after the field's own normalising), so a partial number leaves it disabled with no error. A number already on the account counts. (agent decision implementing REQUIREMENTS.md)
- **A failed save shows "We can’t accept this number at this time. Enter a different one, or continue without one." and turns "Get started" into "Continue without a number"**, which enters the platform without saving. Every failure, the server's refusal or a save that never reached it, shows that one message, as REQUIREMENTS.md asks for a basic one. Editing the number takes the message away and brings "Get started" back, so a member who mistyped can save the corrected number. (agent decision implementing REQUIREMENTS.md)
- **The progress bar has six segments**: the agreement fills the fifth and the phone step the sixth. The app-download screen, out of the flow, would share the sixth. (agent decision implementing REQUIREMENTS.md)
- **Back from the phone step shows the agreement as signed and does not sign it again.** The account and signature exist once Join succeeds, so the agreement step then shows "Agreement received", locks the name field, or leaves it out after a reload has lost the name, and its button reads "Continue" and only returns to the phone step. A member whose session already has an active contract counts as joined, so this holds after a reload on the phone step too. A second Join would record a second signature and repeat the signed announcement and analytics event. (agent decision)
- **The opt-in confirmation text lives in `PhoneOptInService`** and is sent once, the first time a member's saved number can be texted, they want texts by default and they have not opted in, whether the number came from the phone step, Settings, a task form or a verified code; it skips a number that unsubscribed. A member who turned texts off gets none, since the text says they will be texted; a task form applies its text choice first, so one that turns texts off sends none, as `main` already did, and one that turns them on sends it. (agent decision)
- **Two saves of a number that overlap while the opt-in text is sending can each send it.** Closing that takes either a lock held across the Twilio send, up to its 10-second timeout, which holds a pool connection per send (the pool is sized against held connections in `server/src/datasources/pool-options.ts`), or a new column to claim the send before it goes out. A duplicate needs two different paths saving the same member's number at once, and costs one extra welcome text. (agent decision)
- **A request that saves a number waits for the opt-in text before it answers**, as the task form already did, so saving a first number in the phone step or Settings takes as long as Twilio does, up to the 10-second send timeout when it hangs. Inside the request, a failure to record the send fails loudly instead of in an unawaited promise, a shutdown can't cut a send off between Twilio and the record that stops a second one, and tests see the send without polling. The cost is that a database fault after the number is saved fails the request: the member is told the save failed when it didn't, and a verify request has already spent its code. Only a fault between two queries causes it, and the exception filter reports it; catching it here would answer success but need a reporting path of its own to stay loud. (agent decision)
- **A failed opt-in text raises one SMS-failure alert**, the one `MmsService` raises for every failed send; the opt-in path's own second alert is gone. That alert links the member's admin page from their phone number, where the removed one showed their name. (agent decision)
- **The step saves the number without a one-time code**, through `POST /user/update`, the `BACKCOMPAT(phone-verification)` path Settings and task forms use, which refuses a number another live account holds with 409. `docs/provenance/01a1dd13-a21d-72ee-9b98-3eb3d46bb30f-verify-member-phone/REQUIREMENTS.md` has new numbers verified by code before they are saved; the web code step (ALL-2248) does not exist yet, so this step joins the callers ALL-2248 and ALL-2250 must move to it. Open for the user to decide whether the code step comes into this change. (agent decision)

## Walkthrough

- **The tour is one step on `/tasks`** that spotlights the open task card, which on arrival is the first task in the list, with "Your first task" and "Welcome to the Alliance! Start with this task." Back, Skip, the progress bar and the steps on other pages are gone, along with the anchors, profile-menu tour state and `Card`'s `data-walkthrough` prop that only they used. (agent decision, copy open to change)
- **The task card spotlighted is the task itself, not its row in the list**, since that is where the member starts. (agent decision)
- **Any click inside the task closes the tour before the task handles it**, so "Begin" both starts the task and clears the overlay. A click on the dimmed area or Escape also closes it, since with no button those are the only other ways out. The box is a `status` region rather than a dialog, as it holds no controls and doesn't take focus. (agent decision)
- **The tour waits up to 10 seconds for the task, showing nothing meanwhile, and ends unseen if none appears**, as for a member with no tasks. Nothing is on screen while it waits, so the wait costs nothing visible, and a slow first load of the tasks page doesn't end the tour early. (agent decision)
- **The white fade from sign-up and the `/platform-walkthrough` link stay.** The fade is the hand-off from the onboarding panel, and the link is in `common/src/customLinks.ts` for content to use; it now opens the single step. (agent decision)
