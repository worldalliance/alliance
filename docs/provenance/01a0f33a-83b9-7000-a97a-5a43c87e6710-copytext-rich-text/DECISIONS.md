# Decisions

- **`format` enum, optional, absent = plain.** `CopyTextFormat { Plain, Markdown }` on the copy text content schema. Existing blocks may hold literal `*`, `_`, `#`, `1.` that markdown would reinterpret, so rich stays opt-in and no data migration is needed. It lives in the content schema, like `biglink.icon`, so per-user content carries it too.
- **One markdown → clipboard converter in `shared/`**, used by web and mobile: `mdast-util-from-markdown` → `mdast-util-to-hast` → `hast-util-to-html` / `hast-util-to-text`. These are the unified packages react-markdown already renders with, so copied HTML matches what web displays (CommonMark, no GFM, matching `FormMarkdownWrapper`). Raw HTML stays the text it was typed as, as web's react-markdown renders it: letter templates use placeholders like `<Your Name>`, which CommonMark reads as html. `markdownPlainText` was not reused: it joins paragraphs with no line breaks.
- **The plain-text fallback spells out what the html carries in markup**: a link becomes `label (url)`, an image `alt (src)`, and list items get `1.` / `-` markers (nested ones indented with non-breaking spaces, which text rendering doesn't collapse), so a paste into SMS or a social post keeps the link a message depends on.
- **Copied URLs are made safe and absolute** before serializing, by the same rule as rendered markdown (`safeMarkdownUrl`: `safeUrl` drops `javascript:` and unknown schemes, an upload key becomes an image URL). A link to either of the site's domains, or a root-relative path, is put on `thealliance.org`, since the paste lands outside the site: `siteHref` reduces it to a path and `withOrigin` puts that on the new domain (web `getInviteBaseUrl()`, the alt domain the invite links already use; mobile `getShareBaseUrl()`). The user asked to prefer thealliance.org over worldalliance.org here. `SiteOriginLinkProvider`'s own `withOrigin` call is left alone: it renders in-app admin links against the domain the panel was loaded from, which keeps the auth cookie.
- **The web and mobile copy text components move to their own `CopyTextDisplay.tsx` files**, since both host files are past the ~500-line guideline and the change grows these units.
- **Admin control is a `Type` icon toggle** (`aria-pressed`, tooltip) beside the title, per the repo's icon-over-text rule; `format` is block-wide: the toggle writes it to the default content and every user's content alike (`updateBlockWide`, generalized from how the wrapper already spreads visibility conditions), so which format a user copies never depends on when their override was snapshotted. Turning it off clears `format` rather than writing `plain`: mobile store builds from before this change strictly parse display-only schemas (action updates) and reject the unknown key, so a block switched back off parses there again. With the format block-wide, clearing it can't fall back to a stale value. The text placeholder reads "Text to copy (markdown)" while it is on. A rich block gets the same "Show preview" toggle as the Text block editor, since switching an existing block to markdown merges its single-newline lines into one paragraph.
- **The responses HTML export carries `format` as an attribute** on copy text blocks; like the Text block, the body stays the escaped source text.
- **Mobile writes html and plain text through a local native module, `apps/mobile/modules/rich-clipboard`.** `expo-clipboard`'s html write was checked on the iOS simulator: it re-renders the html through `NSAttributedString`, which stamps `Times New Roman` and mismatched sizes on every span, and derives a plain text with no URLs, list numbers or paragraph breaks (ALL-1301, ALL-1302). The module puts our html and our plain text on one pasteboard item (iOS `UIPasteboard.setItems`, Android `ClipData.newHtmlText`). Of the options the agent laid out (native module; plain text only on mobile; keep html with a forced system font), the user chose the native module. On iOS the paste target is what re-renders html through `NSAttributedString` (checked by pasting raw html into WebKit in the simulator), so the iOS side wraps the html in `font-family: -apple-system, sans-serif`; a paste then comes out in `system-ui`, not Times. Android pastes our html and text verbatim, so it gets no wrapper. Both platforms were checked end to end: copy in the dev build, paste into a WebKit/Chrome page that records `text/plain` and `text/html`. It changes the native fingerprint, so mobile rich copying ships with the next store build; `index.web.ts` keeps react-native-web on `expo-clipboard`.
- **Mobile renders a rich copy text block with markdown-it's CommonMark preset plus a core rule** (`commonMarkParser`), not the app's usual parser (linkify, typographer, strikethrough, tables): a soft break becomes a space and raw html (`html: false`) stays text, so the block shows exactly what the CommonMark copy reproduces. The wider web/mobile dialect split is ALL-1313.
- **Copied html drops link and image URLs that stay relative after the origin step** (in-page anchors, page-relative paths): they lead nowhere once pasted, so only the label is copied.
- **No unit test for `apps/mobile/lib/clipboard.ts`.** `react-native` does not load under bun, and the mobile lint rule forbids `mock.module`, the only way around that; the file's logic is one branch.
