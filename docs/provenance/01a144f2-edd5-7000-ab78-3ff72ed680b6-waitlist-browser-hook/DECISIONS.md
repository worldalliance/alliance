- `useWaitlistBrowser` owns the `queryKeys.waitlistBrowser()` cache, so it is the hook to complete. Components that wrote that cache with a raw SDK call become mutations on the hook.
- The hook returns `{ query, forget, ... }`, the shape `useWaitlistReferral` already uses, and hands back the mutation objects rather than `mutateAsync`, since the components render from their pending, error and success state.
- Cache writes stay in the hook's `onSuccess`; component-only effects run in the component after the mutation succeeds. Ending the tab's invitation after forgetting the browser chains on `mutateAsync`, because `mutate`'s per-call callbacks skip a caller that unmounted mid-request and the invitation must end regardless.
- `WaitlistLinkRequest`'s `waitlistRequestLink` touches no cache and stays a one-off mutation.
- `ForgetBrowser` receives `forget` from `WaitlistSignupForm` instead of calling `useWaitlistBrowser` itself. Its own call would mount a second observer of the browser query, and TanStack refetches a failed query when an observer mounts, so the form would lock again once a tab invitation arrived after the browser state had failed. Because the form holds the mutation, a submit resets it; otherwise a failed forget's error would stay on the confirmation, where the parent's remounted `ForgetBrowser` dropped it.
