- `ParticipantRole` moved from the participant entity to `common/src/participantRole.ts`. The client helper in `shared/` kept its own copy of the admin rule keyed on the generated client's union, so server and client could disagree about who is an admin and the client could offer a control the server refuses.
- The rule is a `Record<ParticipantRole, boolean>` rather than an array or a predicate, so a fourth role fails the build in every package until someone opts it in or out. The old server form, `[Admin, Owner].includes(role)`, would have made it non-admin without a word.
- The Postgres enum keeps the name `ParticipantRole` and its three values, so there is no migration and no change to the generated client.
- `ParticipantState` stays on the entity. Nothing outside the server reads it as an enum.
- `getParticipantState` takes a missing conversation and returns null, like `isConversationAdmin`, so the mobile screen drops its own null check. Web's conversation panel keeps its `mode === "new"` check, which is about the mode rather than null: the new-mode props allow a conversation, and the new-message view is never an invite.
- `updateConversation` calls `ensureConversationAdmin` itself, like `addParticipantToConversation` and `removeParticipantFromConversation`, and the controller drops its `ensureParticipantAndRun` wrapper. `ensureConversationAdmin` goes through `getParticipantOrFail`, which refuses an outsider with the same 403, so the wrapper only added a query.
- The admin check runs before `updateConversation` looks at the chat's type, so it covers every type. In a community chat only leaders, who sync in as `Admin`, can update it. In a direct chat both people are `Member`, so an update returns 403 where it used to return 201 and save nothing. Neither client offers the editor in those cases.
- Outside edit mode, the mobile group photo shows the server's photo, not the form's, like web. A pick that comes back after edit mode ended would otherwise show as the group photo with no Save button.
- Web loads the group edit form from `selectedConvo` when the pencil is clicked, not once when the info panel mounts. A rename pushed from another admin updates the header while the panel is open, and a form filled at mount would still hold the old name and save it back.
