- Dropping elements on a page's row in the outline, or on the "No elements" note of an open empty page, appends them to the end of that page; dropping between element rows of any page inserts them there, and dropping on a shared-visibility group's header row puts them before the group. A collapsed or empty page, and the gap before a collapsed group, otherwise have no row to drop on. Appending follows the drop-into-folder convention of file managers. (agent decision)
- "Selected" means the builder's existing selection: a range made with Shift-click or the row checkboxes, or a shared-visibility group. Grabbing an element inside it drags the whole selection; grabbing one outside it drags that element alone. Those selections are contiguous runs on the open page, so a multi-drag moves a contiguous run from one page. (agent decision)
- When the moved elements hold the selection and land on another page, the builder opens that page with them still selected and scrolls the canvas to them. A selection elsewhere follows the elements' new positions as it did for same-page moves. (agent decision)
- Visibility groups need no special handling. The draft already re-derives groups after each schema change, so a group moved whole keeps its key, and a member separated from its group leaves it, as for same-page moves. (agent decision, reconstructed from `normalizeVisibilityGroups` in `apps/admin/src/lib/visibilityGroups.ts`)
- The scope is the sidebar outline, as asked. Dragging on the canvas still reorders one element within the open page. (agent decision)
- The "Move to page" menu sits in the settings heading beside the move arrows, for an element, a range selection and a shared-visibility group. Sidebar actions otherwise appear only under Advanced, which range and group selections lack. The menu is absent on a one-page form and in a display-only builder, which has no pages to move between. (agent decision)
