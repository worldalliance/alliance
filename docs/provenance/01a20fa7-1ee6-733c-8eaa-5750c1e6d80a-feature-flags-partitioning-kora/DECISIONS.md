- The flag file moves from `shared/lib/features.ts` to `common/src/features.ts`, because the server, which can't import `shared/`, enforces the same flags. `isEnabled` takes a `NodeEnv` and looks each environment up in a `Record<NodeEnv, …>`, so a new environment fails the build instead of falling back to production's flags. Test now uses the staging flags; before, any environment other than development or staging, test included, used production's.
- The web helper `isFeatureEnabled` moves from `apps/frontend/src/lib/config.ts` to `sharedweb/lib/config.ts`, so admin and frontend share one helper.
- The Kora staging tools' gate moves from `koraStagingTools()` in `server/src/kora/kora-staging-tools.ts`, and from the admin's `isProduction()` check on Delete, to the `KoraStagingTools` flag, superseding that entry in `01a1cd6d-0fec-7000-a645-62bf6b84df7f-kora-retire-delete-batch-spec`. Each environment keeps its behaviour: off in production, on in staging, development and test.
- Production keeps the partition button visible but disabled with a reason, keeping the behaviour of `01a20f95-0180-723c-bef4-d84ec0be4906-disable-suite-partitioning`; the reason's wording is in REQUIREMENTS.md.
- The server refuses `POST /actions/suite/:suiteId/partition` with 404 where the flag is off, as `KoraStagingTools` already did for its endpoints, so production stays off even for direct API calls. Saving and previewing an existing partition stay open, since production can't create one.
