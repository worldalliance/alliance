# Decisions

- The rule is a pointer line in the root `AGENTS.md` Skills list, and the commands, readout, and failure handling live in `skills/subagents/SKILL.md`. The root file loads every turn and holds rules, not procedures (`skills/writing-for-agents/SKILL.md`).
- The prompt goes in a `.scratch/` file, written with a file-writing tool or a quoted heredoc, passed on stdin (`codex exec … -` reads it from there). A double-quoted `"<prompt>"` argument lets the shell run backticked paths as commands and expand `$`; single quotes break on apostrophes. Stdin from a file also gives `codex exec` an EOF, which it otherwise waits for when stdin is an open pipe. The user left this choice to the agent.
- Each command writes its event stream to a `.scratch/` log and the parent reads back only the final answer (`jq` on the claude `result` event, codex's `-o` file), because the full stream carries every tool result and would flood the parent's context. Each command writes its own exit code to `.scratch/<name>.exit`, so the parent can tell a finished run from one still streaming, and a failed one from a success, whether or not its harness reports a background command's exit. A failed claude run still emits a `result` (`null` or an error message) that reads like an answer. Each run takes a fresh `<name>` because a failed codex run leaves any earlier `-o` file in place, and an old `.exit` would mark an unfinished run done. Stderr goes to its own `.err` file because a CLI that fails before streaming (unknown flag, missing login) leaves the `.jsonl` empty, and merging it into the `.jsonl` would break the `jq` readout. The commands run in the background with the harness's longest time limit because a subagent can outlast the shell tool's foreground timeout, and Claude Code's default background limit equals its foreground maximum. A shell tool with no background mode (Codex CLI 0.163.0) runs it in the foreground instead, because Codex kills a `( … ) &` or `nohup … &` process group when the tool call returns. A run a time limit kills never writes `.exit`, so a command that ends without one counts as failed.
- The File size rule's read-only codex request points at the subagents skill and swaps in `-s read-only`, so the repo names one way to spawn codex.
- The `--output-format` value is `stream-json`, the only streaming value `claude` 2.1.312 accepts. `json-stream` errors out.
