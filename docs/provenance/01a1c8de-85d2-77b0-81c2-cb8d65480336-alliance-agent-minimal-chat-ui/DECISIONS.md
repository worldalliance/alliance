## Folder and conversations

- The main process keeps the conversations it started (session id, folder, first message as title, start time) in `conversations.json` in the app's user data folder, so a conversation can be resumed after a relaunch, since Claude Code keys sessions to their folder. Starting a conversation saves it, titled with its first message, and sends that message in the same call, since Claude Code keeps no transcript for a session no message has reached, so a conversation saved and left unsent could never be resumed. Later sends write nothing, so they reach the CLI at once, and a Stop pressed right after Send finds the turn. Writes are serialised and replace the file whole through `write-file-atomic`, which syncs a uniquely named temporary file before renaming it over the list, and the app holds Electron's single-instance lock, so one process owns the file. The lock belongs to the user data folder, so an unpackaged app keeps its own per checkout, in the checkout's ignored `.scratch/user-data`, and each checkout's dev app runs beside the others, its data going when the checkout is removed. Their Claude sign-in stays shared: an unpackaged app without `--user-data-dir` uses `Alliance agent (dev)/claude` as its Claude config folder, which `capture-claude.ts` signs in to as well, so signing in once serves every checkout and the captures. A file that doesn't parse fails loudly rather than reading as empty, and a conversation that can't be saved is closed rather than started (agent decision, per the root `AGENTS.md` fail-loudly rule). Start replies once the first message is written to the CLI, so a Stop can follow at once, and a new conversation whose CLI then exits before reading that message is removed from the list, with a log, since Claude Code keeps no transcript for it (EVIDENCE.md, A CLI stopped right after its first message keeps no transcript, and A CLI keeps its transcript once it has read its first message), and the window is told, so it doesn't offer to reopen it (agent decision).
- Quitting the app closes every live session at once, stopping any turn still running, aborts a running sign-in or sign-in check, and waits for each of those CLIs to exit, so the transcript upload in its SessionEnd hook finishes, as the desktop-app REQUIREMENTS.md "When the app quits, its agents stop" requires and REQUIREMENTS.md asks of the commit that first starts Claude CLIs. No session, sign-in or sign-in check begins once the quit begins, and a session still starting is waited for, for at most 30 s, since a folder on a hung network drive could stall it forever and leave the app running; the main process logs a wait it cut short. A session that finishes starting during the quit is closed at once and its Start or Resume refused, or, when the quit began while its new conversation was being saved, closed once its first message is written, and waited for if that happens within the 30 s or while other sessions or sign-in CLIs are still closing. Once the sessions have closed, the app exits at once rather than through Electron's quit, whose teardown can wait seconds on a child process still running, such as a starting session's version check. A window that fails to load, which exits the app without Electron's quit, closes the sessions the same way first. Opening the app at any point of the quit relaunches it once the quit finishes, since the quitting process still holds the single-instance lock (agent decision).

## Finding the CLI until it is bundled

Until ALL-2029 bundles the CLI, an unpackaged app runs the `claude` it finds on `PATH`, or the executable `ALLIANCE_AGENT_CLAUDE_EXECUTABLE` names, which the Playwright tests point at the stub. A packaged app reports that the CLI isn't included. Until the CLI is found, each sign-in check looks for it again, so "Check again" finds one installed while the app runs. The adapter's version check still refuses any version but the pinned one. The variable is read only when unpackaged, as `ELECTRON_RENDERER_URL` is (agent decision).

## IPC

The renderer reaches the main process only through a preload script exposing one typed `window.agent` object (`src/shared/ipc.ts`), with context isolation and the sandbox at Electron's defaults, per Electron's security checklist. Every handler also refuses a message from anything but the window's top-level page at the URL it loads, the checklist's sender validation, though the CSP and the navigation lock leave no other frame today. A sandboxed preload must be CommonJS, so it builds to `index.cjs`. Calls with two same-typed arguments take one named object, per the root `AGENTS.md` function-arguments rule. The main process validates every argument with zod before anything else, and an invalid one comes back as a failure like any other, or, for the one-way interrupt, is logged. Failures cross as `Result<T, string>`, so the renderer shows the adapter's message, and the preload turns a handler that throws into such a failure, so the page never waits on a call that silently failed. Each call's reply type is declared once, in `IpcReplies`, which types both `AgentApi` and the main process's handlers, so a handler whose reply drifts from what the page reads fails the typecheck. Likewise each channel the main process pushes to the window declares its payload once, in `RendererEvents`, which types both the main process's sender and the preload's listener. Every session event goes, with its session id, to every window whose top-level page passes that same check, so a page given the preload can't read the sessions either, and a turn's end says whether an interrupt or close stopped it. The session judges that from the CLI's result, since a Stop can cross the turn's end on its way through IPC or to the CLI, and a turn that finished first isn't shown as stopped. Start and Resume check that the folder exists first, since Node reports a missing working directory as the executable not being found (agent decision).

A session's events, `AgentEvent` and `AgentEventKind`, live in `src/shared/agent-event.ts`, with the rules for how a turn's events arrive on `AgentEvent`'s doc comment, so the renderer imports the runtime enum without the main process's session code. This supersedes `src/main/agent/session.ts` as their home, given in `docs/provenance/01a1ae9f-f048-7000-9755-74cef3cbc0e8-alliance-agent-session-interface/`; the session and backend interfaces stay there (agent decision).
