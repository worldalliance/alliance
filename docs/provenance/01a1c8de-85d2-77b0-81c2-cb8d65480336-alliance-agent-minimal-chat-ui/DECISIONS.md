## Folder and conversations

- The main process keeps the conversations it started (session id, folder, first message as title, start time) in `conversations.json` in the app's user data folder, so a conversation can be resumed after a relaunch, since Claude Code keys sessions to their folder. Starting a conversation saves it, titled with its first message, and sends that message in the same call, since Claude Code keeps no transcript for a session no message has reached, so a conversation saved and left unsent could never be resumed. Later sends write nothing, so they reach the CLI at once, and a Stop pressed right after Send finds the turn. Writes are serialised and replace the file whole through `write-file-atomic`, which syncs a uniquely named temporary file before renaming it over the list, and the app holds Electron's single-instance lock, so one process owns the file. The lock belongs to the user data folder, so an unpackaged app keeps its own per checkout, in the checkout's ignored `.scratch/user-data`, and each checkout's dev app runs beside the others, its data going when the checkout is removed. Their Claude sign-in stays shared: an unpackaged app without `--user-data-dir` uses `Alliance agent (dev)/claude` as its Claude config folder, which `capture-claude.ts` signs in to as well, so signing in once serves every checkout and the captures. A file that doesn't parse fails loudly rather than reading as empty, and a conversation that can't be saved is closed rather than started (agent decision, per the root `AGENTS.md` fail-loudly rule).
- Quitting the app closes every live session and waits for its CLI to exit, so the transcript upload in its SessionEnd hook finishes, as the desktop-app REQUIREMENTS.md "When the app quits, its agents stop" requires. The app and its windows hide while it waits, on macOS through the app's hide, as Cmd+H does, so a fullscreen window doesn't leave a black Space, and hides again whenever macOS makes it active, such as through Cmd+Tab or a dock click, since macOS shows a hidden app it activates, so the quit looks done and nothing starts another session, and quitting again waits for the same sessions. Live sessions close at once, so a running turn stops rather than going on unseen, save the exception below, and a session still starting when the quit begins is waited for too, for at most 30 s, since a folder on a hung network drive could stall it forever and leave the hidden app running; the main process logs a wait it cut short. Neither a session nor a sign-in begins starting after it, and a session still reading its saved conversation or checking its folder launches no CLI; one past those checks, in Claude Code's version check or waiting for an earlier CLI of the same session to exit, launches its CLI anyway. A session whose CLI finishes starting once the quit began is closed instead of receiving its first message, unless the quit began while its conversation was being saved, when it gets its first message. A new session that has its first message closes only once Claude Code starts replying, or once the 30 s are up, since a CLI closed before it has read the message keeps no transcript (EVIDENCE.md, A CLI stopped right after its first message keeps no transcript), so the saved conversation stays resumable. The quit waits for the CLI of a session that finishes starting after it began too, if that happens within the 30 s, or later while other sessions are still closing. Once the sessions have closed, the app exits at once rather than through Electron's quit, whose teardown can wait seconds on a child process still running, such as a starting session's version check. Opening the app at any point of the quit relaunches it once the quit finishes, since the quitting process still holds the single-instance lock (agent decision).

## Finding the CLI until it is bundled

Until ALL-2029 bundles the CLI, an unpackaged app runs the `claude` it finds on `PATH`, or the executable `ALLIANCE_AGENT_CLAUDE_EXECUTABLE` names, which the Playwright tests point at the stub. A packaged app reports that the CLI isn't included. Until the CLI is found, each sign-in check looks for it again, so "Check again" finds one installed while the app runs. The adapter's version check still refuses any version but the pinned one. The variable is read only when unpackaged, as `ELECTRON_RENDERER_URL` is (agent decision).

## IPC

The renderer reaches the main process only through a preload script exposing one typed `window.agent` object (`src/shared/ipc.ts`), with context isolation and the sandbox at Electron's defaults, per Electron's security checklist. Every handler also refuses a message from anything but the window's top-level page at the URL it loads, the checklist's sender validation, though the CSP and the navigation lock leave no other frame today. A sandboxed preload must be CommonJS, so it builds to `index.cjs`. Calls with two same-typed arguments take one named object, per the root `AGENTS.md` function-arguments rule. The main process validates every argument with zod before anything else, and an invalid one comes back as a failure like any other, or, for the one-way interrupt, is logged. Failures cross as `Result<T, string>`, so the renderer shows the adapter's message, and the preload turns a handler that throws into such a failure, so the page never waits on a call that silently failed. Every session event goes to every window with its session id, and a turn's end says whether an interrupt or close stopped it. The session judges that from the CLI's result, since a Stop can cross the turn's end on its way through IPC or to the CLI, and a turn that finished first isn't shown as stopped. Start and Resume check that the folder exists first, since Node reports a missing working directory as the executable not being found (agent decision).

## UI choices

Applied from the `ux-guidelines` and `ux-forms-platform` skills (agent decisions):

- The window title names the view: the sign-in state until Claude is signed in.
- A sign-in whose CLI succeeds but leaves `claude auth status` signed out shows that on the sign-in panel, so the user isn't returned to it with no word of what happened (agent decision, per the root `AGENTS.md` fail-loudly rule).
- A failed sign-in or sign-in check says in plain words what failed and what to do, such as "Sign-in didn't finish. Try signing in again.", with the main process's error behind "Details", since `ux-forms-platform` keeps exit codes and CLI output out of an error's headline. A failed sign-in asks Claude Code for the sign-in again first, so a CLI that no longer runs shows "Claude isn't available" rather than a retry that fails the same way.
- Cancelling sign-in returns to the sign-in panel without an error, since the user chose it, unless the CLI had already signed the user in: once it exits, the window asks Claude Code again rather than assuming signed out. Until the CLI exits, which can take up to the 2 s before it is killed, the status says "Cancelling sign-in…" and Cancel sign-in reads as unavailable but keeps focus, so the press shows at once. Sign in and Cancel sign-in each appear where the other was, so each ignores the second click of a double-click and a held Enter's repeats: a double-click or held Enter on Sign in doesn't cancel the sign-in it started, and one on Cancel sign-in doesn't start another. Check again ignores them too, since a check that still can't find Claude Code puts a new Check again in its place.
- A view that replaces the button the user pressed focuses its own action, or its status message when it has none, so focus never falls to the page. The Cancel sign-in button is described by the instruction it replaces, so a screen reader reads both when it gains focus.
- Colours are CSS variables with light and dark values, on a 4 px spacing scale, with 14 px dense text and 16 px body text at 1.5 line height. Controls share a 32 px minimum height token, which fits a line of dense text with its padding and border and clears WCAG 2.2's 24 px minimum target size.
- A button the user can't press right now but that must keep focus, so a press shows at once and focus never falls to the page, carries `aria-disabled="true"` rather than `disabled`, which would drop it from the tab order and lose its focus. It renders at 0.7 opacity with no pressed look, as USWDS styles `aria-disabled` like `disabled` (`ux-guidelines` source `uswds-modal.md`; the 0.7 is agent judgement, and `ux-guidelines` exempts inactive controls from contrast minimums), and its click handler ignores presses itself.
