- The fix comes from the review of "Mark a cancelled friend request's notification read", finding `push-after-cancel`. The user asked for every finding to be fixed. The push worker claimed notifications without looking at `readAt`, so a request cancelled within the worker's 10-second tick still pushed "wants to be friends" to the addressee. Accepting or declining that fast did the same.
- The fix is in the worker's claim query rather than in `removeFriend`, so it covers every path that marks a notification read before its push goes out, not just this one.
- The query skips a notification read at or after its `sendTime` and still pushes one read before it. "Mark all read" (`setReadAll`) marks every unread notification, including action-event reminders scheduled for later that the list doesn't show yet. Skipping every read notification would silently drop those reminders.
- A skipped notification keeps `shouldPush = true` and stays unclaimed. The claim query filters it out on every tick, so it's never sent. I didn't add a write to flip `shouldPush`, because nothing reads it apart from this query.
- The commit sits at the end of the branch. It touches only the push worker and its test, and nothing else in the branch depends on it.
